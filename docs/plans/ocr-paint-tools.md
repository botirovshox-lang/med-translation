# Внешние модели для чтения надписей и вставки перевода 1в1 — план (18.10.2026)

Правило отбора: лицензия Apache-2.0 / MIT / BSD (AGPL и GPL в закрытый сервис
не берём), работа на процессоре сервера (4 ядра, 6 ГБ, воркер один — инвариант 1),
сверка sha256 при установке, отсутствие модели — прежний путь, а не отказ.
Каждый шаг: замер на стенде (плитки лендинга 63–87, проект 89) → критик →
тест → правило в `docs/rules/pdf-reading.md` → выкат.

## Ш1. LaMa

- Модель: `lama_fp32.onnx` из Carve/LaMa-ONNX, вход image 1×3×512×512 (0..1),
  mask 1×1×512×512 (1 — стереть), выход 1×3×512×512 в 0..255.
- Где: `text_paint.erase`, ветка «не ровный, не узор» (сейчас `cv2.inpaint`
  TELEA) — и стирание продолжений за рамкой (`image_text`, `layout_pdf`), они
  зовут тот же `erase`.
- Как: плитки 512 точек без уменьшения, с перекрытием, по порядку; из плитки
  берётся середина (у внутреннего края контекст односторонний); в вырезку
  кладутся ТОЛЬКО точки дыры; тон — прежний `_tone_match`. Только при
  разбросе тона фона ≥ `PAINT_LAMA_SPREAD_MIN` (см. итог замера).
- Ограничения: потолок мегапикселей, сессия onnxruntime одна на процесс,
  `intra_op_num_threads` из окружения; нет файла/модуля/сбой — Telea.
- Установка: `tools/install_paint_models.sh` со сверкой sha256, путь —
  `PAINT_LAMA_MODEL`, выключатель `PAINT_LAMA=0`.

### Итог замера Ш1 (18.10.2026)

- Сервер: плитка 512 — 7.5 с в 1 поток, 5 с в 2, 3.2 с в 4; локальная машина
  в 2–3 раза медленнее.
- Качество: металлическая рамка (разброс тона 98) — LaMa чистый градиент,
  Telea пятна по форме букв; ровный лист таблички (40–45) — равны; белая
  статья и старая книга (0…11) — LaMa хуже: призрак адреса сайта, крапины
  (сеть дорисовывает окружение, а вокруг — буквы). Отсюда порог
  `PAINT_LAMA_SPREAD_MIN` = 60.
- Стенд (плитки 74, 78, 83) с порогом — побайтно те же картинки, что без
  LaMa: она включается только на фоне с перепадом тона.

### Ш3. Детектор PP-OCRv5 mobile — первый замер

Официальный файл RapidAI (ModelScope `RapidAI/RapidOCR`,
`onnx/PP-OCRv5/det/ch_PP-OCRv5_det_mobile.onnx`, 4.8 МБ, sha256
4d97c44a…78ae), подставляется через `IMG_DET_MODEL` без смены пакета.
Стенд (5 разных картинок): статья 18 → 15 строк, конспект 17 → 18.
Боевые книги (проекты 2 и 8, 191 картинка, сервер): строк 1046 → 1108,
время 250 → 184 с (на 27% быстрее), **потеряно 39 рамок**, прибыло 97.
Среди потерянных — настоящий текст: заголовок обложки «АПТЕКА» (дважды),
вертикальная подпись снимка «Неизвестный Мужчина …», «10mm/div», «1954»,
адрес сайта. Закон модуля — «найденное прежним разбором обязано остаться
найденным» (потерянная строка — потерянный кусок книги), поэтому v5 не
включён. Скрипты замера — `det_cmp.py`/`det_lost.py` (сессия 18.10.2026);
к вопросу можно вернуться объединением рамок v4+v5 (цена — вдвое больше
времени поиска строк) или детектором v5 server (84 МБ).

### Ш4. Чтение у себя в браузере: группа `cyrillic` (18.10.2026)

`cyrillic_PP-OCRv5_rec_mobile.onnx` (RapidAI, sha256 90f761b4…0982711,
8 МБ), словарь — `character_dict` из её `inference.yml` (850 знаков, тем же
порядком, что у eslav: пустой символ CTC в начале и пробел в конце
добавляет код). Чтение образцов слово в слово в Chrome: узбекская
кириллица, казахский, киргизский, монгольский, сербский — да; таджикский
(ӣ→й, ӯ→ў) и македонский (Ќ→К, Ѕ→S) — нет, им кнопки нет.

### Ш5. Яндекс Vision — ждёт ключа

Нужны `YANDEX_VISION_API_KEY` и каталог облака от владельца. Код без
ключа не пишем: непроверяемый путь в чтении надписей хуже отсутствующего.

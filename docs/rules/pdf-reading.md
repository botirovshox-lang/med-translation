# Правила чтения PDF и выгрузки «как в оригинале»

Справочник для разработчиков и ИИ-агентов. **Каждая находка о том, как
устроен чужой файл и как его читать, записывается сюда правилом**, и у
правила обязаны быть код и тест. Находка без правила повторится на
следующем файле клиента; правило без теста тихо сломается следующей
правкой.

Формат записи: **симптом** (что увидел человек) → **причина** (как устроен
файл) → **правило** (что делает система) → **где** (код) → **страж** (тест).
Числа — замеры на боевых файлах, а не догадки.

Код: `backend/pdfpages_worker.py` (геометрия строк из pypdf), `backend/pdftext.py`
(абзацы, места строк, `RULES_VERSION`), `backend/layout_pdf.py` (печать
перевода поверх страниц оригинала), `backend/main.py` (`_generate_export`,
`_export_pdf_layout`). Тесты: `tests/test_pdf_layout_export.py` (разделы 12–12м),
`tests/test_pdf_layout.py`, `tests/test_pdf_figures.py`; PDF для тестов
собирается руками — `tests/pdf_fixture.py` (операции `t`, `re`, `img`, `raw`).

Меняешь правило так, что меняются абзацы, — поднимай `pdftext.RULES_VERSION`
(у старых проектов появится «Чтение файла улучшено»).

---

## А. Какая выгрузка вообще печатается

**А1. Формат «PDF» у проекта из PDF/скана/картинки — те же страницы.**
Симптом: «скачивается как обычный текст, без вёрстки» (проект 14, 10.10.2026).
Причина: формат «PDF» печатал собранный Word-документ, а у PDF-проекта Word —
поток абзацев. Правило: PDF-проект → `_export_pdf_layout` (слой поверх
страниц оригинала), скан/картинка → страницы с перерисованными надписями;
печать Word — только когда раскладки нет (`pdfFrom` в отчёте называет дорогу).
Где: `main._generate_export`. Страж: раздел 6 (`pdfFrom == "original"`).

**А2. Невозможная печать слоя — запасная дорога, а не 503.** Письмо, которого
нет в шрифтах, или справа налево: «исходный вид» отвечает 503 словами,
формат «PDF» печатает Word (`layoutWhy`). Где: `_generate_export`.

**А3. Перевод надписи скана, легший подписью под картинкой, не теряется.**
Если `img_captioned > 0`, PDF скана печатается через Word (там подписи есть),
а не страницами-картинками. Скан без приложенного исходника — тоже Word.

**А4. Лист скана — размера оригинала** (`_orig_page_width`), а не A4;
страницы пишутся по одной (reportlab), а не все в памяти.
Страж: раздел 12г («лист скана — размера оригинала»).

## Б. Что есть строка и где она стоит

**Б1. Одна строка без места не отнимает раскладку у страницы.**
Симптом: у PDF-«ленты» CamScanner (2 страницы по 440×14 400 пт) раскладки
не было вовсе. Причина: одна повёрнутая подпись → `_geo_page` → None для всей
страницы, а страница — весь документ. Правило: строки без места — отдельно,
остальное по местам; больше половины ПОВЁРНУТЫХ строк — страница идёт
прежней дорогой (`GEO_PLACELESS_MAX`). Страж: раздел 12.

**Б2. Повёрнутость — по направлению базовой линии, а не по наклону.**
`Tm 1 0 0.21 1` — синтетический курсив Word/Chrome (и нашей печати), строка
стоит ровно. Повёрнута/зеркальна: (tm×cm) даёт базовую линию не вправо.
Где: `pdfpages_worker.vt`. Страж: раздел 12г («наклонная строка»).

**Б3. Повёрнутая строка встаёт в поток только после ПЕРЕНОСА слова.**
Иначе — отдельной вставкой в конце страницы. «Следующая строка со строчной»
как признак отвергнут: подпись оси схемы между строками фразы вливалась бы
в саму фразу. Где: `pdftext._geo_page` (`after`). Страж: раздел 12г.

**Б4. Невидимый текст — не текст страницы.** Две причины невидимости:
прямоугольная обрезка (`re W n`, стек q/Q) и непрозрачная векторная закраска,
нарисованная ПОСЛЕ текста (`_mark_covered`, прозрачность по `gs`/`ca` и `BM`).
Боевой случай: копия схемы, сдвинутая на 23 пт с иными цифрами («500–1000»),
лежала за обрезкой; абзац другого раздела — под заливкой. Правило: такая
строка — геометрия `[]` (не `None`), своей вставкой подряд идущих, в чужой
абзац не вливается и в порог Б1 не входит; её перевод не печатается.
**Картинка текст НЕ «накрывает»**: у скана с распознаванием слой текста
бывает ПОД снимком страницы, и снимок — это и есть тот текст.
Страж: разделы 12, 12д.

**Б5. Форма (Form XObject) — это q…Q.** Обрезка, шрифт и интервалы, заданные
внутри формы, после её `Do` отменяются (`visitor_operand_after`); шрифт и
`gs` внутри формы ищутся в ЕЁ ресурсах; обрезка и закраска внутри формы
не считаются (система координат формы нам не достоверна). Без этого форма-
логотип без q/Q прятала весь текст после себя. Страж: раздел 12д.

**Б6. Строка pypdf бывает двумя визуальными строками.** Надстрочная цифра
сноски между строками гасит разрыв: «Leicester, U.K.» + «²NIHR …» приходят
одной строкой. Текст строки менять нельзя (сверяется буква в букву), место —
можно: куски по базовым линиям → несколько мест (`_line_parts`). Строка,
начатая надстрочником, получает место по основному куску. Высоту строки
для разбора НЕ трогать — на ней стоит склейка дробей (`_join_scripts`).

**Б7. Конец строки — по оператору показа текста, а не по тексту куска.**
Причина: в куске pypdf нет чисел TJ (кернинг, сдвиги выключки), зато есть
вставленные им пробелы; по тексту выходило ±6 пт, у разрядки (Tc) — вдвое
шире листа. А `Font.character_widths` ключуется КОДОМ (chr(байт) у простого,
chr(CID) у Type0), не буквой — по букве бралась ширина чужого глифа (+40%
у Identity-H из Word). Правило (`op_end`, `_exact_ends`): сырые коды Tj/TJ →
ширины, числа TJ, Tc/Tw/Tz, перо копится между подряд идущими Tj, через
матрицы; оператор принадлежит строке, если на её базовой линии, начат
между её началом и началом её последнего куска, тем же шрифтом, видим.
Type3 и CMap не Identity — «не знаю». Замер: точный конец у 3780 из 3783
строк, медиана расхождения с краской 0. **Второй Tj того же BT** («Hello » Tj
«world» Tj — так пишут reportlab, генераторы «по слову», смена жирного внутри
строки) начинается дальше начала последнего куска pypdf (у pypdf все куски
стоят в начале матрицы): принадлежность строке — по НАЧАЛУ ЦЕПОЧКИ (матрица
без пера, `op_end` поле 6), иначе строка объявлялась «точной» с концом первого
оператора, и хвост оригинала оставался на листе. У повёрнутой строки точка
каждого оператора — тоже с пером (`op_rec`), знаки Type0 — без пробелов.
Страж: разделы 12а, 12м.

**Б8. Конец, которого нет, ищется по краске — узко.** От точного конца —
только краска ВПЛОТНУЮ (хвост выключки); от оценки — от начала последнего
куска до первого настоящего пробела. Никогда — за начало соседней строки
справа (`_neighbour_limits`: заголовок закрашивал колонку авторов) и за край
листа. **От точного конца — не дальше `INK_EXACT_SLACK` кегля** (0.6): без
потолка раздвижка шла по рамке плашки и стрелке схемы за подписью, и заливка
цветом стрелки выползала на рисунок («Consider specific factors» на кольце
схемы проекта 14). Влево у точной строки — только полпотолка: значок вплотную
к подписи («светофор» у «DO NOT JUST FOCUS») срезался.

**Б9. Строка pypdf бывает ДВУМЯ надписями одной базовой линии.** pypdf склеил
«making» (рамка посреди схемы, x 250) и «DO NOT JUST FOCUS» (левый край,
x 135) в «makingDO NOT JUST FOCUS»: базовые линии разошлись на 1.8 пт при
кегле 4.2 — для pypdf это одна строка. Правило: куски одной базовой линии,
разделённые зазором больше `SPLIT_GAP` кеглей (3) вправо от собранной части
или влево от её начала, — разные надписи; текст строки не меняется, место
делится по смещениям (`split` в геометрии), `pdftext._geo_page` режет строку
на части с собственными местами. Где: `pdfpages_worker._h_groups`.
Страж: раздел 12к.

**Б11. Текст и картинки внутри формы (Form XObject) — в координатах листа.**
pypdf исполняет форму со своей cm (координаты формы) и вдобавок отдаёт
текст формы ЕЩЁ РАЗ одним куском в её точке. Правило: точки внутри формы
переводятся на лист матрицей формы × cm у Do (`fmats`, вложенные — по
стеку); повтор текста формы помечается (`dups`), и если куски с ним не
складываются в ответ pypdf, геометрия строится без него — прежде такая
страница оставалась без раскладки целиком. Выход из формы — по отметке
своего Do (`dos`), а не по имени: у формы своё «/X0» бывает картинкой.

**Б10. Абзац рвётся там, где следующая строка его геометрически не
продолжает.** Поток pypdf ставит подряд заголовки схемы с разных концов листа
(«GOALS OF CARE…», «HOLISTIC PERSON-CENTERED…», «IMPROVING DETECTION…»), и
текстовые правила склейки (капс к капсу) делали из них один абзац — перевод
делился по долям и садился не на свои подписи. Правило (`_geo_follows`):
продолжение — ниже не дальше `CONT_DY` кеглей (2.4) с перекрытием по
горизонтали, либо та же строка, разорванная надвое, либо переход наверх
колонки правее или ЛЕВЕЕ (письмо справа налево) после строки колонки текста
(не короче `COLUMN_LINE_MIN` = 8 кеглей); другая страница — не судим.
`CONT_DY` = 3 кегля: двойной интервал (2.3–2.4) абзац не рвёт. Пока
вставка ждёт конца абзаца, геометрией его не рвём. Части одной строки
pypdf (Б9) колонками друг другу не свидетельствуют (`li` в `_multi_column`).
Страж: раздел 12к.

## В. Где печатать перевод

**В1. Перевод — в места строк, а не в прямоугольник абзаца** (`slots`).
Прямоугольник вокруг подписей схемы, склеенных в абзац, закрашивал
инфографику. Абзац-разброс (`_scattered`) получает перевод по доле оригинала
в каждом месте (`_spread`); абзац, разорванный рисунком в ТОЙ ЖЕ колонке,
разбросом не считается.

**В2. Не влезло — сперва сужение, потом кегль** (`HSCALE_MIN` 0.85, один
множитель на абзац). Письмо без пробелов (иероглифы, тайское, кхмерское,
бирманское) режется по знакам на КАЖДОМ шаге подбора, а разброс подписей
делит его по графемам — прежде вся строка вставала в первое место, а кегль
падал до самого мелкого. Подпись из одного слова — целиком, пусть вылезет.

**В3. Выключка — по краям строк оригинала** (`_slot_align`); отступ первой
строки и висячий отступ — «влево», а не «вправо»/«по центру».

**В4. Состояние текста — в q/Q на каждую строку**: Tz и обводка
«полужирного» иначе переходят на все следующие строки страницы.

**В5. Повёрнутая строка печатается повёрнутой, дуга — по дуге.** Путь строки
берётся из операторов показа текста (`op_rec`: точка, угол, кегль, конец
каждого Tj/TJ, `_rot_path`): прямая — начало и угол, дуга (у каждой буквы
свой угол) — узлы пути. Перевод прямой встаёт в повёрнутой системе координат
(`_draw_rot`), дуги — буква за буквой по пути, по центру дуги; не влез на дугу —
кегль уменьшается до её длины, не ниже `CURVE_MIN_SHARE` (у дуги нет следующей
строки). Пробелы между словами дуги — по зазору между концом буквы и началом
следующей (`_path_text`). Разные повёрнутые надписи подряд в потоке (дуга
кольца и вертикальная подпись рядом) — разные пачки (`_rot_follows`).
Страж: разделы 12е–12ж.

**В7. Заливка строки сверху — почти без поля** (0.05 кегля): выше прописных
лежат хвосты букв строки над ней, и у непереведённого абзаца при
интерлиньяже 1.15 их срезало.

**В6. Бумага и краска дуги — в КЛЕТКЕ каждой буквы** (`_arc_cells`: квадрат
вокруг середины буквы с учётом её угла). Замер по рамке всей дуги накрывал
само кольцо: «краской» выходил цвет кольца, и перевод его же цветом был
невидим; прямоугольник «вправо-вверх от узла» на крутом участке уходил
за кольцо и красил букву соседним цветом.

## Г. Как выглядит перевод

**Г1. Гарнитура — по ИМЕНИ шрифта** (`_family`): флаги файла врут (у Minion
и Calibri одно «Nonsymbolic»). Явное «serif»/«slab» сильнее списка рубленых
(«RobotoSlab»). Имя без гарнитуры («font0000000030790b66») — гарнитура
документа. Печатаем своим файлом той же гарнитуры (Noto из репозитория),
шрифт оригинала встроен подмножеством и букв перевода не знает.

**Г2. Файл шрифта — по буквам перевода** (`font_path(chars=)`); запасной —
DejaVu из репозитория (армянский, грузинский). **Письмо справа налево и со
сборкой букв** (арабица, иврит, индийские, тайское, кхмерское, бирманское,
иероглифы) печатается растром строки (`_Raster`: Pillow + raqm, шрифты Noto
из `frontend/vendor/fonts/sub`, у каждого знака — шрифт, где он есть, резка
только между графемами), кладётся картинкой в то же место. **Картинкой —
только абзац, которому это нужно** (`needs_raster`); метка направления
(RLM/ALM) письмом не считается. **Порядок — упрощённый двунаправленный
алгоритм Юникода** (`_bidi_levels`): цифры и латиница внутри письма справа
налево идут слева направо, нейтральные знаки — сторона соседей, основа —
от АБЗАЦА, а не от первой буквы строки; куски одного уровня и шрифта
переставляются по уровням, внутри куска справа налево буквы собирает raqm.
Ширина меряется тем же (полужирным) файлом, каким строка рисуется. Дуга со
сложным письмом печатается целиком по хорде (буква за буквой нельзя). **С 12.10.2026 такие строки печатаются КОНТУРАМИ, а не картинкой** —
см. раздел Н; картинка через raqm осталась запасной дорогой.

**Г3. Начертания нет файлом — дорисовать**: курсив наклоном, полужирный
обводкой (`_synth`). Полужирный по краске страницы НЕ ищем: на мелком кегле
штрих упирается в пиксель, обычный текст 4 пт выходил «жирнее» заголовка.

**Г5. Полужирный у шрифта БЕЗ имени — по контуру глифа.** Имя
«font0000000030790b66» начертания не говорит, флаги часто пусты. Порядок:
имя → дескриптор (FontWeight, ItalicAngle, Flags, StemV) → встроенный файл
(OS/2 usWeightClass, PANOSE, имя внутри файла) → толщина вертикального
штриха по КОНТУРУ глифов «l I | i n» (`font_weight.stem_ratio`, fontTools,
доля em, порог `BOLD_STEM` 0.115). Контур от кегля и разрешения не зависит —
этим он и отличается от краски. Замер: безымянный заголовок проекта 14 —
0.140, Helvetica 0.088, Calibri 0.081, Calibri-Bold 0.123.

**Г4. Цвет — краска оригинала**: преобладающий оттенок (синие рамки ссылок
не красят строку синим), самая тёмная четверть (сглаживание осветляет мелкий
кегль), у белой надписи на плашке — светлая сторона. Бумага под строкой —
самый частый тон, а не светлый процентиль (иначе на тёмной плашке — светлая
заплатка). Замер — на 144 точках на дюйм, не больше 12 Мп на страницу.

**Г6. Цвет букв — из самого PDF** (операторы g/rg/k/cs/sc/scn, ICCBased по /N,
стек q/Q и форм; `_set_fill`, `_chunk_color`): цвет строки — тем, которым
набрано больше её знаков, и он сильнее замера по картинке. Замер нужен,
когда цвета нет: узор, плашечный цвет, невидимый текст (Tr 3 — слой
распознавания под снимком). Боевой случай: чёрный заголовок 4 пт на
странице-ленте замерялся серым (сглаживание при 1.4 пикселя на пункт);
на мелком кегле крайняя доля замера сужена (5–10% вместо 25%).
Страж: раздел 12л.

## Д. Слова исходного языка в готовом PDF — проверка после сборки

**Д1. Каждая выгрузка «как в оригинале» проверяет сама себя.** Симптом:
на схеме остались STANDING, SWEATING, «Combined aerobic and resistance
training». Правило (`main._layout_leftovers`): после сборки считаются абзацы
без перевода, строки без места (`unplaced`) и надписи рисунков, которые не
читались, — числом и примерами (`stats.leftover`), браузер называет их
предупреждением, а метрики — событием `dead.pdfLeftover` (вид `fix`).
**Законно оставленное не считается** (`_leftover_kept`): числа, формулы,
адреса, имена файлов, аббревиатуры, которые и в переводе пишутся так же,
и строки, совпавшие с переводом буква в букву (правило «оставить оригинал»).

**Д2. Надписи внутри рисунка — тем же разбором, что у скана, и на своё
место.** Вырезка рисунка несёт метку, откуда она на листе (`importers.tag_figure`:
tEXt у PNG, COM у JPEG, пиксели те же), и рамка прочитанной надписи
переводится в долю листа (`_pdf_image_boxes`). Блок, под которым уже есть
строка текстового слоя, не читается и не заводится (`skip: "layer"`,
`LAYER_OVERLAP`): это дубль.

**Д3. Текст, нарисованный КРИВЫМИ прямо на странице** (нет ни в слое, ни
в растре рисунка), ищется на самой странице: виртуальная часть
`pdfpage/NNNN.png` — страница, отрисованная по требованию под замком pdfium
(`_PageRaster`, `PDF_PAGE_OCR_DPI`), блоки внутри уже вырезанных рисунков
отсеиваются (`skip: "figure"`). Чтение — только кнопкой «Надписи на
картинках», не авточтением при загрузке (это было бы чтение всей книги);
только у раскладки с местами строк (иначе слой не отсеять — дубль за деньги);
доля листа — от MediaBox (рисуется CropBox); повёрнутая страница не берётся;
не отрисовалась — «не знаю», а не обрыв задачи. Блоки слоя и рисунка
ждущими чтения не числятся. **Метка места на вырезке пиксели не меняет**:
картинка с меткой и без неё — та же (`importers.untag_figure`,
`_same_image`, `_docx_media_sha`) — пересборка старого проекта не теряет
оплаченный разбор надписей.

## Ж. «Лента» сканер-приложения и что из неё следует (проект 14, 11.10.2026)

**Ж1. Длинный лист — это стопка страниц.** Симптом: файл из CamScanner —
два листа 440×14 400 и 440×11 454 пт, внутри 46 страниц журнала;
«работать с ним тяжело», текст наезжает, подписи схемы не читаются.
Причина: каждая страница журнала в содержимом листа — группа
`q X Y W H re W n … Q` одного размера (417.5×550.4, шаг 561.6), а вся
постраничная логика разбора считала страницей лист: колонтитулы, колонки,
поля, снимок бумаги (потолок площади сжимал его до ~50 dpi), картинка
страницы под чтение надписей (880×28 800 пикселей — детектор её не видит).
Одна страница журнала разрезана между листами (347 + 203 пт).
Правило (`backend/pdf_panels.py`): `detect` ищет клипы групп верхнего уровня
почти во всю ширину листа, одной высоты H, не пересекающиеся, с пропорциями
страницы (H/W 1.0–1.8), лист не ниже 2H, страницы закрывают ≥ 90 % высоты
листов; неполные у краёв соседних листов с суммой ≈ H — ОДНА страница из двух
кусков. Не нашлось — None, и обычный PDF не меняется ни на байт. `compose`
пишет операторы листа ПРЯМО в содержимое страницы (не формой: внутри формы
разбор слоя не видит ни обрезки, ни закраски, ни ресурсов шрифта), только
группы, чей клип (прямоугольник или контур) пересекает кусок; `cm` между
группами — фильтр выключен. Самопроверка: каждая страница рисуется и
сравнивается с вырезкой листа (лист — с обрезкой ровно по куску, чтобы сетки
точек совпали; по клеткам 8×8), не сошлось — кусок берёт лист целиком
(`whole`). Краска листа вне страниц — отказ, а не обрезка. Дальше ВЕСЬ импорт
идёт по виртуальному PDF; план лежит в раскладке (`layout.virt`), и выгрузка,
чтение надписей страницы (`_pdf_page_png`) собирают PDF ЗАНОВО ПО ПЛАНУ
(`compose_plan`, `main._pdf_work_bytes`): координаты раскладки заданы планом,
а не поиском. Работа идёт отдельным процессом (`_run_child`): разбор
содержимого в 57 МБ — десятки секунд чистого Python. Замер: импорт 320 → 120 с.
Разбор надписей страницы помечен отпечатком плана (`vk`): разбор, сделанный
по листу, на виртуальную страницу с тем же номером не ляжет.
Страж: `tests/test_pdf_panels.py` (синтетическая лента).

**Ж2. Страница журнала, положенная БОКОМ, ставится прямо.** Симптом:
таблица 1 — строки ячеек склеены в одну повёрнутую строку, перевод одной
линией через весь лист, заголовок «Major adverse cardiovascular events»
вертикальной полосой поверх соседней страницы. Правило: ≥ 60 % знаков
страницы под ±90° (pdfium `FPDFText_GetCharAngle`) — страница поворачивается
матрицей (`rot`), и таблица разбирается обычными горизонтальными правилами.
Цена: колонтитул такой страницы становится повёрнутым.

**Ж3. Кегль текста, повёрнутого дважды, — длина вертикали знака.**
У повёрнутой таблицы на поставленной прямо странице диагональ матриц
`tm·cm` нулевая, и прежняя формула давала запасной кегль 1.0: строки рвались
на абзацы-строки, порог зазора `SPLIT_GAP` становился 3 пт. Правило:
`sy = |tm3·cm3| or hypot(vx, vy)` (`pdfpages_worker.vt`); где диагональ не
ноль, ответ прежний.

**Ж4. Ячейки таблицы — по колонкам, а не по строкам pypdf.** Причины:
(а) соседние ячейки стоят теснее `SPLIT_GAP` (1.7–2.4 кегля) — делим и по
началу колонки (`_col_starts`: икс, с которого после зазора начинаются куски
хотя бы двух строк, считая через границу строк pypdf по базовой линии;
конец куска — по оператору `op_end`, а не по оценке ширины); (б) маркер «•»
без букв приклеивается к СЛЕДУЮЩЕЙ части, а не к предыдущей ячейке;
(в) pypdf отдаёт таблицу построчно, и вторая строка ячейки шла после
соседей — `pdftext._table_streams` переставляет блок таблицы колонкой за
колонкой (таблица — ≥ 3 строк по ≥ 4 узких ячейки, медиана ячейки ≤ 0.2
ширины: три колонки текста страницы таблицей не считаются), а `tcol` =
(таблица, колонка, строка таблицы по первой колонке) запрещает абзацу
переходить в другую ячейку (`_geo_follows`). Страж: `test_pdf_panels.py`.

**Ж5. Пропущенная строка перед заглавной — новый пункт.** Симптом:
«Shared decision-making» + «Medication-taking behaviors» одним абзацем, между
ними «Self-efficacy» кривыми. Правило: зазор больше `GAP_BREAK` (1.6)
× min(межстрочный страницы, 1.3 кегля) перед строкой с заглавной/цифрой/
маркером, и прежняя строка не кончается переносом или запятой — разрыв.

**Ж6. Колонтитул с номером страницы.** Колонтитулы ленты стали находиться
(страницы теперь страницы), и «4 Consensus Report» печатался «2 …» на всех
страницах: перевод надписи один. Правило: у рамки повторяющейся надписи —
номер своей страницы (`num`), выгрузка подставляет его в перевод.

## З. Выгрузка: место, кегль, наложения

**З1. Свободная бумага рядом со строкой.** Место строки в инфографике — длина
английской подписи; русская длиннее, и подпись ужималась до половины кегля.
`layout_pdf._free_room`: докуда справа/слева чистая бумага в полосе строки
(ни краски, ни смены фона — светлая надпись на плашке за плашку не выходит),
с отступом `FREE_MARGIN` кеглей, не больше ширины самой строки; межколонник
уже `FREE_MARGIN + FREE_MIN` — колонка текста не растёт. `_fit_slots`
берёт запас, только если в своё место не влезло.

**З2. Один кегль у надписей одного стиля на странице.** `_harmonize`: класс —
страница, гарнитура, начертание, кегль оригинала; кегль класса — нижний
квартиль нужного абзацам, не мельче `HARMONY_FLOOR`; тесным — свой, числом
(`harmonyOutliers`). Узкое начертание оригинала (`c` в стиле: Condensed,
Narrow) печатается сжатым (`HSCALE_COND`) у всех таких строк.

**З3. Наложения ищутся ДО отчёта «готово».** `_resolve_collisions`: у каждой
напечатанной строки — прямоугольник; строка, вылезшая за своё место (запас
бумаги, хвост под последней строкой), на чужой перевод, на оставленный
оригинал или за край листа — абзац теряет запас, потом ужимается до
`FLOOR_HARD`; не помогло — `collisions`, страницы и строки проекта
(`collisionSegs`), экран «Скачать» показывает их кнопкой. Наложения самого
оригинала не считаются.

**З4. Касание полос строк — не сосед.** `_neighbour_limits` обрезал строку по
началу строки НИЖЕ того же абзаца (тесный интерлиньяж, строка по центру):
хвост «ional microvascular/» оставался рядом с переводом. Сосед — только при
перекрытии по высоте больше 0.3 кегля. Конец строки, начатой с номера
(«4  Consensus Report»), не обрывается на широком пробеле до 0.75 оценки
длины (`INK_INNER_SHARE`); светлая краска на цветной плашке — тоже краска
(`_ink_cols`).

**З5. Листы при выгрузке — выбор человека.** «По страницам» (виртуальный PDF)
или «как в файле» (`pdf_panels.unsplit`: страницы с переводом обратно в
листы, каждая на своё место, под своим углом, со своей обрезкой). Экран —
`ExpSheetsPick` с картинками-схемами.

## К. 1в1 по сверке проекта 14 со страницами оригинала (11.10.2026)

Сверка выгрузки EN→RU со страницами оригинала (стр. 1, 4, 6–10, 12, 19, 28,
31, 43). Замер по всей книге — `stats.sizeMedian` / `smallShare` (доля ЗНАКОВ
перевода мельче 0.8 кегля оригинала): было 0.60 / 82%, стало 0.89 / 10%.

**К1. Абзац перевёрстывается в свою колонку, а не «строка в строку».**
Симптом: колонки, ячейки таблиц и плашки печатались кеглем 0.6 при прежних
интерлиньяжах — «пустые полосы между мелкими строками». Причина: `_fit_slots`
кладёт в каждое место строки оригинала ровно одну строку перевода, и русский
текст, длиннее английского на 20–35%, можно было только ужать. Правило
(`_fit_flow`, `_regrid`, `_lay_flow`): места колонки (`_runs` — подряд, шаг
0.5–2.6 кегля, перекрытие по горизонтали) строятся заново под кегль f с
шагом × f (и × `LEAD_SQUEEZE` 0.93, если это даёт заметно крупнее), от
базовой линии первой строки до последней плюс свободная бумага под колонкой
(`_free_below`: чистая по всей ширине, с зазором `FREE_BELOW_GAP` шагов до
чужой краски, не больше `FREE_BELOW_LINES` строк — интервал между абзацами
так не съедается). Ширина строки — медиана ПОЛНЫХ строк, начертание новых
строк — большинства. Из двух ответов берётся лучший по `_fit_score` (кегль
+ ½ сужения). Закраска — по местам ОРИГИНАЛА (`fill_by`), печать — по новым.
Страж: `tests/test_reflow_paint.py` (1, 1а, 10).

**К2. Соседние абзацы одной колонки — одна текстовая рамка** (`_flow_groups`,
`_linked`: та же страница, кегль ±25%, перекрытие, ниже не дальше
`FRAME_LINK_MAX` шагов). Пункт в ячейке таблицы, которому тесно, сдвигает
короткого соседа вниз; оба — одним кеглем; разрыв между абзацами — из
оригинала × f. Берётся, если общий кегль крупнее самого мелкого. Страж: (5).

**К3. Ширина начертания — измеренная, а не по имени** (`_width_ratio`,
`_h0_of`): Σ ширин строк с точным концом ÷ Σ(знаков × кегль) против нашего
шрифта на ТОМ ЖЕ исходном тексте; медиана по классу стиля (гарнитура,
начертание, кегль) во всём документе — короткая подпись берёт ширину класса.
Calibri уже Noto Sans на 12%, DIN Condensed — на 25%. Страж: (4).

**К4. Переносы и выключка.** Переносы по словарю языка перевода (pyphen;
языка нет — нет), составное слово — по своему дефису на любом языке
(`_hyph_split`); выключка по ширине — у абзаца, выключенного так в
оригинале (`_justified`), пословно (Tw у подмножеств TTF не действует),
пробел не шире `JUSTIFY_MAX_GAP` кегля — иначе строка влево (без «рек»).
Растр и письмо без пробелов не выключаются. Страж: (2, 3).

**К5. Перевод = оригиналу не печатается** (`main._same_as_source`,
`_layout_texts(same=)`): NFKC, без мягких переносов и невидимых знаков,
пробелы свёрнуты; пунктуация и цифры не нормализуются. Литература, название
журнала, числа остаются ПИКСЕЛЯМИ оригинала — прежде они перепечатывались
нашим шрифтом по нашим местам кашей. Пропущенная голова в `written` не идёт:
хвост склейки не стирается. Отчёт: `stats.identical`. Страж: (6).

**К6. Свободная бумага вбок — только однострочной подписи**
(`FREE_MAX_LINES` 1, `FREE_MAX_SHARE` 0.6): трёхстрочный пункт внутри плашки
уходил вправо за плашку на поле листа. Многострочному есть перевёрстка.

**К7. Сплошная заливка — не буквы** (`_ink_end`, `SOLID_INK_*`): столбцы, где
краска занимает ≥ 0.7 высоты строки сплошь шире кегля, — тень плашки, рамка,
полоса таблицы; конец строки встаёт до них. Страж: (9).

**К8. Надпись на картинке — как в оригинале** (`backend/text_paint.py`;
PDF — `layout_pdf._paint_measure/_paint_plan/_paint_text/_paint_arc`,
docx/скан — `image_text._paint_plan/_paint_put`). Замер по пикселям вырезки
(PDF рендерит участок до ~28 точек на кегль, `_Sampler.crop`): маска — точки,
отличные от медианы окрестности и близкие к ОДНОМУ цвету краски (край
плашки и кольца схемы — другого цвета), без областей, касающихся края
вырезки (это соседняя надпись); кегль — по верхнему децилю высоты букв
(÷ 0.73, строчные без выносных — ÷ 0.53), полосы строк — только для мест
строк; полужирный — толщина штриха / кегль ≥ `BOLD_STEM`; угол — главная
ось маски у однострочной рамки, не вытянутой вширь; дуга — окружность через
середины букв, если она описывает их заметно лучше прямой (`_arc_of`).
Не надпись: маска шире `MASK_MAX_COVER`, буквы-крошки (`LETTER_MIN_*`),
меньше половины точек в областях размером с букву, текстура фона выше
`TEXTURE_MAX`. Стирание: ровный фон — заливка, неровный — `cv2.inpaint` по
расширенной маске букв; в PDF заплатка прозрачна вне маски. Печать: рубленым,
цветом краски, измеренным кеглем и шириной начертания, перенос строки
перевода — новая строка (заголовок блока, пункты «•»), выключка блока,
по центру строк оригинала; повёрнутая — под её углом; дуга — буква за
буквой по дуге, верх букв как у оригинала. Подписи под картинкой больше
нет: пёстрый фон без выделимых букв — плашка цвета фона в самой картинке.
Рамка «одна строка, выше ширины» при горизонтальных буквах — отказ
`vertical` (угол неизвестен). Страж: (7), `tests/test_image_text.py`,
`tests/test_image_scan.py`.

**К9. Сверка надписей со слоем — построчно** (`main._mark_layer_blocks`,
`LAYER_RULE` 2). Симптом: «Self-efficacy» между пунктами слоя и строки
таблицы стр. 10 («VLED and formula meal replacement…») не переводились
вовсе. Причина: детектор склеил кривые строки со строками слоя в один блок,
и блок целиком ушёл в `skip: layer`. Правило: блок хранит рамки строк
(`lineBoxes`), строки вне слоя — новыми блоками В КОНЕЦ списка (номер блока —
связь с сегментом). Прочитанные прежде записи (`layerRule` < 2) сверяются
заново при следующем разборе (`_relayer_old`: локальный детектор только по
блокам слоя, дубли с имеющимися блоками не заводятся); разбор ставится сам
при открытии файла (`_auto_relayer_kick`, один раз на версию правила).
Страж: (8).

**К10. Самопроверка размера** (`_size_report`): `sizeMedian`, `smallShare`,
`smallPages` — в отчёте выгрузки рядом с наложениями и остатками языка;
экран «Скачать» называет их одной строкой (`ExpSmallText`).

**К11. Блок картинки, повторяющий текст слоя под ним, не печатается**
(`main._dup_of_layer`, `LAYER_DUP_SHARE` 0.3, `skipped.layerDup`). Симптом
(стр. 19): столбец схемы напечатан дважды — абзацами слоя и блоком разбора
страницы поверх, крупно. Причина: прежнее правило сверки со слоем считало
ПЛОЩАДЬ, а столбец схемы — это рамки и пустота. Слова блока сверяются со
словами строк слоя, стоящих ПОД блоком (по месту, не по странице: подпись
к рисунку с теми же словами повтором не делает).

**К12. Прочитанный смешанный блок пересверяется построчно**
(`_relayer_old`): у страницы PDF многострочный блок, часть строк которого
— напечатанный слой, а часть — растр под невидимым (закрытым) слоем, делится:
старый блок перестаёт печататься (его перевод в проекте цел), строки вне
слоя — новыми блоками в конец, к чтению и переводу. Так находятся строки,
которые стояли английскими: «Efficacy for glucose lowering», «Consider
medication for weight loss», «Pioglitazone» (стр. 19). Детектор — по вырезкам
блоков. Новый разбор ставит новые блоки рядом с родителем.

**К13. Столбец схемы из нескольких плашек печатается по участкам**
(`text_paint._areas`, `split_text`; у блока и в .docx, и в PDF): участки —
строки на одном фоне без большого разрыва; перевод делится по его переносам
строк, иначе по словам, пропорционально краске участка. Новый разбор не
собирает в один блок строки разного фона (`image_text._bg_of`,
`IMG_BG_SAME`).

## Л. Единый набор: один кегль, одна выключка, ничего поверх (проект 14, 12.10.2026)

Жалоба: «шрифты разноразмерные, разные отступы и интерлиньяж, текст налезает,
закрашивание выходит за рамки, на стр. 34+ нет перевода, адрес транслитерирован,
аббревиатуры местами латиницей, местами кириллицей». Мера — `stats.fClasses`
(по классу стиля: мода кегля и доля знаков НЕ этим кеглем, `offShare`) и
`stats.fOffShare` по всему документу. Замер на проекте 14: основной текст
`offShare` 0.77 → 0.00, весь документ 0.74 → 0.09.

**Л1. Выключка — по ВИДИМЫМ строкам** (`_vis_lines`, `_slot_align`, `_justified`).
Симптом: строки колонки «по центру/вправо» (стр. 17). Причина: строка pypdf
режется на два места на ссылке и на смене шрифта, а у абзаца с заголовком
в подбор первая строка начинается на 50 пт правее — `_slot_align` отвечал
«вправо». Правило: места одной базовой линии вплотную (зазор ≤ 1.5 кегля) —
одна строка; все строки, кроме первой, с одного края — «влево» при любой
первой; «по центру» — только если середины всех строк совпадают и последняя
строка не от общего края; «по ширине» — по каждой колонке абзаца отдельно.
Страж: `tests/test_pdf_unified.py` (1).

**Л2. Строка — одним кеглем и начертанием абзаца.** Кегль строки pypdf — кегль
её ПЕРВОГО куска: строка, начатая заголовком в подбор («Colchicine.» 5.25 при
теле 6.65), считалась мельче, рвала колонку строк (`_runs`) и задавала шаг
строки. Правило: в перевёрстке у строки абзаца кегль большинства строк
(`_regrid`, `_stories`), у абзаца от трёх строк — и начертание большинства
(полужирная первая строка целиком — брак хуже потерянного полужирного слова).
Страж: (2).

**Л3. История страницы** (`_stories`, `_story_link`, `_story_join`). Абзацы
одной страницы верстаются подряд, одним кеглем, по своим колонкам, и тесноту
одного забирает пустота под соседним. Связи: «v» — ниже в той же колонке
(заголовок крупнее тела или мельче, но выделенный, до 2×; мелкий обычный —
сноска, не связь); «c» — наверх соседней колонки ТЕКСТА (от 12 кеглей шириной,
от трёх строк, та же ширина ±15%); «inline» — заголовок в подбор (тело
начинается на последней строке заголовка, правее него, а вторая строка тела
возвращается к левому краю колонки — у ячеек таблицы она возвращается под
ячейку, и они не сцепятся) и фраза, разорванная разбором (последняя строка
полная, нет знака конца фразы, нет отступа). История не переходит через смену
бумаги (полоса таблицы → ячейка, `STORY_PAPER_DELTA`) и через страницу: абзац,
разорванный страницей, делится на куски по доле строк. Область строки —
колонка области, а не рамка абзаца по высоте оригинала (история сдвигает
текст). Заголовок не остаётся последней строкой колонки; заголовки без
переносов. Части одной видимой строки сливаются (`_merge_line_slots`):
иначе кусок со ссылкой открывал «новую колонку» на той же высоте и строка
печаталась поверх строки. Страж: (3, 4, 5).

**Л4. Кегль ступенями, потолок у класса** (`STORY_STEPS`, `STORY_Q`). История
берёт самую крупную ступень, на которой укладывается; у класса стиля
документа (гарнитура, начертание, кегль оригинала) потолок — ступень, которую
держат 75% его знаков. Кому тесно — ступенью ниже (`storyOutliers`), а не
«своим числом». Наложение у истории — вся история ступенью ниже
(`_story_relay`). Подписи и ячейки (не история) — один кегль класса на
странице, нижняя четверть нужного (`_harmonize`, `HARMONY_Q` 0.25).
Страж: (4).

**Л5. Выключка по ширине в истории** — пробел до `JUSTIFY_MAX_GAP_FLOW`
(1.6 кегля): рваная строка посреди ровной колонки заметнее широкого пробела.

**Л6. Свободная бумага вбок — до начала соседней колонки** (`lim2` в
`_neighbour_limits`): ближайшее начало строки правее в строках ±3 кегля.
У таблицы без линеек пустая ячейка — чистая бумага, и подпись уезжала в
соседнюю колонку. `FREE_MAX_SHARE` 1.0. Страж: (6).

**Л7. Наложения считаются по всему напечатанному** (`_resolve_collisions`):
перевёрстанные строки (`_v`), хвосты, надписи картинок (`img_plan`) и рамки
без мест (`plan`); надписи картинок только называются (`collisionImages`).

**Л8. Кусок слоя внутри надписи, нарисованной кривыми** (`main._pdf_image_boxes`,
`erase`): «vs.» посреди строки таблицы лежит текстом, остальная строка —
кривыми и прочитана с картинки целиком. Перевод надписи уже содержит кусок,
и абзац слоя печатал бы «по сравнению с» второй раз. Правило: абзац слоя до
четырёх слов, рамка которого ≥ 80% внутри рамки надписи, а слова — подряд
в её оригинале, только стирается (пустой перевод названного абзаца — закраска
без печати, `build`). Вложенные надписи (`_drop_nested_labels`): вложенность —
по площади (≥ 85%), а не по пикселю; многострочный РОДИТЕЛЬ уступает
однострочным наследникам, если их слова покрывают ≥ 80% его слов (наследники
— строки, выделенные пересверкой К12), иначе снимаются наследники.

**Л9. Надпись рисунка без маски букв — рубленым и без заплатки** (`onFig`,
`PAINT_FALLBACK_FLAT`): у вырезки рисунка, где буквы не выделились по пикселям
(дуга кольца, градиент), прямоугольник цветом полос ложился заплаткой
(«СРЕДИЗЕМНОМОРСКАЯ ДИЕТА», «УКРЕПЛЕНИЕ»). Больше четверти полос другого
цвета — не печатаем, остаётся оригинал (`figureUnpainted`). Цвет букв — по
краске вырезки. Кегль надписи не крупнее строки её рамки (в маску попадал
значок рядом: «Глаз» вдвое крупнее «Eye»). Страница-скан (`_png_page_index`)
под это правило не попадает: там фон — бумага.

**Л10. Текст к печати** (`main._print_by_id`; проект не меняется, выгрузки
.docx 1в1, PDF 1в1 и в исходном формате печатают одинаково):
а) **литература** — оригиналом, если в строке зоны (`_refs_of` keep) машинный
перевод (переведена до правила «как в оригинале»); работа человека не
трогается. Зона тянется к началам нумерованных записей цепочкой (≤ `REFS_ZONE_GAP`
строк) — запись №1 и записи на стыке кластеров (`REFS_RULES` 2). Решение
пользователя 12.10.2026: литература — на языке оригинала, единообразно.
Проверка остатков (`_layout_leftovers`) такие строки не считает;
б) **адрес** (URL, DOI, e-mail, домен с путём) — буква в букву: калька
(«хттпс://дои.орг/10.17605/осф») узнаётся по скелету из цифр и знаков и
нелатинской букве (`_keep_verbatim`); адрес, разорванный переносом строки
оригинала («osf» | «.io/pu93h»), склеивается (`_glue_urls`, `_join_targets`).
То же — сразу в переводе (`_openai_translate`) и правилом 6 промпта;
в) **метка-сокращение** — как её определил сам документ («Low-energy
ketogenic diet (LEKD)» → «(НЭКД)»: метка схемы «LEKD», «VLEKD» → «ВЛЕКД»,
«VLED» → «ВНЭД (очень …)» печатаются «НЭКД», «ОНЭКД», «ОНЭД») — только когда
оригинал строки и есть сокращение; ответ — у варианта с ≥ 2/3 голосов
(`_abbr_map`). Сокращение внутри фразы не трогается (латиница в русском
медицинском тексте бывает законной), несколько меток одной строкой — тоже
(это две дуги одним путём). Страж: (7).

## М. Сверка выгрузки (5) критиками: маркеры, подзаголовки, глифы, литература (проект 14, 12.10.2026)

Жалоба: «испортилась вёрстка» (таблица редактора) и «некорректные вставки
вёрстки» в выгрузке PDF. Три критика сверили 46 страниц с оригиналом.
Правила разбора подняты до `RULES_VERSION` 11 — открытый проект пересоберёт
строки сам (раздел И), изменившиеся строки ждут «Перевести».

**М1. Имена глифов — буквы** (`pdftext._glyph_names`, в `_clean_line`).
Симптом: в оригинале строки «/uni0056/uni0069/uni0065/uni0077…» и «BMI
/uni226530 kg/m2». Причина: у шрифта без ToUnicode pypdf отдаёт имена глифов.
Это не косметика: «≥30» терял знак (26 абзацев: ≥, ∼, β, α). Правило:
`/uniXXXX` и `/uXXXXX` → знак, после раскладки строки (части `split`
режутся по смещениям в сыром тексте). Повторный импорт считает «/uni2265»
и «≥» одним текстом (`main._match_key`) — перевод таких строк не
сбрасывается. Страж: `tests/test_pdf_heuristics.py` (M).

**М2. Разрядка — слова** (`pdftext._unspace`). Симптом: «AH O L I S T I CA N T I
C I P A T O R Y…», «P.T. s e r v e s o r h a s…» — строка без места переноса
распирала колонку оригинала в редакторе. Причина: межбуквенный интервал (Tc,
выключка по ширине) — pypdf ставит пробел за каждой буквой. Правило: серия
от 8 токенов, на 75% из одиночных знаков, собирается; одиночный пробел —
внутри слова, двойной — между словами, две ПРОПИСНЫЕ буквы токеном — стык
слов («AH» = «A» + «HOLISTIC»). Римские номера и перечни под правило не
попадают (одиночных мало). Страж: тот же.

**М3. Маркер «•», прилипший к слову, — на рамку абзаца** (`bulch` → рамка
`bullet` → `layout_pdf._with_bullet`). Симптом: пункты рекомендаций печатались
голыми абзацами с висячим отступом, пункт без пропуска строки склеивался
с соседним. Причина: чистка мусора снимала «•» вместе с украшениями.
Правило: строка, начатая маркером, — начало абзаца (`bul`), знак запоминается
на рамке и печатается перед переводом. В текст сегмента маркер НЕ входит —
иначе каждый пункт ушёл бы в перевод заново. Страж: `test_pdf_heuristics.py`
(M), `test_pdf_unified.py` (10).

**М4. Подзаголовок кончается сменой начертания и кегля** (`pdftext._heading_ends`).
Симптом: «Консенсусные рекомендации Системы здравоохранения…», «Возраст:
пожилые люди с диабетом Возможности принятия…» — заголовок внутри фразы
(стр. 11–32, ~35 мест). Причина: строка заголовка (b/bi, 5.25–5.95) и строка
тела (6.65) — соседние, геометрия продолжения выполнялась. Правило: строка
выделенного начертания ДРУГОГО кегля, за которой идёт обычная строка, —
конец абзаца. Не рвут: вводный заголовок в строке текста
(«Hypercortisolism.Hypercortisolism may» — после точки идёт текст),
продолжение со строчной или скобки, перенос на конце. Строка тела, начатая
курсивным словом, того же кегля — не заголовок. Страж: `test_pdf_heuristics.py` (M).

**М5. Строка-адрес колонкой не продолжается** (`_URL_LINE_RE` в `_geo_follows`).
Симптом: «https://doi.org/10.2337/dci26-0141 Мелани» — колонка авторов справа
вклеилась в строку DOI под заголовком (правило «переход наверх соседней
колонки»). Правило: строка, целиком являющаяся адресом/DOI, — свой абзац.

**М6. Название статьи между записями литературы — часть записи** (`main._refs_of`,
`REFS_RUN_MAX`). Симптом: посреди списка «как в оригинале» мелкие строки
перевода («Натрий-глюкозный котранспортер…», «Финеренон и клинические
исходы…»), стр. 34, 41, 43. Причина: строка без признаков ссылки бралась в
зону, только будучи зажатой записями с ОБЕИХ сторон по одной; «FIDELIO-DKD
… Investigators.» + название — две такие подряд. Правило: серия до трёх
таких строк, зажатая записями, — часть записи. Страж: `test_pdf_unified.py` (10).

**М7. Заголовок в конце потока остаётся на месте** (`layout_pdf._stories`).
Симптом: «Литература» поднималась за ужатым текстом выше, а её список
(печатается оригиналом) оставался внизу — пустая полоса между ними (стр. 34).
Правило: кусок-заголовок, которым кончается цепочка истории, из истории
снимается и печатается на своём месте. Страж: `test_pdf_unified.py` (10).

**М8. Таблица редактора не распирается строкой без пробелов**
(`.tbl .src-cell, .tbl .tgt-cell` в `styles.css`): оригинал и перевод — по 44%
ширины, `overflow-wrap: anywhere` (у таблицы колонку считает наименьшая
ширина содержимого, и `break-word` её не уменьшает).

## Н. Вставка текста любой письменности: бесплатные модули (12.10.2026)

Задача — не перевод, а ВСТАВКА: текст любого языка ложится в вёрстку
оригинала поверх прежнего. Что изучено и что взято:

| Модуль | Лицензия | Что делает у нас |
|---|---|---|
| reportlab | BSD | слой поверх страницы, простое письмо — настоящим текстом |
| pyphen | LGPL/GPL/MPL | переносы по слогам при перевёрстке (К) |
| fontTools | MIT | таблицы знаков, толщина основы (полужирный) |
| OpenCV inpaint | Apache-2.0 | стирание надписи на картинке (`text_paint`) |
| **uharfbuzz** (HarfBuzz) | Apache-2.0 / MIT | **новое:** сборка букв и контуры глифов (`glyph_shaper.py`) |
| **BudouX** | Apache-2.0 | **новое:** перенос строки без пробелов по границе фразы |
| Pillow + raqm | HPND / MIT | теперь запасная дорога картинкой |

Не взяты: BabelDOC, PDFMathTranslate, PyMuPDF (AGPL — сервис по сети
обязан был бы открыть весь свой код), manga-image-translator (GPL),
PyICU (нужна системная libicu на сервере), fpdf2 (LGPL, другой холст —
это переписывание; изучено как образец: вшивает подмножество шрифта
с ToUnicode, то есть текст после сборки копируется).

**Н1. Строка со сборкой букв — контурами** (`glyph_shaper`). Симптом:
арабица, иврит, индийские, тайское, кхмерское, бирманское и иероглифы
печатались картинкой 4 пикселя на пункт — мыло при увеличении, тяжёлый
файл, ширина округлена до пикселя; без raqm в Pillow (Windows, часть
сборок) выгрузка отказывала совсем. Правило: тот же HarfBuzz, что внутри
raqm, собирает строку, а глифы уходят в PDF путями. Порядок кусков справа
налево считает по-прежнему `_bidi_levels`, внутри куска — HarfBuzz
с ЯВНЫМ направлением (угадывание на куске из знаков препинания ошибается).
Каждый разный глиф — одна форма (Form XObject) на документ, кэш форм — на
холсте (форма другого документа в этом не существует), в теле формы нет
цвета. Полужирного файла нет (иероглифы) — обводка контура
(`LAYOUT_VECTOR_BOLD`, доля кегля). `LAYOUT_VECTOR=0` — прежняя картинка.
Отчёт выгрузки: `stats.shaper` (vector | image), `stats.notdef` — знаки,
которые шрифт так и не собрал (глиф 0 после сборки; таблица знаков этого
не видит). Тест: `tests/test_glyph_shaper.py` (1–5).

**Н2. Знак препинания — из шрифта, который его знает** (`_Raster._path_of`).
Симптом: «(نص)» — скобки квадратами: знак препинания оставался в куске
соседней буквы, а в Noto Naskh Arabic скобок нет. Правило: пробел
и огласовка — всегда с соседом, знак препинания — только если шрифт соседа
его знает. Строка, начатая пробелом, — основным шрифтом (прежде искался
файл с пустым именем). Тест: раздел 6.

**Н3. Строка без пробелов — по границе фразы** (`_break_point`, BudouX).
Симптом: японский, китайский и тайский резались «сколько влезло знаков» —
посреди слова. Правило: граница фразы не дальше влезшего и не ближе
`LAYOUT_PHRASE_FILL_MIN` (0.6) от него, иначе прежняя резка не посреди
буквы. Модель — по буквам строки (тайское, кана → японская, иначе
иероглифы → китайская упрощённая). Тест: раздел 7.

## О. Десять критиков выгрузки проекта 14: один источник, история, плашки (12.10.2026)

Разбор десяти скриншотов десятью критиками дал пять корней, а не десять
дефектов. Стражи — `tests/test_pdf_holes.py`.

**О1. Одно место — один источник** (`main._pdf_image_boxes`). Симптом:
слова слоя поверх перевода надписи («влиять», «(например,» на плашке
стр. 19), огромное «Глаз» поверх «Глаз» слоя (стр. 4). Причина: защиты
«кусок слоя внутри надписи» и «надпись повторяет слой» сравнивали СЛОВА
и имели пороги по их числу — рваный слой («a!ect»: лигатура ff знаком
«!»; «(e.g.,» — ни одного слова от двух букв) и однословная надпись
(«Eye») под них не попадали. Правило: сверка по БУКВАМ И ЦИФРАМ
(`_alnum`, лигатуры раскрыты): кусок слоя на ≥80% площади внутри
печатаемой надписи и чьи буквы стоят в её тексте подряд на ≥0.7
(`_piece_in`, `LAYER_PIECE_SHARE`), до `LAYER_PIECE_WORDS` слов —
стирается; надпись, совпавшая с абзацами слоя внутри неё
(`_same_text`: короткие — буква в букву, длинные — сходство ≥0.9), НЕ
печатается, если у тех абзацев есть перевод (`skipped.layerSame`), —
слой точнее по месту и кеглю (рамка надписи захватывает и значок).

**О2. История не переходит через нарисованное** (`layout_pdf._drawn_below`,
`_drawn_between`, `LAYOUT_STORY_INK`). Симптом: «зачёркнутые»
Благодарности (абзац поднят на серую линию, стр. 33), пункты таблицы
поверх строк, которые есть только в картинке (стр. 10). Причина:
`_blocked` видел только строки СЛОЯ, а у скана линия и растровая строка —
пиксели. Правило: под последней строкой колонки меряется первая краска
вне рамок строк слоя — линия (≥60% ширины в одном ряду), полоса краски
(≥0.35 кегля высотой при ≥8% ширины) или другой фон; если она выше
первой строки следующего куска — сцепки «v» нет.

**О3. Ячейки и отступ** (`_cells`, `_row_mates`, `LAYOUT_STORY_V_X0`).
Симптом: перевод ячейки «Potential benefit» уехал в шапку таблицы
(стр. 6), пункты списка съехали влево на галочки (стр. 31). Правило:
два однострочных узких (<12 кеглей) куска, у которых в том же ряду есть
соседи, — ячейки, не история; допуск левого края «v» — 1.5 кегля
(было 3: отступ пункта в два кегля проходил).

**О4. Строки плашки — один абзац** (`pdftext._merge_label_lines`).
Симптом: «ЗДОРОВЫЙ ОБРАЗ ЖИЗНИ ПОВЕДЕНИЕ», висячий «ДИАБЕТА-», два
кегля в одной плашке (стр. 19). Причина: строки плашки идут в потоке
вперемешку со строками соседних плашек и переводились порознь. Правило:
части КАПСОМ до двух строк, одной оси (центр или левый край ±0.6
кегля), одного кегля и начертания, шаг ≤1.6 кегля, без чужой строки
между ними, первая не кончается знаком конца фразы, — один абзац;
дефис на стыке сохраняется у составного слова и снимается у переноса
(`_joins_to_word`).

**О5. Две надписи в одной строке pypdf** (`pdfpages_worker._h_groups`,
`V_SPLIT_GAP`; `pdftext._apart` для блоков вставок). Симптом:
«PROGRAMS THAT ADDRESS:24-H PHYSICAL» → «…ЩИЕ: 24-ЧАСОВУЮ…» (стр. 4).
Причина: деление строки было только для кусков ОДНОЙ базовой линии.
Правило: кусок другой базовой линии, не пересекающийся по горизонтали
с собранной частью (зазор ≥1 кегля), с буквами и не надстрочник, —
другая надпись (`split`); строки вставки/заголовка без пересечения по x —
разные абзацы. Замер на всей книге: меняются ровно 5 мест, все целевые.

**О6. Перечень через «/» и дуги** (`_hyph_split`, `_harmonize_arcs`).
Слово-перечень рвётся после «/», если обе части — от трёх букв и нет
цифр и адресов («и/или», «mg/kg», даты — нет). Дуги одного кольца
(общий центр ±0.35 радиуса, кегль ±20%) — к меньшему множителю,
но не мельче `LAYOUT_ARC_HARMONY_KEEP` (0.85) своего.

**О7. Варианты через « / »** (`main._variant_misses`, находка `variants`;
правило 10 в промптах перевода и ремонта). Симптом: «ШАГАНИЕ / ШАГОВЫЙ
РЕФЛЕКС / СТЕППИНГ» в подписи схемы. Бесплатная находка, если у
оригинала косой черты нет; входит в ремонт, его приёмку (`_free`),
бесплатные сверки ревизии.

Названная цена: абзац, которому история больше не даёт места после
линии или рамки, печатается своей рамкой и ступенью класса кегля — мельче
соседей («Благодарности», заголовок плашки «ДИНАМИЧЕСКОЕ НАБЛЮДЕНИЕ»).

## П. Остаток после десяти критиков: разрывы слоя, повёрнутая таблица, узкие ячейки, дуга (12.10.2026)

Стражи — `tests/test_pdf_holes.py` (разделы П1–П4), сравнение разбора
целых книг прежним и новым кодом (проект 14 и боевые книги 8 и 19: у 8 и 19
изменений нет, у 14 — только ряды повёрнутой таблицы).

**П1. Разрыв строки слоя** (`pdfpages_worker._line_gaps` → поле 10 места
строки; `main._mark_layer_blocks`, `_gap_blocks`, `LAYER_RULE` 3,
`LAYER_GAPS=0` — выключить). Симптом: обрывок «1с, снижение массы тела…»
(стр. 10) — голова строки «Beneficial effect on HbA» есть только в картинке,
а слой несёт «•» и «1c, body…». Причина: строка слоя при сверке — прямоугольник
от начала до конца, и промежуток между её кусками считался покрытым; строка
картинки отсеивалась как «уже в слое». Правило: разбор записывает разрывы
строки — промежутки между кусками одной базовой линии от 2.5 кегля по точному
концу куска (от 4 по оценке; выключка по ширине и табуляция этого не дают),
у строк с надстрочником (`parts`) — нет. Сверка режет прямоугольник строки
слоя по разрывам; непокрытый кусок строки картинки становится своей надписью
ТОЛЬКО если лежит на разрыве (конец строки слоя — оценка, и «непокрытый
хвост» у края был бы платным дублем), и своим блоком, не склеиваясь с
соседними строками. Пересверка: записи правила 2 берут только блоки на
разрывах и добавляют только куски на разрывах — прежние решения по остальным
строкам не пересматриваются; строка, по которой уже есть решение («шум»,
«надпечатка»), заново не заводится. Карта без разрывов (разбор до правил 13)
пересверке не подлежит; пересборка с исходом «same» (абзацы те же) переносит
разрывы в карту проекта там, где место строки совпало по геометрии
(`_merge_layout_fields`), — иначе правило не дошло бы до книг без изменений
абзацев. Индекс разрывов — один обход карты на раскладку (`_gap_index`).
Цена: голова и хвост фразы — разные строки перевода.

**П2. Ряд повёрнутой таблицы — ячейки** (`pdftext._rot_columns`, `_rot_cells`,
`PDF_ROT_COLS=0` — выключить). Симптом: «Повышенный риск Нейтральный Коррекция
дозы не требуется» одной строкой (стр. 9, таблица боком при прямой колонке).
Правило: прямая повёрнутая строка режется в куске, начало которого вдоль пути
совпадает (±1 пт) с началами кусков ещё как минимум в двух строках того же угла,
у предыдущего куска начало тоже на столбце, зазор от 0.5 кегля и в строке не
меньше трёх кусков на столбцах. Маркер «•» с текстом (зазор меньше полкегля),
одиночная подпись оси и повёрнутый список не режутся. Продолжение ячейки
следующей повёрнутой строкой (начало — на начале куска первой строки ячейки,
в том числе по тексту после «•», не дальше 2.5 кегля поперёк пути) идёт в её
же абзац (`_rot_cell_host`): «• No dose adjustment required».

**П3. Узкая ячейка растёт в свободную сторону** (`layout_pdf._fit_slots` →
`_span`, `_span_x`, `LAYOUT_LABEL_SPAN=0`). Симптом: «Эффективность»,
«Стоимость» в шапке таблицы — пол кегля (стр. 6). Причина: однострочная
ячейка считалась выровненной влево и росла только вправо, а справа сосед;
слева 18 пт бумаги. Правило: однострочной подписи, которой тесно, — свободная
бумага с обеих сторон (`room0`..`room1`); печать ставит строку как можно
ближе к центру её места в пределах этой бумаги. Влезает и так — печать прежняя.

**П4. Надпись под краем кольца** (`text_paint.measure`, `TEXTURE_BIG_SHARE`,

английским (стр. 12): буквы найдены, но фон признан «пёстрым» — край
розового кольца у вырезки. Правило: из замера пестроты вынимаются крупные
(≥2.5 высоты буквы) области краски вне букв, ВЫХОДЯЩИЕ за рамку надписи

предмет внутри рамки, пёстрый предмет фотографии и крупинки шума остаются
в замере — пёстрый фон по-прежнему отказ.

распознаватель не отметил, — и квартиль тесных подписей ужимал заголовок.
Правило: набор капсом (от четырёх букв) — отдельный класс.

## Р. Выгрузка (6) проекта 14 после пересборки и перевода: что осталось и почему (12.10.2026)

Стражи — `tests/test_pdf_holes.py` (разделы Р1–Р6), сравнение разбора целых
книг прежним и новым кодом (проект 14 — 8 абзацев, все в нужную сторону;
книги 8 и 19 — без изменений).

**Р1. Светлые буквы на плашке уже окна размытия** (`text_paint.measure`,
`_plate_of`). Симптом: «MEDITERRANEAN DIET» на синей дуге схемы оставался
английским (стр. 10). Причина: фон надписи — размытая вырезка (окно 0.6
строки); лента дуги уже окна, размытый фон — смесь ленты и белой бумаги,
и «краской» выходила сама лента, а буквы — её дырками: одно пятно больше
буквы, «похожесть на буквы» 0.02, отказ. Правило: если первый замер букв
не нашёл, а в вырезке есть РОВНАЯ (разброс цвета ≤ `PLATE_FLAT`) область
больше буквы и не меньше `PLATE_MIN_SHARE` вырезки, фоном считается она:
буквы — точки внутри неё, отличные от её цвета, стирание — её цветом.
Только однострочные надписи, только когда прежний замер отказал (найденное
прежним правилом не меняется), и только при контрасте букв с плашкой от
`PLATE_CONTRAST` (90 из 255) — крапины на ровном участке фотографии (небо,
кожа) буквами не становятся.

**Р2. Разрыв строки слоя — препятствие и при ПЕЧАТИ** (`layout_pdf._gap_pieces`,
`_slot_width`, раздвижка по краске). Симптом: «Благоприятное влияние на
гемоглобин A» с картинки и «• 1с, снижение массы тела…» слоя печатались одна
поверх другой (стр. 10). Причина: П1 научил разбор надписей видеть разрыв,
но печать строки слоя держала место сплошным от «•» до конца, раздвигала его
по краске (а в разрыве краска — надпись картинки) и давала ему расти в
«свободную бумагу» разрыва. Правило: место строки с разрывами (поле 10)
режется на куски между разрывами; знаки оригинала делятся по ширине, начало
последнего куска и точный конец — у последнего; кусок не раздвигается по
краске и не растёт в сторону своего разрыва. Перевод заполняет куски по
порядку («•» — в первом, текст — после разрыва). Крошечный кусок (уже
1.5 кегля), в который не влезает первое слово, остаётся пустым, а не
заставляет ужимать весь абзац. Зажим по разрыву стоит ДО замера цвета
бумаги — иначе цвет мерился бы в разрыве, на надписи картинки.

**Р3. Край светлой плашки — конец свободной бумаги** (`layout_pdf._room_hit`,
`FREE_STEP_DELTA`, `LAYOUT_FREE_STEP=0` — выключить). Симптом: синий
заголовок «Доза и время/расписание…» уходил за плашку на поле листа
(стр. 12). Причина: запас бумаги кончался на краске или на фоне светлее
бумаги на 12 из 255, а плашка 245 на листе 255 отличается на 10. Правило:
РЕЗКИЙ скачок середины тона столбца на `FREE_STEP_DELTA` (6) в пределах
двух столбцов, после которого новый тон держится `FREE_STEP_RUN` столбцов,
— конец места. Плавный градиент фона инфографики (доли единицы на столбец)
и шум скана (середина между минимумом и максимумом столбца стоит на месте)
краем не считаются — первая версия правила по уровню тона срабатывала на
них, и подписи стр. 4 теряли запас. Ошибка в эту сторону лишь запрещает
рост (подпись ужимается, как до запаса бумаги).

**Р4. Блок, лежащий в рисунке, сверяется ПОСТРОЧНО** (`main._mark_figure_blocks`,
`_figure_rows`, `LAYER_RULE` 4). Симптом: «Everyday settings» рукописным
шрифтом (стр. 12) оставалось английским. Причина: детектор собрал в один
блок 20 строк — рамку «WHAT?» внутри вырезанного рисунка и заголовок
«WHERE?: Everyday settings» под ним; блок на ≥80% площади в рисунке и
отсеивался ЦЕЛИКОМ («читает разбор вырезки»), а строки за краем рисунка не
читал никто. Правило — тот же закон, что у слоя (правило 2): строки блока,
лежащие вне рисунка, уходят своими блоками и дальше сверяются со слоем.
Записи правила 3 пересверяются сами (локальный поиск строк бесплатно; новые
строки читаются платно — единицы на книгу). Проверка на дубли блок,
отсеянный как рисунок, живым не считает.

**Р5. Надпись, СОДЕРЖАЩАЯ кусок слоя, — не повтор слоя**
(`main._holds_layer_pieces`; рамка надписи — от начала куска слоя). Симптом:
надпись «WHERE?: Everyday settings» отсеивалась как «повторяет слой»: одно
слово из трёх стоит в слое под ней, а порог повтора — 0.3. Правило: если
каждый абзац слоя, задевающий рамку надписи, лежит в ней (≥80% площади),
его текст — кусок её текста, и сверх них в надписи есть ≥30% своих знаков
(и кусок проходит те же условия, что у стирания: не длиннее
`LAYER_PIECE_WORDS` слов и короче надписи — иначе исключение без стирания
дало бы двойную печать),
это строка «начало слоем, продолжение кривыми»: печатается надпись целиком,
кусок слоя под ней стирается (правило О1). Надпись, начинающаяся куском
слоя, начинается там же, где он: рамка строки детектора захватывает значок
слева, и стирание размазывало его (только у однострочной надписи: у
многострочной кусок слоя стоит в одной строке, а остальные могут начинаться
левее).

**Р6. Повёрнутая строка: путь назад и широкий пропуск — разные надписи**
(`pdftext._rot_cells`, `_rot_piece_end`, `_rot_centered_host`, `PDF_ROT_GAP`,
`RULES_VERSION` 14). Симптом: строка шапки повёрнутой таблицы «…введения
Стоимость Клинические соображения Основные неблагоприятные…» печаталась
одной строкой за край таблицы (стр. 9). Причина: pypdf склеил в одну
повёрнутую строку ячейки шапки из двух мест таблицы: путь идёт вперёд
(administration → Cost → Clinical considerations) и прыгает НАЗАД (MACE,
Heart failure); правило П2 резало только по столбцам данных, а начала ячеек
шапки на них не попадают. Правило: прямая повёрнутая строка режется там, где
путь идёт назад больше чем на полкегля (кроме письма справа налево — там
путь назад законен), и там, где пропуск от ЗАПИСАННОГО
конца куска до следующего — от `ROT_GAP_SPLIT` (3) кеглей (по оценке конца —
нет: у узкого и широкого шрифта она врёт на кегли). Ячейка, продолжающая
надпись строки выше (начата строчной, соседняя строка, отрезки вдоль пути
перекрываются наполовину, а начала строк РАЗНЫЕ — выключка по центру),
идёт в её абзац («Route of administration»); значение, стоящее на начале
столбца данных («(95% CI)» под «0.8»), продолжением не считается. Повёрнутые колонтитулы альбомных страниц с двух концов
листа больше не склеиваются в одну строку.

## С. Текст на фото и сканах-картинках: лендинг /start/ (13.10.2026)

Стражи — `tests/test_image_text.py` (разделы «непрочитанная строка столбца»,
«кусок строки отдельным блоком внутри абзаца», «перенос, оставленный чтением»).
Файлы — плитки «Что переводим» на click.simpletranslate.me/start/
(`tools/landing_tiles.py`): машинописная справка 1940 г., разворот
«Пёстрых рассказов» 1886 г., шапка статьи npj.

**С1. Строку с нулевой уверенностью распознавалки судит геометрия столбца**
(`image_text._column_rescue`). Симптом: на переведённой справке три строки
из десяти остались русскими, а их текст пропал из перевода. Причина:
латинско-китайская распознавалка движка поставила выцветшей машинописи 0.0
(пустой текст), движок отбрасывал такие строки сам (`text_score`), а правило
`_in_column` брало только слабые от 0.3 и только между двумя уверенными.
Правило: движку передаётся порог 0; строка ниже `IMG_MIN_CONF` берётся, если
у неё не меньше двух «соседей по столбцу» (высота ±30 %, тот же левый ИЛИ
правый край в пределах высоты строки), она не короче `IMG_COL_WIDTH` (0.6)
их медианной ширины и стоит вплотную (до 0.8 высоты) к одному из них сверху
или снизу; спасённая строка сама становится соседом следующей. Пятно у края
и короткий обрывок под столбцом не проходят.

**С2. Кусок строки внутри многострочного блока — не блок** (`_drop_inner`).
Симптом: поверх переведённого абзаца стояло второе слово — «Один», «奥丁»
(бог Óдин), «واحدٌ». Причина: слово «одинъ» за буквицей детектор отдал своей
рамкой пониже строки, она не склеилась со строкой и стала блоком из одной
строки; модель прочла его отдельно, а кроп абзаца прочёл его ещё раз.
Правило: блок из одной строки, лежащий в многострочном блоке на
`IMG_INNER_COVER` (0.7) своей площади, выбрасывается — если своего текста
у него нет или он уже есть в тексте абзаца (чтение в браузере не теряет
подпись).

**С3. Перенос, оставленный чтением, снимается до сегмента**
(`image_text.dehyphen`, в `main._openai_read_image`). Симптом: «civil ser-
vant», «look- ed» в английском переводе Чехова. Причина: модель склеивает
строки блока пробелом и оставляет «экзеку- торъ», хотя промпт просит
склеить слово; перевод повторяет дефис. Правило: «буква + дефис (в т. ч.
неразрывный и мягкий) + пробел или разрыв строки + строчная буква»
склеивается, остальные разрывы строк внутри блока — пробелы (`read_clean`:
модель отдаёт строки через перевод строки, и разрывы оригинала становились
жёсткими разрывами перевода, а китайский повторял дефис посреди фразы);
перед союзом
(«двух- и трёхкомнатные», «pre- and post-test»), перед заглавной и между
числами — нет.

**С4. Выключка абзаца — по доле строк, держащих край, а не по разбросу**
(`image_text._align_para`, рисование — `block_align` по `lineBoxes`).
Симптом: перевод абзаца Чехова встал рваным левым краем («вправо»),
машинописи — «по центру». Причина: разброс левого края раздували отступ
первой строки за буквицей и абзацные отступы. Правило (от трёх строк):
первая строка не судит левый край, последняя — правый; край держится,
если строка в половине высоты строки от медианы; держатся оба — «влево»
(выключку по ширине рисуем от левого края); победитель ниже 70 % строк
или ничья — прежний замер разбросом. Выключка для рисования считается
заново по сохранённым рамкам строк — прочитанные раньше картинки получают
её без нового платного чтения. «Влево» — это начало строки: перевод справа налево
(арабский, иврит, фарси) рисуется от правого края (`_start_align`). Сверка: 68 блоков с рамками строк в картах
и 32 блока 40 картинок учебника — изменились только блоки лендинга и две
колонки надписей аппарата УЗИ с отступом первой строки (вправо → влево).

Что осталось и названо: заголовок статьи и строка авторов собираются в один
блок (кегль различается меньше порога `group_blocks` 0.6–1.7), жирный
подзаголовок «INTRODUCTION» прилипает к первой строке абзаца того же кегля.
Сужать порог кегля без замера на боевых картинках нельзя — у строки без
выносных элементов рамка законно ниже соседних.

## Т. Сверка выгрузки (7) проекта 14 с оригиналом: виды дефектов → правила (13.10.2026)

Первая сверка по порядку `docs/rules/export-review.md`. Выгрузка (7) была
сделана за 15 с до автопересборки по правилам Р, поэтому Р4–Р6 на ней
не проявились; после перевода 20 новых строк они подтверждены на свежей
выгрузке (стр. 9 — шапка повёрнутой таблицы по ячейкам, стр. 12 — «ГДЕ?:
Повседневные условия»). Остальное — виды дефектов, правил на которые не было:
A — слипшиеся куски, B — свой кегль у каждого куска, C — надписи на
картинках и дугах, D — перевод по кускам, E — разнобой одного и того же,
F — знаки и смысл. Стражи — `tests/test_pdf_rules_c.py` (Т1–Т9, Т18) и
тесты правил ниже по разделам. Эталоны регрессии — проекты 8 (книга
RU→UZ-CYRL, скан), 19 и 20 (статья EN→RU/UZ), 14 (инфографика EN→RU).

**Т1. Узкая ячейка спускается в свою строку таблицы** (`layout_pdf._free_below`,
`_row_bottom`, `FREE_BELOW_CELL_EM` 16, `FREE_BELOW_CELL_LINES` 12). Симптом:
«SGLT2 inhibitors» → «Ингибиторы натрий-глюкозного котранспортера 2 типа»
втрое мельче соседних ячеек (стр. 6), подписи схем вдвое мельче оригинала,
рамки полупустые (вид B). Причина: ячейка получала столько строк, сколько
было в оригинале; «свободная бумага ниже» мерилась на три строки, и пустота
под ячейкой высокой строки таблицы принималась за поле страницы. Правило:
колонка не шире 16 кеглей ищет чистую бумагу до первой краски ниже
(до 12 строк), а ячейка строки таблицы — до низа своей строки, который
известен по соседним ячейкам, начатым на той же высоте (самая длинная
соседняя ячейка цепочкой строк). Пустота до края досягаемости без соседей
по-прежнему поле. Колонка книги — по-старому.

**Т2. Слово режется переносом не больше одного раза; одно слово — не
переносится** (`_lay_flow`, `_fit_flow`). Симптом: «Сердечная недо-/ста-/
точ-/ность» в узкой шапке, «Ней-/тральное» в ячейке. Правило: хвост слова,
уже разрезанного переносом, второй раз не режется (не влез — кегль мельче);
абзац из одного слова не переносится вовсе.

**Т3. Рамка не сцепляет ячейки соседних строк таблицы** (`_frame_cut`
в `_flow_groups`). Симптом: шапка «Heart failure», получив место ячейки под
ней, спускалась в неё. Причина: текстовая рамка сцепляла абзацы одной
колонки через линейку шапки. Правило: не сцеплять через нарисованное
(`_drawn_between`) и когда у последней строки верхнего и первой строки
нижнего в ряду есть соседи (`_row_mates`) — это ячейки разных строк
таблицы. Пункты одной ячейки по-прежнему сцеплены.

**Т4. Граница колонки — середина зазора** (`_free_room`, `ROOM_TAKE` 0.5,
`ROOM_GUTTER` 1 кегль, `ROOM_NEAR_EM` 12). Симптом: «Нейтральный эффект
Пероральный» — две ячейки читаются одной фразой (стр. 6). Причина: левая
ячейка росла вправо до соседа, правая — влево до левой. Правило: к близкому
соседу (ближе 12 кеглей) строка растёт не дальше середины зазора минус кегль;
далёкий сосед — прежний запас.

**Т5. Линейка в полосе строки — не краска соседа** (`_trim_rule_rows`,
`RULE_ROW_SHARE` 0.85). Симптом: «Стоимость», «Сердечная недостаточность»
в шапке таблицы ужимались до 0.55. Причина: шапка стоит на линейке, линейка
попадала в полосу замера запаса вбок, и запас был нулём. Правило: ряды
пикселей у верхнего и нижнего края полосы, тёмные на 85% ширины, — линейка;
полоса обрезается по ней. Середина полосы (зачёркнутое) не трогается.

**Т6. Строки таблицы — от начал ячеек первой колонки** (`pdftext._table_streams`,
`TABLE_CONT_LEAD` 2.5). Симптом: «Dosing/use» и «considerations», «Route of»
и «administration» — разные абзацы, переведены кусками («Дозирование-применение
соображения», «Путь введение», стр. 7–8, вид D); «Benefit for kidney end» |
«points in CVOTs». Причины: узкий заголовок «Table 1—Continued» над шапкой
попадал в блок таблицы и «съедал» первую границу; вторая строка ячейки
первой колонки («Dual GLP-1/GIP» | «agonists») ставила границу строки через
все колонки. Правило: границы — только от строк первой колонки не выше первой
строки таблицы; строка, начатая строчной в пределах 2.5 кегля от предыдущей
строки колонки без конца фразы, — продолжение ячейки. Замер: проект 14 —
22 обрывка → 11 целых ячеек; книги 8, 19 — без изменений.

**Т7. Знаки сравнения, «&» и знаки сноски — не мусор** (`pdftext._clean_line`,
`_is_noise_line`, `_CMP_KEEP`, `_NOTE_KEEP`). Симптом: «and <TEE» → «и ОРЭ»
(условие перевернулось, стр. 10), «Merck Sharp & Dohme» → «Merck Sharp
Dohme», «therapy§», «*Evidence…» без знаков (связь с легендой рисунка
потеряна). Причина: чистка мусора распознавания снимала эти знаки с края
слова. Правило: «<», «>», «±», «~» перед словом или числом (не обёрнутые
парой, как «<308>») остаются; «&» между словами — союз; «*» и «§» на краю
слова остаются, кроме «*» посреди фразы перед строчной (в скане это
неверно прочитанная запятая: книга 8, «живота* выпадение»); строка со
знаком сравнения при числе («HbA1c <7%») мусором не считается.

**Т8. «MLTCs» — капс** (`_caps_label`). Симптом: «PEOPLE WITH T2D OFTEN LIVE
WITH OR | DEVELOP MLTCs» — два сегмента, перевод «ЖИВУТ С ИЛИ У НИХ
РАЗВИВАЮТСЯ МХЗ» (стр. 4, вид D). Правило: строчная «s» множественного
числа после прописной латинской («MLTCs», «RCTs») не мешает строке быть
капсом.

**Т9. Над- и подстрочные знаки — знаками Юникода** (`pdfpages_worker._script_marks`,
`_is_script`; `checks._extract_numbers`). Симптом: «MACE a» → «…событияа»
(кириллическая «а», приклеенная к слову), «considerationsb», «1,73 м2»,
«B12» (вид F). Причина: pypdf склеивает мелкий приподнятый кусок со словом
без пометки. Правило: кусок до трёх знаков, кеглем не больше 0.8 соседнего
слова, со сдвигом базовой линии 0.1–0.9 кегля, вплотную к слову,
записывается знаками Юникода (⁰…⁹, ⁺⁻⁼⁽⁾, ᵃ…ᵉ; ₀…₉, ₊₋₌₍₎) один к одному —
длина строки и смещения геометрии не меняются. Буква — только одиночная
надстрочная (сноска). Не всё отображается («1c» в HbA1c: у «c» нет
подстрочной формы) — как было. Проверка чисел сводит такие цифры к обычным.

**Т18. Узкий оригинал — узким файлом** (`FAMILY_CANDIDATES["sansc"/"sansx"]`,
`_cond_family`, `COND_FONT_AT` 0.78, `COND_FONT_X` 0.7, `COND_FONT_RATIO_MAX` 0.95;
файлы Noto Sans Condensed и ExtraCondensed,
OFL, в `frontend/vendor/fonts/sub`). Симптом: подписи инфографики тонкие,
сплющенные и мельче оригинала («ПОЛОЖЕНИЕ СТОЯ», стр. 4, 12). Причина: узкий
оригинал (DIN Condensed) печатался обычным Noto Sans, сжатым не дальше
`HSCALE_MIN`. Правило: рубленый оригинал уже 0.78 нашего обычного (замер
ширины `_width_ratio` или флаг «c») печатается узким файлом (уже 0.7 —
самым узким), а сжатие считается от ширины этого файла. Порог выбран
замером: при 0.9 узким стал и основной текст статьи (гуманистическая
гарнитура журнала уже Noto Sans на ~18%, но не узкая) — буквы выглядели
сжатыми, а разброс кегля в основном тексте вырос с 2% до 22% знаков.
Узкого файла нет или он не знает букв перевода (под его именем стоит
запасной DejaVu — шире 0.95 обычного) — прежний обычный с сжатием.

**Т10. Маркер в конце строки — своя ячейка** (`pdfpages_worker._h_groups`,
`_chunk_end_exact`). Симптом: «Cardio-kidney protection Physical function»
одним абзацем, а галочка второго пункта стояла в конце первой строки
(стр. 1, 4, 31). Правило: знак без букв и цифр в конце строки отделяется,
когда ТОЧНЫЙ конец левой части известен и зазор не меньше `SPLIT_GAP`
(или знак стоит на начале колонки таблицы при зазоре больше `COL_GAP`).
Цифры (оглавление) и знак вплотную клеятся, как клеились. По оценке конца
не режем: на узком шрифте книги 8 оценка занижена, и появлялся абзац «—».

**Т11. Значок-контур перед пунктом — маркер списка** (`pdfpages_worker` копит
рамку контура m/l/c/v/y/re до оператора закраски и отдаёт `geom["icons"]`
только у начала строк; `pdftext._mark_icon_bullets`). Симптом: пункты,
нарисованные значком-кривой, а не символом, сливались в один абзац.
Правило: значок не больше 1.5 кегля (`ICON_REACH`), не у конца чужой
строки. Строчная буква пункта сама по себе не запрет (русские и немецкие
пункты бывают строчными) — запрет, только если строка выше вплотную и не
кончила фразу. **Фон — не значки** (`pdftext.icon_backdrop`, общий для
разбора и печати): прямоугольники одного x и ширины, стоящие столбиком
вплотную, — полосы заливки под строками. Серая аннотация статьи 19
нарисована полосой на строку, и без фильтра каждая строка аннотации
становилась «пунктом», а строка цитаты под ней мельчала.

**Т12. Пункт со значком на выгрузке — у своего значка** (`_Sampler.icons`,
`_icon_marks`, отметка места `_mark`; `LAYOUT_MARKS=0` выключает).
`_story_link` и `_flow_groups` не связывают помеченный пункт с абзацем
выше; однострочный пункт держит свой левый край (`STORY_INDENT_KEEP`),
продолжение под значок не уходит. Работает и по старым картам — значки
берутся с отрисованной страницы.

**Т13. Хвост, задевший соседа, — последний ход** (`tail_hs` в `_fit_slots`,
`_fit_flow`, `_refit`, проход в `_resolve_collisions`). Симптом:
«недостаточность» над «Печень» налезала на 0.9 пт при пороге счёта 1.0 —
наложение было, а счёт его не видел. Правило: абзац, чей хвост задевает
чужую рамку, ещё раз укладывается с сужением начертания до `TAIL_HS_FLOOR`
(0.55; `LAYOUT_TAIL_HS_FLOOR=0` выключает) при кегле не ниже `FLOOR_HARD`.

**Т14. Надписи рисунка группируются по разделителям** (`image_text._bg_of`,
`divider_between`, `regroup_boxes`; `main._split_uncovered(…, arr)`).
Симптом: на стр. 19 строки двух плашек склеивались в один блок. Правило:
между строками, разделёнными линией или сменой фона, блок не идёт;
непокрытые строки пересобираются теми же условиями (колонка, кегль,
выравнивание, зазор, фон, разделитель). Поле фона — не меньше 3 px.

**Т15. Колонтитул — по ВЫСОТЕ строки, включая повёрнутый** (`pdftext._bands`,
`HEAD_ROT_EDGE`, кластер `rc`, `_page_note`). Симптом: «N Consensus Report»,
«Davies and Associates N», «diabetesjournals.org/care» оставались в теле
(разные номера — дедупликация не видит), а на повёрнутых страницах (4, 6,
7, 8, 19, 31) не сверялись вовсе. Правило: полоса верх/низ берётся из
высоты строки (порядок в потоке — запасной ход), окно из трёх строк
считает РАЗНЫЕ строки; строка у края листа повёрнутой страницы сверяется
со своим кластером и уходит в тот же переводимый абзац колонтитула
(`rotatedHeads`). Записка «Continued on p. N» (короткая, с заглавной,
кончается «сокращение + число») — граница абзаца на стыке страниц, вставка
через неё не откладывается.
**Т15b.** `_stories` не берёт абзац, у места которого есть разрыв
(`_gapL`/`_gapR`): «Низкоэнергетическая диета (НЭД)» уезжала из ячейки.

**Т16. Двойники печатаются одним переводом** (`main._twin_unify`, `_tpl_of`,
`_print_by_id`; stats `twinsUnified`, `twinGroups`). Симптом: одна и та же
подпись на стр. 1 и 4 переведена по-разному — ревизия и ремонт правили
копии отдельно («…С ДРУГИМИ ЗАБОЛЕВАНИЯМИ ИЛИ» против бессмыслицы «…С ИЛИ
У НИХ РАЗВИВАЮТСЯ»). Правило: двойники — тот же нормализованный исходник
И те же исходники соседей; эталон — заверенный > набранный человеком >
большинство машинных > меньше чужих вариантов через «/» и скобки > меньший
номер. Шаблон «короткая строка с одним числом в начале или конце»
(колонтитул «Davies and Associates 9») — эталон по маске числа, число —
своё. Тексты людей не трогаются, данные проекта не меняются — только
печать (PDF и .docx 1в1, «в исходном виде», xlsx/txt, простой .docx).
Шаблон **не переставляет число** (`_tpl_side`): «15-расм» и «Расм 15»
к одной форме не приводятся — место числа задаёт язык перевода (книга 8,
стр. 247: верное узбекское «15-расм» стало бы «Расм 15»). Число в начале
и одно слово после («5 Cases») — счёт предметов, а не название. Сбой
сверки — `twinsError` в отчёте, а не «двойников нет».

**Т17. Легенда сокращений «ABBR, расшифровка;»** (`main._abbr_map`). Симптом:

расшифровывает. Правило: легенды целого сегмента и подписи рисунка дают
пары, только когда записей в оригинале и переводе поровну, а расшифровка
короткая (≤ `LEGEND_WORDS` слов, ≤ 2 запятых). Три разных варианта одного
сокращения в документе — ответа нет, сокращение не подменяется.
Сдвиг записей (одна пропала в переводе, другая совпала по виду) выдают
цифры и длина: у пары те же цифры («T2D → СД2») и длина 0.5–2.5
оригинала; одна пара не сошлась — легенда сегмента не голосует.

**Т21.** Строки с путём и без пути не склеиваются в один повёрнутый абзац

**Т27–Т28. Хвост и ширина закраски — по краске СВОЕГО цвета** (`_own_ink`,
`_own_ink_cols`). Симптом: серая заплатка часов «24 часа» выходила за круг

боковая кромка в Т30 не сужает поле, а линия сверху и снизу меряется по
полосе шире строки на два кегля: рамка плашки выходит за текст, рамка
ссылки — нет.

`ERASE_FILL_HULL`): белые середины букв оставались пятнами. Достраивается

**Т30. Место перевода надписи — комната плашки** (`text_paint._area_rooms`,

**Т31. Буква прямой строки — по высоте области** (`LETTER_BY_HEIGHT`).
Симптом: «GOALS OF CARE» находилась или нет в зависимости от одного
пикселя кропа (слипшиеся жирные буквы шире строки отбрасывались).
**Т32. Краска минус слой — новые надписи** (`main._layer_rects`,
`_residual_groups`, `_layer_residual_add`, `LAYER_RULE` 5; флаги
`LAYER_ARC_GLYPHS`, `LAYER_EXACT_TAIL`, `LAYER_RESIDUAL`). Симптом: «Office –»
кривыми в строке слоя (стр. 12), «To avoid» и «3–6 months)» (стр. 19),
«Prevent complications» внутри круга (стр. 1) — не переводились: рамка
дуговой строки слоя накрывала середину круга, а хвост за точным концом
строки считался слоем. Правило: рамки дуги — по глифам; непокрытое за
точным концом — своя надпись; краска вне слоя и вне блоков — новые блоки,
только если похожа на строку текста (буквоподобных частей ≥ 3, ширина ≥ 2
высот, контраст и фон как у соседней строки слоя — штамп CamScanner
отсекается). Не больше `RESIDUAL_MAX_PAGE` (6) на страницу — больше значит
«шумная схема», и не заводится ни один. Страница, где концы строк
слоя в большинстве ОЦЕНЕНЫ (скан с невидимым слоем распознавания),
остатка не ищет (`residualSkipped: "est"`): хвост книжной строки там
прочитали бы платно и напечатали дважды. Шумная вырезка (больше
`RESIDUAL_COMPS_MAX` частей) — не строки. Ответ «нужна ли пересверка»
помнится и положительным (`_RELAYER_SEEN`) — иначе каждое открытие
перечитывало бы карту. Проход бесплатный (пиксели);
платно читается только найденное. Замер: проект 14 — 6 блоков, книги 19
и 20 — 0.

**Т33. Точный конец строки — через надстрочную ссылку** (`pdfpages_worker._exact_ends`,
`EXACT_CHAIN_GAP` 0.6, `EXACT_CHAIN_RISE` 0.6). Симптом: в статьях 19 и 20
сквозь перевод проступал английский хвост строк («These effects have been»,
«In fact, the cognitive performance», «Outside of a laboratory setting…»).
Причина: ссылка «⁷,⁸» посреди строки — свои операторы, поднятые на 0.43
кегля, а текст за ней — оператор, начатый правее начала последнего куска
строки; такие считались «чужим текстом на той же линии», и точный конец
вставал на ссылке. Закраска шла до него, а «от точного конца» раздвижка по
краске не идёт. Правило: оператор того же шрифта, начатый вплотную к уже
принятому (зазор не больше 0.6 кегля), с подъёмом до 0.6 кегля, — тоже эта
строка; текст той же линии через большой зазор не цепляется. Замер: статьи
19 и 20 — по 22 строки из 181 (все — строки со ссылкой посреди), книга 8 —
5 из 2911 (концы ушли до настоящего конца текста строки). Найдено сквозной
выгрузкой эталонов при сверке (7) — было и в прежних выгрузках.

**Т34. Линии таблицы, нарисованные обводкой, — границы ячеек и рядов**
(`pdfpages_worker._rules_of`, `_split_at_rules`, `_h_groups`, `vrules`/`hrules`
в геометрии страницы; `pdftext._rule_parts` в `_geo_follows`; `RULES_VERSION` 16).
Симптом (статья «Бюллетень сибирской медицины», проект 105, стр. 4 и 5): шапка
таблицы «SNP (ген) | Гено-/тип | БА, n, % | Контроль, n, %» разобралась в абзацы
«SNP (ген) Гено-» и «тип БА, n, % Контроль,». Перевод одного абзаца раскладывался
по рамкам трёх ячеек: «type» в одной, мелкое «asthma (BA), n, % Control» в другой,
а в ячейке «Контроль» оставался непокрытый оригинал. Причина: строку режут только
зазор больше `SPLIT_GAP` кеглей и «начала колонок» данных; у ячеек шапки,
выключенных по центру, нет ни того, ни другого. Линии таблицы не учитывались вовсе:
`rects` собирает только `re`, а здесь каждая линия — отрезок `m`/`l` со своим `cm`
и `S`. И pypdf отдаёт всю строку шапки ОДНИМ куском, хотя внутри она нарисована
отдельными операторами в разных ячейках. Правило: обведённый отрезок (и тонкая
полоска) — линия листа. Вертикальная линия между двумя операторами показа текста —
граница ячейки: кусок pypdf режется по операторам (их знаки без пробелов обязаны
сойтись с куском, иначе не режем). В `_h_groups` такая линия делит строку при любой
базовой линии и любой длине куска, а часть за линией — ячейка, даже без букв
(«0,001»). Горизонтальная линия между двумя строками, накрывающая обе по ширине, —
граница ряда: абзац через неё не идёт. Подчёркивание (ближе 0.3 кегля к базовой)
границей не считается. **Линия таблицы — только сетка** (`_grid_rules`):
вертикаль считается, если оба её конца упираются в горизонтали, горизонталь — если
касается такой вертикали или пересекает её, и таких вертикалей на странице хотя бы
две. Залитая полоска тоньше 0.25 пт — ступенька градиента, а не линейка. Без этих
двух условий инфографика проекта 14 резала подписи по словам («Consider | specific |
factors»): стрелки, рамки плашек и градиент из 573 полосок по 0.1 пт становились
«линиями таблицы». Замер на эталонах: книга 8 и статьи 19/20 — разбор буква в букву
прежний; проект 14 — тот же текст, две подписи плашки поменялись местами (по месту
на листе); статья 105 — две таблицы и два абзаца, разрезанных ложной колонкой.
Страж — `tests/test_pdf_table_rules.py`.

**Т34б. Строки расчерченной таблицы — по ячейкам** (`pdftext._cell_order`,
`_cell_of`). Симптом: двухстрочная ячейка («Гено-» / «тип», «Контроль,» / «n, %»)
переводилась кусками. Причина: pypdf выдаёт шапку по высоте — сначала верхние строки
всех ячеек, потом нижние, — и строки одной ячейки в потоке стоят не подряд.
Правило: в пачке подряд идущих строк, стоящих между двумя вертикалями, строки одной
ячейки (те же вертикали слева и справа, те же горизонтали сверху и снизу) идут
вместе, сверху вниз. Ячейки — по месту: ряд сверху вниз, в ряду слева направо.
Строки вне ячеек пачку обрывают и не двигаются.

**Т35. Начала колонок — только внутри расчерченной таблицы** (`pdfpages_worker._in_ruled`).
Симптом: заголовок таблицы «Ассоциация варианта rs10905277 гена *GATA3* с развитием /
бронхиальной астмы» разобрался в четыре абзаца. Перевод собрался из кусков в русском
порядке слов («…of the gene» + «GATA.» + мелкое «with the development of»). Причина:
широкий пробел выключенной по ширине строки перед курсивом в обычном тексте давал
«начало колонки» `_col_starts` на x ≈ 464. Совпавший с ним курсив заголовка резал
его, и тот же кусок резал абзацы текста посреди фразы («…гена | GATA3 связан…»).
Правило: на странице, где есть вертикальные линии, начало колонки режет только строку,
стоящую по высоте в пределах этих линий. Вне таблицы колонок нет, а внутри ячейки
разделяют сами линии (Т34). На странице без линий — как прежде: таблица без линейки
держится на `_col_starts`.

**Т36. Подпись серии с ключом легенды — свой блок** (`image_text.legend_key`,
`_finish_lines` → признак строки `key`, `group_blocks`, `split_plan`,
`main._split_keyed`; `IMG_GROUP_RULE` 4). Симптом: на столбчатой диаграмме (картинка)
подпись оси «AA» и строка легенды под ней «■ Легкая степень БА» стали одним блоком
«AA Легкая степень БА». Перевод «AA Mild bronchial asthma (BA)» лёг на место подписи
оси, а легенда осталась пустой — квадраты без текста. Причина: `group_blocks` склеивает
строки, выровненные по одному краю, и правый край «AA» случайно совпал с правым краем
строки легенды. Правило — по устройству графика, а не по словам: строка, у левого края
которой стоит ключ (сплошной квадрат со стороной 0.22–1.05 высоты строки, почти
квадратный, заполнение от 0.86, правее — буквы), — подпись серии. К блоку выше она
не приклеивается, продолжение снизу к ней — приклеивается. Цвет не важен: серия бывает
серой. Круглый маркер списка (заполнение π/4) ключом не считается. Уже разобранные
картинки перегруппировка режет перед строкой с ключом (`split_plan`): части без текста,
их дочитывает обычный шаг чтения (несколько коротких блоков). Сегмент прежнего блока
снимается, а блок с работой человека не режется (сегмент, `by`/`textBy` блока). Части
в ритмовую склейку больше не идут (`splitKey`). `flat` у части перемеряется заново.
Ключ обязан стоять по высоте внутри строки и вплотную к её тексту: столбик диаграммы
слева ключом не считается.

**Границы Т34–Т36 (сказано честно).** Трёхлинейные таблицы (только горизонтали,
частые в журналах) в сетку не попадают: правило для них молчит, и они держатся
на прежних `_col_starts`. Кусок, у которого знаки операторов не сошлись с текстом
(лигатуры «ﬁ», неразрывный пробел, многознаковые карты Type0), не режется — молча.
Густая штриховка дороже `GRID_PAIRS_MAX` пар линий считается рисунком. Пороги
(`RULE_THIN`, `RULE_FILL_MIN`, `GRID_TOL`, `KEY_*`) измерены на статье 105
и проекте 14 — на других документах их предстоит проверить. Цена подъёма версий:
`RULES_VERSION` 16 перечитывает каждый PDF-проект при открытии. Строки, которые
изменились, теряют машинный перевод (он уходит в `prevTarget`) и переводятся
заново; у файлов без расчерченных таблиц не меняется ничего. `IMG_GROUP_RULE` 4
перепроверяет блоки картинок из нескольких строк по пикселям — бесплатно.
Платно дочитываются только разрезанные части.

## У. Рукописный конспект в клетку (RU→EN, 16.10.2026)

Фото тетрадной страницы, текст от руки через клеточку, красная строка.
Выгрузка «как в оригинале»: 4 строки из 18 остались русскими, перевод
напечатан рубленым гротеском, соседние абзацы разного кегля.

- **У1. Абзац рассыпался на блоки по строкам.** Симптом: предложение
  переведено обрывками, строка-обрывок осталась оригиналом, хвост «нах.»
  переноса «доме-нах.» стал своим блоком «cells.». Причина: `group_blocks`
  склеивает строки с зазором не больше высоты строки, а рукопись идёт через
  строку. Правило: колонка с ровным ритмом (`IMG_RHYTHM_MIN_LINES` строк,
  разброс зазоров ≤ `IMG_RHYTHM_MAD`, длинные строки ≥ `IMG_RHYTHM_WIDE`
  высот) склеивается при зазоре ≤ медиана × `IMG_RHYTHM_SLACK`; пустая строка
  между абзацами больше и абзацы не сливает; колонка — вся цепочка, а не
  последний блок (короткий хвост не рвёт её). Форма с короткими полями и
  три строки правило не трогает. Код: `image_text._rhythm_merge`.
  Короткая строка заканчивает абзац: к хвосту, заголовку и подписи следующая
  строка не приклеивается. Тест: `tests/test_image_text.py`, «рукопись через
  строку». **Уже разобранные картинки перегруппировываются сами**: версия
  правил сборки — `image_text.IMG_GROUP_RULE`, запись картинки помнит свою
  (`groupRule`); открытие проекта ставит разбор картинок (`_auto_regroup_kick`,
  один раз на версию — `regroupAsked`), и тот склеивает сохранённые блоки
  (`_regroup_rec`) без детектора и без второго чтения: текст склеивается
  из прочитанного, сегменты обрывков снимаются, якоря уцелевших
  (`origin.block`) идут за новыми номерами. Есть работа человека среди
  обрывков — картинка не трогается (`groupHeld`). Склеенный абзац ждёт
  перевода. Тест: `tests/test_image_regroup.py`.
- **У2. Рукопись печаталась гротеском.** Причина: признака рукописи не было
  нигде, шрифт выбирался только по буквам. Правило: модель чтения отвечает
  `hand` на блок; страница рукописная, когда рукописью помечено ≥
  `IMG_HAND_SHARE` площади текстовых блоков (`main._hand_image`, решение
  на страницу, иначе соседние абзацы разными шрифтами); семейство `hand`
  в `layout_pdf.FAMILY_CANDIDATES` — Marck Script (OFL, латиница и
  кириллица), своё — `LAYOUT_FONT_HAND`. Узбекских ў қ ғ ҳ ʻ в нём нет —
  `font_path(chars=)` берёт запасной DejaVu. Прочитанное до правила признака
  не несёт и печатается как раньше (закон миграции); вердикты чтения
  не перекупаются. Тест: `tests/test_pdf_layout_export.py`, раздел 13.
- **У3. Разный кегль соседних абзацев.** Причина: кегль надписи меряется
  по краске каждого блока, а почерк пляшет. Правило: на странице не меньше
  `LAYOUT_PAINT_EVEN_MIN` блоков одного семейства с кеглем в пределах
  `LAYOUT_PAINT_EVEN_SPREAD` от медианы — один кегль (медиана); схема
  с разными кеглями подписей не трогается. Код: `layout_pdf._page_em_even`.
- **У4. Детектор не увидел строку рукописи** (проект 89, 16.10.2026: три
  строки из восемнадцати — «эукариотических клеток…», «Вместе с тем…»,
  «структуры… доме-» — не попали ни в один блок, перевод встал без них,
  а «бакте-/рии» модель прочла «ры»). Причина: детектор печатного текста
  пропускает рукописные строки, а читает модель только рамки. Правило:
  в ровной колонке шаг ≈ k шагов значит k−1 пропущенных мест
  (`image_text.gap_slots`, порог `IMG_GAP_STEP`); место — строка, только
  если в нём есть краска темнее фона на `IMG_GAP_INK_DELTA` (клетка и
  линейка тетради светлее), её доля ≥ `IMG_GAP_INK_SHARE` и она тянется
  ≥ `IMG_RHYTHM_WIDE` высот (`rhythm_gaps`). Пустая строка между абзацами
  краски не содержит и строкой не становится. Шаг ритма меряется от верха
  до верха строки, а не зазором: рамка рукописи пляшет от выносных букв.
  Короткий хвост без выносных букв ниже на треть — допуск высоты
  `IMG_RHYTHM_SIZE` 0.4. Новый разбор находит такие строки сразу
  (`detect_lines`), старые записи — перегруппировкой (`IMG_GROUP_RULE` 3,
  `main._regroup_gaps`); страницы PDF отрисовываются для этого, только
  если место пропуска вообще есть (`_regroup_wants`, геометрия без картинки).
  Абзац с найденной строкой читается целиком заново (одним вызовом).
  Тест: `tests/test_image_regroup.py`.
- **У5. Человек не мог исправить оригинал строки с картинки** — отказ
  «правится разбором картинок». Распознавание рукописи и скана ошибается,
  и вписать верное может только человек, глядя на кусок картинки в
  карточке. Правило: строка с картинки правится как любая
  (`/segments/{pid}/{sid}/source`, те же допуск, рост и страницы); текст
  уходит и в блок карты (`_image_block_text`: `text`, `textBy: human`).
  Перегруппировка склеивает абзац с его текстом, а группу, где его правка
  соседствует с непрочитанной строкой, НЕ склеивает (`groupHeld`): иначе
  чтение абзаца целиком переписало бы исправление. Пока идёт разбор
  картинок — 409. Тест: `tests/test_source_edit.py`, раздел 5.
- **Абзацный отступ, шаг строк и рукописный шрифт у выгрузки КАРТИНКОЙ** —
  раздел Ф ниже (У2 и У3 доехали только до PDF).

## Ф. Перевод в фото абзаца: строки, кегль, перо, бумага (проект 89, 16.10.2026)

Выгрузка конспекта картинкой (JPG) после раздела У: первый абзац —
рубленый гротеск, сжатый по ширине, второй — Noto Sans на непрозрачном
сером прямоугольнике 680×590 поверх клетки; кегли и шаг строк разные,
красной строки нет, на месте стёртых слов — серые пятна и разорванная
клетка. Разбор — три критика (дизайнер, редактор-переводчик, типограф
рукописи) и четыре трассировки кода. Правила общие: любой язык, любая
письменность, печать и рукопись, фото и скан. Код — `text_paint` (общий
для обоих путей), `image_text` (картинка), `layout_pdf` (PDF). Тест —
`tests/test_hand_paint.py`.

- **Ф1. Строки абзаца — по рамкам строк, а не по полосам маски.**
  Симптом: второй абзац ушёл на плашку. Причина: у слитного почерка петли
  сливают две строки в одну полосу маски, а обрывки выносных дают лишние —
  12 «строк» на 11; `fit_lines` принимал раскладку на 12 строк (`rows_min`
  перекрывал предел по высоте), вызывающий её отвергал строже — и блок,
  буквы которого уже были найдены и стёрты, уходил на плашку. Правило:
  у абзаца с `lineBoxes` (их число = `rows`) база строки — низ «тела»
  (ряды с краской ≥ половины пика), шаг — медиана расстояний между базами,
  ритм ровный при разбросе ≤ `PAINT_RHYTHM_MAD` и без выброса больше
  `PAINT_RHYTHM_MAX` шага (`text_paint.line_geometry`). Строки перевода
  ставятся на базы оригинала тем же шагом (база первой — по всем строкам
  наименьшими квадратами), абзац не центрируется в рамке. Начало строки —
  по КРАСКЕ тела в пределах блока, а не по рамке детектора (слово за
  буквицей детектор отдаёт отдельно, С2); отступ первой строки —
  разница с медианой начал остальных, если они выровнены
  (`PAINT_INDENT_ALIGN`), сдвиг ≥ `PAINT_INDENT_MIN` и ≤ `PAINT_INDENT_MAX`
  кеглей. Правый край — `PAINT_RIGHT_Q`-й процентиль концов строк (строка
  с переносом у края листа его не задаёт). Без рамок строк — прежний путь,
  но число строк для `fit_lines` не больше, чем вмещает место по той же
  мерке, что проверка. Выгрузка передаёт `lineBoxes` (картинка —
  `main._export_images`, PDF — `lines` у `_pdf_image_boxes`).
- **Ф2. Почерк не сжимается по ширине.** Симптом: высокие сплющенные буквы
  (h0 0.74), всё равно шире краски. Причина: у слитного почерка связная
  область — слово с петлями, кегль по её высоте в 1.6 раза больше; разницу
  прятало сжатие начертания. Правило (`text_paint.calibrate`): у рукописи
  кегль = измеренный × (ширина краски ÷ ширина исходного текста тем же
  шрифтом), не больше измеренного, сжатия нет; ширина исходника меряется
  шрифтом, знающим ЕГО буквы. У печати — как прежде.
- **Ф3. Длинный перевод — в свободные строки ниже, а не теснее.**
  `text_paint.fit_rhythm`: полный кегль в строках оригинала и свободных
  строках ниже (`image_text._free_rows`, до `IMG_EXTRA_ROWS`, не больше
  строк абзаца); потом мельче буквы при ТОМ ЖЕ шаге до `PAINT_FIT_FLOOR`;
  потом буквы и шаг вместе до `PAINT_FIT_HARD`; не влезло — печатается
  и называется (`over` → `img_overflow`, строка в тосте выгрузки).
  Свободная строка — не задевает чужую надпись (рамки ВСЕХ надписей
  картинки, `obstacles`; была пустая строка между абзацами — остаётся),
  не выходит за низ картинки и не ложится на краску размером с букву
  (`text_paint.has_letters`: бумага — максимум окрестности, клетка и
  линейка буквами не считаются). У PDF свободные строки не ищутся — там
  раскладка в строках оригинала.
- **Ф4. Один кегль, шаг и цвет у абзацев страницы.** Абзацы одного
  семейства с кеглем в пределах `PAINT_EVEN_SPREAD` — класс (от
  `PAINT_EVEN_MIN` = 2: у конспекта два абзаца — обычное дело; подписи
  схемы однострочные и в класс не входят): кегль класса — меньший из
  подогнанных, шаг — общий, если шаги близки (`PAINT_EVEN_STEP_SPREAD`),
  цвет чернил и сжатие — медиана класса. Абзац ниже пола или с выходом
  за место класс не держит. Картинка — `image_text._page_even`, PDF —
  `layout_pdf._harmonize_paint_rhythm` (и `_page_em_even` для рукописной
  страницы — от двух абзацев).
- **Ф5. Плашка на неровном фоне — восстановленный фон.** Плашка остаётся
  только там, где буквы по пикселям не выделились. На неровном фоне она —
  медиана с окном шире буквы по уменьшенной копии (буквы и тонкие линии
  сняты, перепад света сохранён), рамка — по строкам с полем
  `IMG_PLATE_PAD` строки, не по раздутой рамке блока (`image_text._plate_bg`).
- **Ф6. Бумага с узором стирается по модели.** Симптом: внутри стёртого
  пропадали 60 % горизонтальных линий клетки, на пересечениях — серые
  пятна. Причина: Telea — диффузия от края дыры. Правило
  (`text_paint._paper_periodic`): бумага = освещение (серое «закрытие» +
  размытие по известным точкам) × узор; период — пик автокорреляции по
  каждой оси (`PAINT_PERIOD_PEAK`); точка дыры — медиана узора в ближайших
  точках той же фазы × освещение. Модель принимается, только если на
  кольце известных точек вокруг дыры ошибается меньше ровного тона в
  `PAINT_PERIOD_GAIN` раз — ложный узор (шум, ткань) экзамен не сдаёт,
  стирание остаётся прежним. Точки без соседей той же фазы (край
  вырезки) добираются размытием, если их не больше `PERIOD_MISS`.
  Выключатель — `PAINT_PERIODIC_ERASE=0`. В отчёте блока — `erase: periodic`.
- **Ф6а. Период узора — не гармоника строк** (17.10.2026, слайд конспекта
  на /start/). Симптом: во втором абзаце клетки под стёртыми строками
  «замазаны» серыми разводами. Причина: у вырезки, продлённой до края листа
  (продолжение надписи за рамку), строки текста стоят на каждой второй
  линии клетки, и их следы складываются с клеткой — сильнейший пик
  автокорреляции по вертикали вышел 54 точки вместо 27. С двойным периодом
  модель не сдавала экзамен (половина линий «не в фазе»), а где сдавала —
  полоса строк не дотягивалась до известной бумаги той же фазы, и
  стирание падало на Telea. Правило (`text_paint._period_cands`): кандидаты
  периода — сильнейший пик и его делители P/2, P/3 (`PAINT_PERIOD_DIV_MAX`),
  если на делителе стоит свой пик над впадиной вокруг
  (`PAINT_PERIOD_DIV_PROM` нулевого сдвига; знак не важен — следы строк
  сдвигают весь профиль). Все пары кандидатов (x × y) идут на тот же
  экзамен кольцом; из сдавших берётся с наименьшей ошибкой, у которого
  точки дыры находят соседей той же фазы (не больше `PERIOD_MISS` без
  них). Решает экзамен, а не высота пика: ложный делитель экзамен
  не сдаёт. Тест — `tests/test_hand_paint.py`, раздел Ф6а.
- **Ф7. Толщина пера рукописи.** Рукописный шрифт тоньше ручки: недостающая
  толщина (штрих оригинала `_stem` против штриха шрифта `font_stem`)
  добирается обводкой цветом букв, не больше `PAINT_STROKE_MAX` кегля
  (больше — дефис слипается с буквами).
- **Ф8. Чтение рукописи — переписывать, не править.** Модель заменяла слова
  правдоподобными («наиболее просто» → «гораздо проще», «системы секреции»
  → «специальные секреции») и теряла последнюю точку абзаца; перевод
  повторял подмену смысла. Промпт чтения (`_image_read_system`) запрещает
  исправлять, дополнять и нормализовать и требует сохранять пунктуацию.
  Прочитанное раньше не перечитывается (кэш по sha).
- **Ф9. Неровный фон без узора стирается нейросетью LaMa** (Ш1 плана
  `docs/plans/ocr-paint-tools.md`, 18.10.2026). Симптом: на фото, градиенте,
  металле, бликах стёртое выходило серыми пятнами в форме прежних букв —
  Telea тянет тон от края дыры. Правило (`backend/paint_lama.py`, ветка
  `text_paint.erase` «не ровный и не узор»): LaMa (big-lama, Apache-2.0,
  ONNX Carve/LaMa-ONNX, вход 512×512, sha256 сверяет
  `tools/install_paint_models.sh`) закрывает дыру плитками 512 точек БЕЗ
  уменьшения, по порядку (закрытое прежней плиткой — известный фон
  следующей); в результат идут только точки дыры. **Только при перепаде
  тона фона** (`_bg_spread`: P95−P5 яркости после медианы шире штриха по
  кольцу вокруг дыры не меньше `PAINT_LAMA_SPREAD_MIN`, 60): на бумаге
  с текстом сеть «дорисовывает» окружение, то есть буквы, — замер на стенде:
  призрак адреса сайта на белой статье и светлые крапины на старой книге
  (разброс 0…11), на ровном листе таблички — равенство с Telea (40–45),
  на металлической рамке — чистый градиент вместо пятен по форме букв (98).
  Ровный фон — заливка
  (Х5), узор — Ф6: там LaMa не нужна и дороже. Цена названа: плитка на
  сервере 3–5 с в два потока (`PAINT_LAMA_THREADS`), поэтому потолки —
  `PAINT_LAMA_CALL_S` на вызов, `PAINT_LAMA_BUDGET_S` на перерисовку
  картинки и на выгрузку PDF целиком (`lama_budget`), `PAINT_LAMA_MAX_TILES`,
  `PAINT_LAMA_MAX_MPX`; не уложились, нет модели или модуля, сбой — Telea,
  отказа нет. Сессия одна на процесс даже при двойном импорте модуля.
  В отчёте блока — `erase: lama`. Выключатель — `PAINT_LAMA=0`. MI-GAN
  (MIT) замерена и не взята: её готовый конвейер оставлял «призраки»
  букв. Тест — `tests/test_paint_lama.py`.
- **Ф1 — общий список рукописных шрифтов.** Список живёт в
  `backend/print_fonts.py` и его берут оба пути: прежде он был только
  в `layout_pdf`, и та же страница картинкой печаталась гротеском.
  Семейство страницы решает один `main._hand_image`.
- **Края раскладки (ревью кода).** Слово шире строки даже на полу (URL,
  формула) — своей строкой с `over`, а не пустая раскладка: пустая стёрла бы
  оригинал и не написала ничего (`_wrap_rhythm(force=True)`). Абзац с ритмом,
  не влезший и тесно, уходит прежней дорогой (строки в рамке абзаца или
  плашка), а не строками поверх соседнего абзаца. Абзац, выпавший из класса
  страницы, раскладывается со СВОИМ сжатием и пером; свободные строки
  проверяются тем шагом, которым будут напечатаны. Калибровка почерка —
  только по рамкам строк и не ниже `PAINT_CALIB_FLOOR` (по полосам маски
  ширина краски ненадёжна). Модель бумаги — только на вырезке до
  `PAINT_PERIODIC_MAX_MPX` (2.5 Мп): несколько копий вырезки в float32,
  а воркер один. Прозрачная картинка — прежней заливкой (хранит
  прозрачность). В PDF жирность рукописи — обводкой, не DejaVu Bold;
  ширину исходника меряет шрифт, знающий его буквы.
- **Кинсоку и кавычки.** Кавычка, за которой сразу стоит «。» или другой
  знак, которым строка не начинается, — закрывающая при любой форме
  (немецкие кавычки в китайском переводе): к началу строки её не переносят
  (`image_text._cjk_units`, `_QUOTES`); «”» и «’» добавлены в `_NO_LINE_START`.
- **Не сделано и сказано:** почерк автора не воспроизводится — потолок
  это общий рукописный шрифт (Marck Script: латиница и кириллица; иначе
  шрифт письменности, `img_hand_fallback`). Второе независимое чтение
  рукописи для сверки слов не делается — ошибку чтения исправляет человек
  (У5). Сильно изогнутая или снятая под углом бумага может не сдать
  экзамен модели — тогда прежнее стирание. У PDF свободные строки ниже
  абзаца не ищутся.

## Х. Остаток разбора плиток лендинга: машинопись, выключка, абзацы, след (16.10.2026)

Регрессия раздела Ф на картинках лендинга (машинопись 1940 г., страница
Чехова EN/ZH/AR, статья npj) и критики показали, что ещё не «как в
оригинале». Код — `text_paint` (общий), `image_text`, `layout_pdf`; тест —
`tests/test_hand_paint.py` (разделы Х).

- **Х1. Машинопись печаталась гротеском.** Признак — шаг знака постоянный:
  середины «букв» (связных столбцов краски) строки ложатся на сетку шага;
  шаг — ширина строк ÷ знаков исходника (без кегля, который у машинописи
  меряется плохо). Мера — лучшая фазовая согласованность по шагам около
  него (`text_paint.mono_score`), порог `PAINT_MONO_COH` 0.55. Замер:
  машинопись 0.65, набранная книга 0.40, статья 0.24–0.30, почерк —
  «букв» мало, мерить нечем. Семейство `type`: Liberation Mono (OFL,
  метрика Courier) лежит в `frontend/vendor/fonts/sub` (`print_fonts.MONO_FONTS`).
  В PDF — своё семейство `type`, а не `mono`: тот печатает код из PDF.
  Толщина удара литеры — как у пера (Ф7).
- **Х2. Выключка — по краям строк оригинала**, а не по слову модели о блоке
  (машинопись стояла по центру). Ровный левый край (разброс начал ≤
  `PAINT_ALIGN_MAD` кегля без первых строк абзацев) — влево; плюс правый
  ровнее `PAINT_JUSTIFY_MAD` (0.1 кегля; у почерка «на глаз» 0.14, у книги
  0.05) — по ширине; только правый — вправо; ровные середины — по центру
  (`text_paint.geometry_align`). Почерк по ширине не выключается никогда.
  По ширине печатаются все строки абзаца, кроме последней; промежуток шире
  `IMG_JUSTIFY_MAX` пробелов — строка остаётся невыключенной (дыры хуже
  рваного края); письмо без пробелов не растягивается. В PDF — `Tw`.
- **Х3. Абзац внутри блока.** Строка (не первая), начатая с той же красной
  строки, — первая строка нового абзаца (`text_paint.para_heads`); перевод
  получает разрыв у ближайшего конца предложения к доле исходника до этого
  абзаца, не дальше `PAINT_PARA_BREAK_REACH` (`para_breaks`); нет такого —
  разрыва нет (рвать предложение хуже). Отступ — у первой строки КАЖДОГО
  абзаца (`rhythm_heads`).
- **Х4. Отступ у перевода справа налево — справа.** Красная строка — это
  начало строки; у арабского перевода русского абзаца она стоит справа.
- **Х5. След стёртого текста.** Три причины, три правила: (а) волосяные
  штрихи, засечки и сглаживание слабее порога маски — краска, отличная от
  фона больше `PAINT_WEAK_INK` порога, не дальше `PAINT_WEAK_REACH` точек
  от маски, стирается вместе с буквами (кроме бумаги с узором — там Ф6);
  (б) мягкий край альфы стирания — снаружи маски, на нетронутых точках
  (размытие по самой маске оставляло серый ободок); (в) тон каждой области
  стёртого выравнивается по кольцу бумаги вокруг (`_tone_match`, не больше
  `PAINT_TONE_MAX`); «ровный» фон заливается местным тоном, а не одним
  цветом. Перенос «зерна» бумаги пробовали — он добавлял шум и след
  усиливал; отвергнут.
- **Х6. Засечки.** Модель чтения отвечает `serif` на блок —
  перерисовка картинки печатает Noto Serif, PDF — шрифт с засечками.
  Прочитанное раньше признака не несёт — его решает Х9.
- **Х7. Дефис рукописного шрифта.** Дефис короче 0.25 кегля при печати
  заменяется тире, если оно есть и не длиннее 0.45 кегля (у Marck Script
  дефис 0.2 кегля, «free-living» читалось «freeliving»). Текст строки
  не меняется — только печать.
- **Х8. Буква, разрезанная краем вырезки, стирается целиком.** Симптом:
  буквица «В» у Чехова выходит вверх за рамку блока, стирание резало её
  по краю вырезки — над переводом оставалась верхняя половина с завитком.
  Правило (`text_paint.continuation_mask`, вызов — `image_text._cut_patch`
  и `layout_pdf._paint_measure`): если стёртое касается края вырезки,
  вырезка расширяется на `PAINT_CUT_REACH` строк в эту сторону, и краска,
  связанная со стёртым (та же связная область; фон — максимум окрестности
  шире штриха, иначе у толстой буквицы середина штриха не считалась
  краской), стирается одним проходом с буквой, вместе с мелкими областями
  рядом (завитки, точки орнамента, не крупнее `PAINT_CUT_SAT` строки).
  Не стирается область выше или шире `PAINT_CUT_MAX` строк (рамка, линия,
  рисунок) и лежащая за краем больше чем на `PAINT_CUT_FOREIGN` долю в рамке
  ЧУЖОЙ надписи. Заплатка кладётся ПОСЛЕ стирания блока — шва по краю
  вырезки нет. Замер своё/чужое у края вырезки: область своя, если её
  середина в рамке надписи ИЛИ в рамке лежит не меньше `PAINT_OWN_SHARE`
  её точек (буквица больше выше строк, чем внутри). Бледные края завитка
  (на 6–12 единиц темнее бумаги) берёт ореол Х5а: порог — от шума самой
  бумаги (`PAINT_HALO_K` разбросов, не меньше `PAINT_HALO_MIN`).
- **Х9. Засечки — по буквам.** Симптом: книга Чехова (1886, антиква)
  на лендинге переводилась гротеском — блоки прочитаны до вопроса
  о засечках (Х6), признака нет. Правило (`text_paint.serif_score` /
  `serif_fam`, вызов — `image_text._paint_measure` и
  `layout_pdf._paint_measure`): вертикальный штрих (не шире 1.8 штриха
  строки) берётся на высоте 0.5 и 0.3 буквы, прослеживается вниз до строки,
  и меряется ширина его «ступни» в нижних строках; вынос =
  (ступня − штрих − 1 точка) / высота строчной (размах между пиками
  профиля, у прописных с засечками середина тоньше пиков); медиана по
  штрихам. Не меньше `PAINT_SERIF_EXT` (0.13) — антиква, не больше
  `PAINT_SANS_EXT` (0.05) — гротеск, между — слово модели; строчная ниже
  `PAINT_SERIF_XH` (10) точек или штрихов меньше `PAINT_SERIF_STEMS` (10) —
  мерить нечем, слово модели. Рукопись и машинопись (Х1) мера не трогает.
  Замер: гротески (Arial, Calibri, Verdana, Segoe, Tahoma, Trebuchet,
  Noto Sans, обычные и жирные, 24–60 px) 0–0.05; антиква (Times, Georgia,
  Cambria, Noto Serif, обычные и жирные) 0.1–0.58, от 40 px — от 0.17;
  книга 1886 г. 0.42, её заголовок прописными 0.29, заголовок статьи
  (Times) 0.24, текст статьи (гротеск) 0.09 — между порогами, остаётся
  гротеском. Ниже 24 px антиква часто «не знаю» — промах даёт прежний
  гротеск, а не ложные засечки.
- **Х10. Дореформенная печать — старой антиквой; кегль — по строчным.**
  Симптом: перевод книги Чехова (1886) печатался Noto Serif — современной
  широкой антиквой, сжатой по ширине до 0.84, — «шрифт далёк от
  оригинала». Пробовали мерить стиль по пикселям: ширина при равных
  строчных, пропорция строчных к выносным, распределение толщин штрихов
  с имитацией размытия — все три ставили книгу БЛИЖЕ к Noto (контраст
  и форму засечек съедает размытие скана); на впечатление правило не
  ставим. Объективный признак эпохи — текст: ять, фита, ижица или ер на
  конце слов (не меньше 3 слов и `PAINT_OLD_ER_SHARE` кириллических;
  «і» — не признак, она жива в украинском и казахском) — значит, набор
  до 1918 г., «обыкновенной» антиквой. Тогда семейство засечек — «old»:
  Old Standard TT (OFL, `print_fonts.OLD_FONTS`, общий список картинки
  и PDF), её воспроизведение. Эпоха — свойство СТРАНИЦЫ (`render_target`:
  заголовок «СМЕРТЬ ЧИНОВНИКА.» без ъ — той же антиквой); в PDF — по
  надписи. Нет букв письменности (китайский, арабский) — шрифт
  письменности, как везде. Кегль: высота строчных оригинала ÷ высота «x»
  шрифта, если меньше кегля из долей 0.73/0.53 (`em_by_xheight`; доля
  строчных в тексте не меньше `PAINT_XH_LOWER` — прописные не строчные).
  Вес обводкой НЕ догоняется: штрих скана раздут размытием.
  Граница: на чистом цифровом рисунке Old Standard мера машинописи (Х1)
  даёт 0.51–0.60 при пороге 0.55 (у скана книги — 0.40, у машинописи —
  0.65): короткий абзац контрастной антиквы может уйти в машинопись.
- **Х11. Полужирный от размытия снимается площадью краски.** Симптом:
  аннотация статьи (обычный гротеск) печаталась жирным — толщина штриха
  к кеглю 0.121 при пороге 0.12, порог решало размытие JPEG. Правило
  (`text_paint.bold_by_area`): площадь краски в рамках строк против
  площади исходного текста, набранного обычным и жирным файлом при том
  же кегле; ближе к обычному (лог-расстояние) — не жирный. Только
  СНИМАЕТ: размытие площадь раздувает, то есть тянет к жирному; назначать
  жирный площадью нельзя (у контрастной антиквы размытая обычная похожа
  на жирную: Old Standard 0.94 к жирному при 1.38 к обычному). Аннотация:
  1.09 к обычному, 0.69 к жирному; заголовки «ARTICLE», «OPEN» и адрес
  остались жирными. В PDF — то же (Х13).
- **Х12. Замер штриха — по середине тона.** Маска букв берёт всё, что
  заметно темнее бумаги, и размытие скана раздувает по ней штрих — поэтому
  вес по маске не мерили (Х10, Х11). На уровне ровно посередине между
  бумагой и краской край штриха при симметричном размытии стоит на месте
  (`text_paint.stem_mid`, край — с интерполяцией между точками: Old
  Standard 48 px — 3.43 без размытия, 3.49 при 1.5 px). Штрих тоньше
  `PAINT_WEIGHT_MIN_PX` (3 точки) сравним с размытием — по нему ни цвет,
  ни вес не правим (аннотация статьи по середине тона выходила «жирнее»
  шрифта и темнела против оригинала).
- **Х13. Цвет краски — по оси штриха; вес — до плотности набора.**
  Симптом: книга 1886 г. и старой антиквой «не похожа» — перевод на треть
  светлее (доля тёмного 0.097 против 0.144) и бледнее (краска 29 при самых
  тёмных точках оригинала 16).
  * Цвет (`core_ink`): медиана точек на ОСИ штриха — маска середины тона,
    расстояние до её края не меньше половины толщины штриха; там краска
    не смешана с бумагой. Прежняя мера (медиана тёмной трети точек маски)
    у штриха в 3–4 точки наполовину состоит из краёв. Подбирать долю
    тёмных точек нельзя: доля, при которой сходилась книга (0.2), делала
    машинопись темнее оригинала.
  * Вес (`band_density`, `sample_density`, `weight_by_density`): цель —
    ПЛОТНОСТЬ набора, доля краски в полосе строчных (середина тона), а не
    толщина штриха в точках: у перевода, сжатого по ширине, тот же штрих
    на узкой букве читается жирнее (заголовок статьи, Noto Serif сжат
    до 0.78, со штрихом «как у оригинала» выглядел полужирным). Пробная
    строка перевода рисуется тем же файлом, кеглем, сжатием и краской,
    обводка подбирается делением пополам до плотности оригинала (допуск
    `PAINT_DENS_TOL`), не больше `PAINT_STROKE_MAX` кегля; без обводки уже
    не светлее — обводки нет (истончать нечем). Слой строки рисуется
    вчетверо крупнее и уменьшается — обводка дробная.
  * Кегль по строчным — только вниз (Х10): «в обе стороны» перелетал
    (строчные 23 против 21) — высоту оригинала меряет маска, раздутая
    размытием. Высота «x» шрифта мерится тем же размахом профиля строки,
    что у оригинала (`font_xh`), а не рамкой буквы.
  * Итог на книге: доля тёмного 0.141 против 0.144, плотность в полосе
    строчных 0.347 против 0.326, краска 22 против 16. Заголовок статьи
    обводки не получает; аннотация и машинопись не изменились.
  * Машинопись — тем же правилом плотности, а не толщиной пера (Ф7):
    штрих по маске раздут размытием, и перевод машинописи 1940 г. выходил
    плотнее оригинала (0.449 против 0.31; стало 0.322). Ф7 остаётся
    только у рукописи.
  * PDF (`layout_pdf._paint_measure` / `_paint_plan`): те же функции —
    ось штриха, плотность, обводка (`setLineWidth`, дробная), и Х11.
    Обводка — только у надписи с рамками строк (ветка `geo`).
  * Не сделано: латиница и дореформенная кириллица заполняют строку
    по-разному, полного совпадения плотности быть не может; ширина Noto
    Serif против Times (сжатие 0.78 у заголовка статьи) — вопрос выбора
    шрифта, не веса.
- **Х14. Строка другого размера в конце блока — свой участок.** Симптом:
  чтение склеило две строки заголовка статьи (Times, полосы 50 и 40 точек)
  и строку авторов (мелкий гротеск, 27) в один блок; перевод один на блок
  и укладывался одним кеглем — авторы размером заголовка, и всё сжималось
  до 0.78. Правило (`text_paint.size_split`, `tail_anchor`; раскладка —
  `image_text._paint_layout1`, ветка участков): ПОСЛЕДНЯЯ настоящая полоса
  (не обрывок выносных: не ниже `PAINT_SPLIT_FRAG` самой высокой) ниже
  медианы предыдущих в `PAINT_SPLIT_SIZE` (1.5) раза и больше, И в конце
  перевода есть хвост, перенесённый из оригинала дословно (имена не
  переводятся): не меньше `PAINT_TAIL_MIN` слов, чужих — не больше
  `PAINT_TAIL_FOREIGN`, слова хвоста идут в оригинале в том же порядке
  и заканчивают его. Тогда блок — два участка: у каждого свой кегль (по
  высоте ЕГО строчных против первого), сжатие по ширине — по первому
  участку и его части оригинала; ровный ритм строк (Ф1) у такого блока
  не применяется. Число сегментов не меняется. Нет однозначного хвоста
  ни дословно, ни по номерам (Х16) — блок не делится: разрез по доле
  длины посреди имени хуже общего кегля. Порог
  по высоте — только для последней строки: буквица, индексы и прописные
  дают рамки в 1.3–1.5 раза разные посреди обычного абзаца. Правило
  сборки блоков при чтении не меняли по той же причине. Шрифт у участка
  общий с блоком (авторы оригинала — гротеск, у нас — антиква блока).
  В PDF — то же (`layout_pdf._paint_plan1`: полосы, высота строчных
  и ширина краски полос пишутся в замере); обводка Х13 у разделённого
  блока — своя у каждого участка (Х16).
- **Х15. Машинопись уменьшается поровну кеглем и шириной.** Симптом:
  английский перевод машинописи 1940 г. длиннее русского, раскладка (Ф3)
  уменьшала только кегль — 30.5 при замеренных 43.4, строчные 16 против 23.
  Правило (`image_text._paint_layout`): у машинописи, если раскладка
  уменьшила кегль в f раз, она повторяется со сжатием по ширине h0·√f
  (общее, вместе с калибровкой ширины, не ниже `IMG_TYPE_HMIN` 0.8)
  и берётся, если кегль вырос. Итог: кегль 35.5, строчные 19, плотность
  0.314 против 0.31. Почерк по ширине не сжимается (Ф2), печатный набор
  держит порядок Ф3 — правило только для машинописи. В PDF — то же
  (`layout_pdf._paint_plan` — обёртка над `_paint_plan1`, пороги из тех же
  переменных окружения).
- **Х16. Хвост по номерам аффилиаций; обводка участка — своя.** Симптом:
  на китайском, казахском и арабском переводе статьи имена авторов
  транслитерированы, дословного хвоста (Х14) нет, и блок «заголовок +
  авторы» не делился — авторы печатались кеглем заголовка. В PDF
  разделённый блок шёл без обводки Х13, и тонкий авторский гротеск
  против жирного заголовка терял разницу. Правило
  (`text_paint.tail_by_numbers`): в оригинале с последней строкой
  авторов стоит ряд «имя+номер» — не меньше `PAINT_NUM_MIN` (3) номеров
  1–99 вплотную после буквы (не год, не «[1]», не «COVID-19»), номера
  не больше числа авторов и идут по первому появлению (1, дальше не
  больше уже встреченного + 1 — «CO2, SO2, NO2» не авторы), перед номером
  слово от двух букв, имя из 1–`PAINT_NAME_WORDS_MAX` слов с заглавной
  (частицы «de», «van» допускаются), и ряд — ПОСЛЕДНЯЯ сплошная цепочка
  до конца оригинала (номер в заголовке, «IL6», её не продолжает).
  У письма с регистром имя в переводе считается своим обходом и обязано
  совпасть по числу слов («Harvard Students Kana Okano» против
  «Garvard talabalarida Kana Okano» — не делим); у письма без регистра
  (арабица) — столько же слов, сколько в оригинале. В переводе — тот же ряд номеров В ТОМ ЖЕ порядке,
  и после последнего номера текста нет; номера в переводе ищутся и
  в над/подстрочной и полноширинной записи. Хвост начинается с имени
  перед первым номером: у письма без пробелов — после ближайшего
  разделителя («、», «，», пробел). Совпали не все номера или порядок —
  не делим. Обводка: у каждого участка своя, по плотности ЕГО полос
  (`bandDens` в замере; картинка — `strokeF` у участка в
  `image_text._paint_layout1`, PDF — `stroke` у участка в
  `layout_pdf._paint_plan1`); блок без деления (столбцы схем) обводки
  участков не получает, как и прежде. Сторожит `tests/test_hand_paint.py`
  (раздел Х16).
- **Х17. Семейство шрифта у участка — своё.** Симптом: заголовок статьи
  набран антиквой, строка авторов — гротеском; блок разделён (Х14/Х16),
  но перевод авторов печатался антиквой заголовка. Правило
  (`text_paint.part_fam`): засечки каждой полосы участка меряются тем же
  `serif_score`, что у блока (Х9); медиана известных против тех же порогов
  (`PAINT_SERIF_EXT`, `PAINT_SANS_EXT`); замер не удался или между
  порогами — семейство блока. Почерк и машинопись участкам не меняются,
  дореформенная антиква (Х10) остаётся дореформенной. Высота строчных
  участка сохраняется: кегль пересчитывается на высоту «x» нового шрифта
  (`font_xh`). Картинка — `image_text._paint_layout1` (шрифт и мерка
  строки участка свои), PDF — `layout_pdf._paint_plan1` (засечки полос
  `bandSerif` в замере, шрифт участка `part["font"]`, печать —
  `_paint_text`; у PDF антиква — пустое семейство). Замер на статье: полосы заголовка 0.24 и 0.29, полоса
  авторов 0.0.
  Попутно найдено и исправлено: у надписи с картинки в PDF пустое
  семейство значит «антиква» (так его пишут и чтение — `serif` модели, —
  и Х9 в замере), а раскладка (`_paint_plan1`) читала пустое как рубленый
  (`or "sans"`) — найденная антиква печаталась гротеском. Теперь пустое
  печатается антиквой, рубленый — только явным «sans»; семейства нет
  вовсе — рубленый, как прежде.
- **Х18. Значок в строке — не буква.** Симптом: зелёный кружок ORCID у
  фамилии последнего автора стирался вместе с текстом и пропадал. Правило
  (`text_paint.find_icons`): значок — связная область ЦВЕТНОЙ краски
  (насыщенность выше `PAINT_ICON_SAT`, дальше `PAINT_ICON_DIST` и от краски
  букв, и от фона), сама краска блока не цветная (иначе это цветной текст:
  «OPEN» оранжевым значком не стал), стороны в 0.6–1.6, заполнение
  выпуклой оболочки не меньше `PAINT_ICON_FILL`, рост
  `PAINT_ICON_HMIN`–`PAINT_ICON_HMAX` высот строчных своей полосы. Справа
  от него в полосе не больше `PAINT_ICON_TAIL` высот строчных краски
  («Grossman ⓘ³») — значок КОНЦА строки. Стирается вместе с выпуклой
  оболочкой (белое «iD» внутри) и ставится после последней строки перевода
  СВОЕГО участка (у письма справа налево — перед её началом), тем же ростом
  к строчным и на той же высоте над строкой (`image_text._put_icons`,
  `layout_pdf._paint_icons`). Значок посреди строки, не в последней строке
  участка или за краем картинки не ставится и называется числом
  (`iconsSkip` в отчёте): место посреди переведённой строки — догадка,
  а значок посреди слова хуже пропавшего. Стирается только значок конца
  строки: ложное срабатывание посреди картинки (шум JPEG на цветном фоне)
  иначе стёрло бы кусок рисунка без замены. Ничего не хранится: значок
  вырезается из самой картинки при каждой выгрузке. Не больше
  `PAINT_ICON_MAX` на блок.
- **Х19. Строка другого размера — разрыв строки при ЧТЕНИИ.** Симптом:
  письмо без пробелов (китайский, японский) без номеров аффилиаций и без
  разделителя перед первым именем не делилось: модель чтения склеивает
  строки блока пробелом, перевод — один текст, и где в нём кончается
  заголовок, сказать нечем (Х14, Х16 молчат). Правило
  (`image_text.size_break`): блок от 2 до `IMG_BREAK_ROWS` строк, не наклонный
  и не по дуге, у которого высота строчных ПОСЛЕДНЕЙ строки (по пикселям,
  `x_height`, обе не меньше `IMG_BREAK_XH_MIN`) меньше медианы остальных
  в `PAINT_SPLIT_SIZE` раза, читается двумя вырезками: строки над ней — под
  номером блока, она сама — под номером после всех блоков
  (`main._openai_read_image`), и текст склеивается через «\n»
  (`sizeBreak` у ответа). Число блоков и сегментов то же; модель не
  гадает, где разрыв, — его ставим мы. Перевод получает строку
  «LINE BREAKS: keep exactly the same number» ТОЛЬКО когда в оригинале есть
  разрыв (`_openai_translate`; обратный перевод не трогается), у остальных
  промпт байт в байт прежний. Раскраска (картинка и PDF) режет блок по
  последнему разрыву (`text_paint.tail_by_break`, при равном их числе)
  раньше дословного хвоста (Х14) и номеров (Х16). Ключ памяти переводов
  и дедупликации разрыв не различает (`_norm_key`). Действует на НОВЫЕ
  чтения: прочитанное лежит в кэше по отпечатку картинки и не
  перечитывается; ручная перегруппировка блоков разрыв снимает (там блоки
  сливаются заново). Замер на статье: срабатывает ровно на блоке
  «заголовок + авторы», на машинописи, книге и конспекте — ни разу.
  `IMG_READ_SIZE_BREAK=0` выключает. Сторожит `tests/test_size_break.py`.
- **Х20. Чужая краска в рамке надписи не стирается.** Симптом: печать,
  подпись синей ручкой, пометка маркером лежат поверх строки или касаются
  её рамки, и стирание по маске букв (с добором бледной краски и ореола,
  Х5а) уносило их вместе с текстом — документ терял печать. Правило
  (`text_paint.foreign_marks`, `_colour_parts`): цветная краска (тот же
  признак, что у значка Х18: насыщенность, далеко от краски букв и от
  бумаги, краска блока сама не цветная) считается чужой, если доходит до
  верхнего или нижнего края вырезки (продолжается за рамку строки — буква
  строки за неё не выходит) или крупнее буквы (`PAINT_FOREIGN_H` высот
  строчных, `PAINT_FOREIGN_W` высот строк). Части одного предмета,
  разрезанного рамкой (две дуги кольца), объединяются в одну рамку, и мелкая
  цветная краска внутри неё («SEAL», дата штампа) — тоже её. Эти точки
  становятся ЗАЩИЩЁННЫМИ (`m["protect"]`): `erase` вычитает их и из маски,
  и из её расширения, и из добора бледной краски и ореола. Перевод пишется
  поверх, как в оригинале текст лежал под печатью. Картинка
  (`image_text._paint_measure`) и PDF (`layout_pdf._paint_measure`).
  Чёрная подпись цветом от букв не отличается — её правило не видит
  (названо). Сторожит `tests/test_paint_marks.py`.
- **Х21. Неразрывный пробел строку не рвёт.** Симптом: перевод ставит
  U+00A0 и U+202F между числом и единицей («5 мг», «12 %»), перед «:;!?»
  во французском, после инициалов, а раскладка разбивала текст на слова
  `str.split()`, который считает их обычным пробелом, — «5 / мг» уезжали
  на разные строки (правило набора nbsp, Брингхерст; CLDR). Правило
  (`text_paint.words`): слова режутся только по пробелам, где перенос
  разрешён; U+00A0, U+202F, U+2007, U+2060 остаются внутри слова. Все
  переносы раскладки идут через него: `fit_lines`, `fit_rhythm`,
  `rhythm_heads`, `image_text._wrap`, `layout_pdf._wrap`, `_spread`,
  `_fit_flow` и соседи. Сторожит `tests/test_paint_marks.py`.
- **Х22. Кинсоку — одним набором из данных.** Симптом: знаки «строку не
  начинает» и «строку не кончает» жили тремя копиями (субтитры, надписи на
  картинках) и разошлись — у картинок не было маленьких кан и знаков
  повтора, — а выгрузка PDF их не знала вовсе: японская строка в PDF
  начиналась с «。» и кончалась «「». Правило: наборы — данными
  (`backend/line_break.json`: `no_start` по JLREQ 3.1.7, `closing_quotes`,
  `postfix` — знак после числа, `no_end`; классы UAX #14), загрузчик
  `backend/linebreak.py` (`fix_break` сдвигает разрез НАЗАД, пока строка
  начинается запрещённым знаком или кончается открывающим). Пользуются:
  субтитры (`media`, наборы прежние буква в букву — вывод не меняется),
  надписи на картинках (`image_text._cjk_units`: открывающий знак держится со
  следующим) и PDF (`layout_pdf._break_point`). Правит набор человек, знающий
  язык; код не трогается. Сторожит `tests/test_paint_marks.py`.
- **Х23. Строка без нижних выносных — потолок кегля по высоте прописной.**
  Симптом (синтетика `heading-colour`, 18.10.2026): заголовок «Results and
  discussion» кеглем 40 перекрашивался кеглем 31 и полужирным. Причина:
  у однострочной надписи кегль ограничен высотой рамки строки (1.05·lh), а
  рамка строки без g/p/y — это высота прописной (~0.74 кегля), не кегль;
  кегль занижался на четверть, и обычный штрих при мелком кегле читался
  жирным. Правило: есть ли нижние выносы, решает сам шрифт
  (`text_paint.has_descender`: рамка буквы опускается ниже базовой линии
  больше 0.08 кегля, Noto Sans из репозитория) — списка букв нет; без
  выносов потолок 1.02·lh / `CAP_SHARE` (0.74, `PAINT_CAP_SHARE`). Только
  у письма с регистром и одной строки: у иероглифов и арабицы прописной
  нет, у многострочной рамка своя. Нет шрифта — прежний потолок.
  Сторожит `tests/test_synth.py`.
- **Синтетические страницы.** Рецепты — данными
  (`backend/doc_catalog/synth_recipes.json`: строки, шрифт, кегль, цвет,
  значок, печать, фон; коэффициенты длины перевода и алфавиты языков),
  страница рисуется `backend/synth.py`, «переводится» псевдословами той же
  формы без модели и проходит раскраску выгрузки и замеры `fidelity`. Ловит
  откаты правил; покрытием каталога не является (проверяет раскраску на её
  же представлении о мире). Новый вид документа — новый рецепт. Замер
  `outside` считает только изменённое СОДЕРЖИМОЕ вне рамок (пиксели, что
  отличались от бумаги), а не любую разницу: законные лишние строки Ф3
  растут на чистую бумагу. Линии схемы в рецепте — `rules`.
- **Х24. Одна строка — во вторую строку на чистой бумаге, а не мельче.**
  Симптом (синтетика `caption-on-tint`): подпись в одну строку, перевод
  длиннее на десятую, печаталась кеглем 0.71 — у одной строки не было
  геометрии абзаца, и Ф3 (свободные строки ниже) её не касался. Правило:
  у одной строки — своя геометрия (`text_paint.one_line_geometry`: база по
  телу краски, края по краске, шаг — «авто»-интерлиньяж `ONE_LEAD` 1.2
  кегля, `PAINT_ONE_LEAD`); если в одну строку перевод ужимается мельче
  `ONE_SHRINK` (0.85) кегля, `image_text._one_line_grow` берёт свободные
  строки ниже (`_free_rows`, не больше одной) и оставляет раскладку, только
  если кегль там крупнее. Вторая строка — лишь на ЧИСТОЙ бумаге: не больше
  `ONE_PAPER` (1 %) пикселей полосы отличаются от фона надписи сильнее
  `ONE_PAPER_TOL` — линии схемы и сетка буквами не считаются, а печатать
  по ним нельзя. Ф4 (общий кегль класса абзацев) одну строку не трогает.
  Сторожит `tests/test_synth.py` (и без проверки бумаги тест падает).
- **Х25. Не текст в рамке надписи — код и линия поля — не стирается.**
  Симптом (синтетика `qr-label`, `signature-field`): QR-код рядом с текстом
  и линия «Подпись пациента ______» попадали в маску текста (цвет тот же,
  Х20 их не видит), стирались вместе с ним — QR становился белой
  заплаткой, линия поля пропадала, — а QR ещё и считался «второй строкой»
  (кегль 0.69). Правило (`text_paint.object_marks`, без списков): КОД ищут
  детекторы OpenCV (`QRCodeDetector`, `barcode.BarcodeDetector` — правила
  формата кода, а не наши), и только у КАНДИДАТОВ: пятно после растяжки по
  горизонтали выше `CODE_TALL` (1.4) строк и плотнее `CODE_FILL` (0.32) —
  строка текста остаётся высотой в строку, слипшиеся выносными строки
  неплотные; высота строки — по самим буквам (медиана, взвешенная по
  ширине: рамка строки с кодом выше строки на код), детектору — только сам
  кандидат в поле фона (чужие буквы рядом сбивают поиск меток). Кандидат и
  находка обязаны быть ДВУХЦВЕТНЫМИ (`CODE_TWO_TONE`: доля пикселей у краёв
  диапазона яркости ≥ 0.8 — у фото и градиента середина; без этого на
  плавном фото детектор находил три «кода»), не больше `CODE_MAX` (12)
  строк по стороне, QR — почти квадратный (`CODE_QR_ASPECT`), кандидатов
  к детектору — не больше `CODE_CANDS` (8). ЛИНИЯ ПОЛЯ —
  штрих тоньше `FIELD_THICK` (0.15) строки, длиннее `FIELD_W` (3) строк,
  и над ним пусто (не больше `FIELD_EMPTY` столбцов с краской на строку
  вверх): у подчёркивания над линией буквы — оно стирается с текстом, как
  прежде. Если оригинал сам набран подчёркиваниями или точками
  (`typed_rule`: «Имя: ______») — это текст, его повторит перевод, и линия
  не защищается (иначе вышла бы двойная). Найденное: замер — без него, стирание — мимо него (`protect`),
  место перевода (`text_span`, ключ `tx`) — от текста до объекта с зазором
  `OBJ_GAP` (0.3 строки), длинный перевод уходит во вторую строку (Х24).
  `fidelity` закрывает те же объекты с обеих сторон. В PDF — замер без
  объектов и защита от стирания; место перевода там своё, по рамке блока
  (сужения нет — названо). Штрихкод синтетикой
  не проверен (нет кодировщика без лишних библиотек) — только QR; QR после
  перерисовки читается тем же детектором. Сторожит `tests/test_synth.py`.
- **Не сделано и сказано.** Значок посреди строки не переносится (см. Х18).
  Кегль по строчным «в обе стороны» (искажение
  поровну между кеглем и шириной) не делали: на книге он даёт 42.0 при
  нынешних 42.5 — нынешнее «только вниз» уже этот компромисс, а правка
  меняла бы раскладку всех печатных картинок. Полного совпадения шрифта
  нет и не будет: латиница и дореформенная кириллица — разные письма;
  Liberation Serif (метрика Times) при той же высоте строчных той же ширины,
  что Noto Serif (0.884 / 0.882), добавлять его незачем.

## Ц. Статья журнала RU→EN/DE/ZH: ложный полужирный, колонтитулы, надстрочники, эхо слоя (проекты 105/106/110, 18.10.2026)

Разбор трёх выгрузок статьи «Бюллетеня сибирской медицины» (7 страниц, две
колонки, таблицы, диаграмма) критиками по языкам: 44 дефекта в английской,
60 в немецкой, 80 в китайской. Сведены в виды; почти все — следствие
шести особенностей ОДНОГО файла, и каждая повторится на любом журнале,
свёрстанном так же. Правила — `pdfpages_worker.py`, `pdftext.py`
(`RULES_VERSION` 17), `main.py`, `checks.py`, `lang_rules.json`; страж —
`tests/test_journal_article_rules.py` (сквозная проверка на самой статье —
по `ARTICLE_PDF`, файл клиента в репозиторий не кладётся).

**Ц1. Текст, напечатанный дважды в одной точке — один текст**
(`pdfpages_worker._faux_bold_strip`, `_undouble`, `PDF_FAUX_BOLD`).
Симптом: колонтитул на каждой странице читался «Бюллетень сибирской медицины.
Бюллетень сибирской медицины. 2026; 25 (3)2026; 25 (3): : 34–4034–40»,
переводился задвоенным, а на соседних страницах не узнавался колонтитулом
и вклеивался в абзац. Причина: «ложный полужирный» — тот же кусок обводкой
(`1 Tr`) и сразу заливкой (`0 Tr`, `0 0 TD`); pypdf отдаёт обе копии ОДНИМ
куском. Правило: оператор показа текста с теми же байтами в той же точке
сразу после такого же — повтор; из текста куска своей базовой линии он
вырезается по длинам операторов (число и порядок кусков не меняются,
номера `dups` остаются верны), оставшийся кусок — полужирный.

**Ц2. Колонтитул по месту, когда пробела под ним мало**
(`pdftext._bands_by_place`, `BAND_GAP_PLACED`). Симптом: на стр. 3, 5, 6
нижний колонтитул вклеивался в последний абзац колонки («…другого иссле-
Бюллетень сибирской медицины…»). Причина: полоса требует пробела не меньше
1.6 интервала, а здесь тело опущено до 1.54. Правило: на странице без полосы
она ищется порогом 1.2 — и принимается, только если ВСЕ её строки стоят на
высоте полос, найденных обычным порогом на двух и более других страницах
(±1.5 пт). Высота колонтитула — свойство вёрстки журнала.

**Ц3. Две надписи в одном куске; конец куска — цепочкой операторов**
(`pdfpages_worker._op_gap`, `OP_GAP_SPLIT`, `_chain_end`, `_abuts`).
Симптом: правая половина колонтитула «Ассоциация полиморфизма гена GATA3
(rs10905277)» терялась: курсивное «GATA3 (rs10905277)» становилось отдельным
абзацем, а прямое «Ассоциация полиморфизма гена» — «краской вне слоя», которую
разбор картинки читал заново (Ц8); в аннотации курсивное «GATA3» посреди строки
— отдельным абзацем, висящим справа («GATA3 in the additive»). Причины две:
pypdf склеил левую и правую надписи в один кусок (между операторами — 90 пт),
и конец куска, собранного из нескольких операторов, брался по ПЕРВОМУ из них.
Правило: кусок режется там, где следующий оператор начат дальше 3 кеглей
от конца предыдущего; конец куска — цепочка операторов, начатых вплотную
(0.6 кегля) один за другим, но не дальше начала СЛЕДУЮЩЕГО куска той же строки
(иначе ячейки инфографики «Loss (intermediate)» и «Beneﬁt:» слипались, проект 14);
кусок, начатый в конце оператора своей части (допуск — пробел, 0.3 кегля), —
продолжение надписи, а не «колонка». Выключатели: `PDF_OP_GAP_SPLIT=0`,
`PDF_CHAIN_GAP=0`, `PDF_ABUT_TOL=0`. Граница следующего куска заменяет оценочный потолок
цепочки (`RULES_VERSION` 18): оценка по ширине знака бывает короче настоящего
конца, цепочка обрывалась посреди куска, и в строке «…включая rs16967593
(STAT5B)…» оставался ложный разрыв 165–373 пт — перевод его обходил,
а оригинал в нём не стирался («including rs16967593 5 лет). Варианты генов…»). Пересборка с теми же абзацами («same») теперь переносит в карту проекта
и СНЯТИЕ разрыва (`main._merge_layout_fields`, `RULES_VERSION` 19): прежде она
добавляла только новые разрывы, и ложный оставался в карте навсегда.

**Ц4. Надстрочник не продолжается основным текстом**
(`pdfpages_worker._exact_ends`, `_other_row_at`). Симптом: строка авторов
«Мелентьева А.П.¹, Покотилова А.С.¹, Брагина Е.Ю.¹˒², …» выходила кусками
в разном порядке («Мелентьева А.П.¹ , Брагина Е.Ю.» | «, Покотилова А.С.¹» |
«1, 2, Огородова Л.М.»), индексы — обычными цифрами. Причина: цепочка Т33
(«надстрочная ссылка посреди строки») растягивала конец надстрочного «¹» на
следующего автора ниже него, а конец автора — на индекс, начатый СВОЕЙ строкой
pypdf; перекрытые места не давали склеить строку. Правило: на другой базовой
линии цепочка идёт только через оператор мельче строки, и никогда — через
оператор, с которого начинается другая строка ответа.

**Ц5. Номера надстрочником: «¹,²» и аффилиация с номера — абзац**
(`pdftext._script_text`, `_SCRIPT_LIST_RE`, `_SUP_LEAD_RE` в `_geo_follows`).
Список «1, 2» надстрочником пишется «¹,²» (запятая — только с пробелом:
«1,5» мелким кеглем — дробь, не список); надстрочник в НАЧАЛЕ строки
(«¹ Сибирский…») — тоже знаком надстрочника; строка, начатая надстрочным
номером и ПРОБЕЛОМ, начинает абзац (аффилиации и сноски не склеиваются
в одну), а «¹⁸F-ФДГ» в начале строки — нет.

**Ц6. Сноска не продолжается на следующей странице**
(`pdftext._page_size_break`, `PDF_PAGE_SIZE_BREAK`). Симптом: сноска автора
«✉ Мелентьева А.П., …@gmail.com» внизу стр. 1 и «Для цитирования…» стр. 2 —
один абзац. Правило: через границу страницы абзац не идёт, если последняя
строка страницы набрана мельче основного текста документа больше чем на 8%
и либо кончается адресом почты или ссылкой, либо мельче первой строки
следующей страницы, набранной кеглем основного текста. Строка основного
кегля с адресом на конце («see https://doi.» | «org/…») продолжается.

**Ц7. Таблица в одной колонке страницы**
(`pdftext._table_page_column`, `_crosses_cols`, `TABLE_IN_COLUMN`). Симптом:
строки левой колонки («…этапы: начальная денатурация в течение 10 мин при»)
шли вперемешку с ячейками таблицы правой колонки, шапка и заголовок таблицы
отрывались от тела, а таблица вставала посреди абзаца, перешедшего с прошлой
страницы. Причина: таблица (Т6) бралась по ВЫСОТЕ во всю ширину листа.
Правило: если 80% ячеек лежат в одной колонке страницы (колонки — по медиане
краёв длинных строк), таблица — только её строки; расширение вверх
останавливается на строке без соседей по ряду, перекрывающей начало колонки
таблицы (вторая строка названия по центру); таблица встаёт в поток своей
колонки — после её строки над таблицей.

**Ц8. Надпись картинки страницы — эхо текстового слоя**
(`main._layer_echo`, `_page_block_rect`, `LAYER_ECHO`). Симптом: в аннотации
поверх строки второй раз печаталось «SOCS5),», «IFNGR2», «inhibitory
protein», во «Введении» — «интерфероны (IFNG)», «CTGF», в литературе — «СТМЫ.»:
каша из двух текстов. Причина: место курсивных кусков слой знал неточно,
сверка «краска минус слой» (Т32) объявляла их краску потерянным текстом,
разбор картинки читал эти слова заново и заводил строку; отсев повторов
(`_dup_of_layer`) требует трёх слов. Правило: блок картинки страницы, чей
текст (от 3 букв и цифр) — подряд идущие СЛОВА абзаца слоя (у блока от
6 знаков — и нечётко), а сам блок лежит на СТРОКЕ этого абзаца (не просто
в рамке абзаца: у абзаца, обтекающего рисунок, она накрывает рисунок,
и «Age» на рисунке не эхо «stage» в тексте), — эхо:
при чтении строка не заводится (`skip: "layer"`, `echo`), заведённая прежде
не печатается (`layerEcho` в отчёте выгрузки). Надпись, СОДЕРЖАЩАЯ кусок слоя
и свои слова (Т32), эхом не является.

**Ц9. Красная строка, разрез адреса, «v. 2.050»**
(`pdftext._geo_follows` + `INDENT_BREAK`, `_addr_cut`, `_letter_mark_midphrase`,
`_same_baseline` в `_assemble`). Короткая строка, КОНЧАЮЩАЯСЯ адресом
почты или ссылкой, а следующая — с отступа 0.8–4 кегля, во всю ширину
и с заглавной: новый абзац («…orcid.org/0000-0002-2962-1076» и «Федорова
Ольга Сергеевна –» — пять авторов «Информации об авторах» были одним абзацем).
Без адреса на конце правило молчит: висячий отступ списка литературы
(«1. Автор А.Б. Название» | «Журнал. 2020;5:34») так не рвётся. Точка в конце строки после
почты или ссылки перед строчной — разрез адреса, а не конец фразы
(«…fedorova@gmail.» | «com, https://…»). Буквенный маркер пункта («v.», «a)»)
начинает пункт, только если предыдущая строка закончила фразу, короче 60 знаков
(заголовок списка «Критерии включения») или за ним идёт следующий пункт:
«…в программе PLINK» | «v. 2.050 (http://…)» — одна фраза; так же перестали
рваться «в начале II тыс. до» | «н. э.», «и т.» | «п.» в книге-скане 8. Часть строки (курсивное название
и прямой хвост) судит о продолжении по всей строке: «https://doi.» |
«org/10.20538/…» в «For citation» больше не рвётся.

**Ц10. Десятичный разделитель — норма языка перевода**
(`checks._extract_numbers`, поле `decimal` в `lang_rules.json`,
`_lang_conventions`). Симптом: в английском и китайском переводе стояло
«10,1 ± 8 years», «95% CI 0,34–0,77». Причина: сверка чисел сравнивала строки,
«10,1» и «10.1» были для неё разными числами (критичная находка, сильнее
заверения), и ремонт возвращал запятую. Правило: при сверке десятичная
запятая и точка — одно число; промпт перевода, ремонта и ревизии называет
разделитель языка перевода (`decimal`: «.» — EN, ZH, JA, KO; «,» — RU, DE, FR,
ES, IT, PT, UZ, KK, KY, TG, TR, AZ) и велит перевести в него дробное число
оригинала; номера разделов, версии, даты и идентификаторы — как есть.
**Ц10б.** Прежние переводы модель заново не трогает (сверка теперь их не
ругает), поэтому дробь оригинала, записанная запятой («10,1»), в переводе на
язык с точкой заменяется на «10.1» детерминированно (`main._decimal_fix`) —
на выходе перевода и в «тексте к печати» выгрузки; только числа, стоящие
в оригинале тем же видом, и только когда язык оригинала пишет дроби запятой.
Обратного направления нет: у точки в оригинале слишком много значений
(версии, номера пунктов). Там же при печати снимается Markdown (Ц12).

**Ц11. Символ гена, белка, кода — буква в букву**
(`main._ident_misses`, `IDENT_CHECK`, правило в `_translate_system`). Симптом:
в китайском переводе 32 строки из 234 «перевели» символы генов — «GATA3» стал
«GATA结合蛋白3» и «鸟嘌呤—腺嘌呤—胸腺嘧啶—腺嘌呤结合蛋白3», «STAT5B» —
«信号转导及转录激活因子5B». Правило: символ без дефиса из трёх и
более заглавных латинских и цифры (GATA3, STAT5B, SOCS5, IFNGR2, FCGR2A) или
номер варианта rs… из оригинала обязан стоять в переводе буква в букву —
бесплатная находка `ident` (ремонт), счётчик `_repair_scores`,
`REVIEW_FREE_KEYS`; промпт перевода говорит это прямо. Узко намеренно:
«HIV-1» → «ВИЧ-1», «IL-6» → «ИЛ-6», «CO2» → «CO₂», «T2DM» → «СД2» — законный
перевод сокращения, находкой не становятся. **Ц11б:** символ на месте, но рядом своя «расшифровка»
в скобках, которой в оригинале нет («GATA3（鸟嘌呤—腺嘌呤…结合蛋白3）»,
«…结合蛋白3（GATA3）» — так модель отвечала на первый ремонт), — та же находка.

**Ц12. Markdown, которого нет в оригинале, снимается**
(`main._strip_markdown` на выходе перевода и ремонта). Симптом: «**材料与方法**»,
«**结果**» — звёздочки в выгрузке. Правило: «**…**» и «__…__» снимаются,
содержимое остаётся, если в оригинале таких знаков нет.

**Ц13. Знак журнала — не надпись** (`main._logo_block`, `_same_look`,
`LOGO_RULE`). Симптом: логотип «ЕСМ» читался словом; английская выгрузка
закрашивала знак полосами и печатала «ECM», китайская — «细胞外基质».
Правило: блок картинки страницы из одного слова капсом до 5 букв у края
листа (верхние или нижние 15% высоты), строка которого выше основного текста
в 2.5 раза и выше любой строки на листе, — знак (`skip: "logo"`, не печатается;
слово капсом посреди страницы — заголовок, его переводят); надпись, чей перевод совпадает
с оригиналом по виду букв («ЕСМ» и «ECM»), не перерисовывается вовсе.

**Ц8б.** Блок, начатый вплотную за оценённым концом строки слоя (курсивный
хвост «варианта» после «…ассоциация»), и кусок СЛОВА своей строки («СТМЫ.» —
распознанный хвост «астмы.»), — тоже эхо: место доказано строкой.
**Ц8в.** Эхо за концом строки значит, что конец строки слоя оценён коротко:
в выгрузке строка продлевается до конца эха (`main._echo_extend_slot`), и её
закраска накрывает хвост оригинала. Без этого «варианта» в конце строки
«Заключения» оставалось русским, когда эхо перестало печататься поверх.

**Ц10в.** Абзац из одних чисел («0,51», «50 (64,9)» — ячейки таблицы) сегментом
не становится по правилу импорта, и на листе оставалась запятая посреди
английской таблицы. При переводе с языка с запятой на язык с точкой такой
абзац печатается с точкой (`main._numeric_para_texts`), без модели.

**Т36б.** Запись картинки, помеченная правилом групп 4 по ветке «склеивать
нечего», разреза по ключу легенды не получала никогда: разрез виден только по
пикселям, а решение «нужна ли перегруппировка» принималось по геометрии
(`_regroup_wants`). Теперь многострочный блок записи правила ниже 5 —
повод перегруппировать (`IMG_GROUP_RULE` 5); легенда «AA Легкая степень БА»
расходится на подпись оси и подпись серии.

**Ц14. Ключ легенды — первая слева краска, похожая на ключ** (`image_text.legend_key`,
`_key_from`, `IMG_GROUP_RULE` 6). Детектор начинает рамку строки на самом
квадрате ключа, и в зону поиска слева попадает буква соседней подписи оси
(«A» из «AA» перед «■ Среднетяжелая степень БА»); правило брало САМУЮ ЛЕВУЮ
краску — букву — и ключа не находило, вторая серия оставалась склеенной с
подписью оси. Теперь проверяются до трёх краск слева направо, ключ — первая,
которая сама сплошной квадрат.
**Ц14б.** Рамка строки детектора бывает начата на самом ключе, и закраска
стирала цветной квадрат серии; при печати перевод подписи встаёт правее ключа
(`main._legend_key_end` в `_pdf_image_boxes`).

**Не сделано и сказано.** Подпись оси, идущая снизу вверх («Евклидово
расстояние» на дендрограмме), не переводится — повёрнутую надпись картинки
выгрузка не печатает (`vertical`, см. правило в `_pdf_image_boxes`). Полужирные
метки-заголовки внутри абзаца («Цель.», «Материалы и методы.») печатаются
начертанием абзаца: перевод не знает, какие его слова соответствуют выделению
оригинала. Перевод фамилий в списке литературы и названий журналов — вопрос
перевода, не вёрстки.

## Ч. Приёмка готового файла и разбор очереди сверки (13 выгрузок, 22.10.2026)

Разбор очереди сверки: свежая выгрузка ТЕКУЩИМ кодом семи проектов (скан
1903 года с текстовым слоем RU→EN — 111, инфографика RU→UZ-CYRL/ZH —
118/112, проза RU→UZ-CYRL — 117, статья RU→UZ-CYRL/DE — 119/110, обзор
с инфографикой EN→RU — 14) и три критика-верстальщика по парам страниц:
около 200 дефектов. Прежние виды проекта 14 (A — куски слиплись, B — разный
кегль, D — перевод по кускам, F — знаки) всё ещё видны. Главное открытие —
не дефект печати, а дефект ПРОВЕРКИ: у скана 111 отчёт сборки сказал
«на языке оригинала осталось 0», а на листе стояли десятки русских строк.
Отчёт верит раскладке, которую сам построил, и не видит того, чего раскладка
не знает. Отсюда Ч5 — приёмка, которая смотрит на пиксели готового листа.
Страж раздела — `tests/test_export_qa.py`.

**Ч1. Слой распознавания у страницы-скана — обрывки видимых строк
→ страница картинкой** (`textcount.layer_fragment_pages`,
`pdftext.clean(force_images=)`, `importers.pdf_to_docx`, `RULES_VERSION` 20).
Симптом: скан «Золотого петушка» (дореформенная графика, декоративный шрифт)
выгружался так: верх страницы переведён, середина — русская, перевод разбит
на кусочки по 6–9 точек, у строк стёрты начала, а хвосты остались,
поверх — второй перевод тех же строк. Причина: строки слоя накрывали лишь
4–11% своих видимых строк (у цифровых PDF и CamScanner — 94–100%); печать
шла по слою, а надписи, прочитанные с той же картинки, печатались вторым
слоем. Правило: у страницы с картинкой во весь лист (`LAYER_SCAN_FIG`)
меряется, какую долю видимой строки (краска полосы строки слоя, тянущаяся
в обе стороны с пробелами не шире межсловного) накрывает строка слоя;
медиана ниже `LAYER_LINE_COVER` (0.5) — страница уходит картинкой целиком
(одним источником: текст читает зрячая модель). Цифровой PDF не рисуется
вовсе — проверка стоит только у страниц-сканов. Страница-скан ВОВСЕ без
слоя посреди PDF с текстом — тоже картинкой (у «петушка» это первая
страница: её текст есть только на картинке, и без этого правила она
оставалась оригиналом целиком; у книги-эталона 8 таких 3 из 378).
Пересборка и кнопка «пересобрать строки» принимают разбор без текстовых
строк, если страницы ушли картинками, и ставят их чтение сами.

**Ч1б. PDF, у которого ВСЕ страницы с текстом ушли картинками, —
по-прежнему «как в оригинале»** (`_store_source_docx` хранит раскладку
и без рамок слоя, `_export_pdf_layout` печатает надписи с картинок поверх
своих листов). Прежде такой проект молча откатывался на печать
Word-документа: рамок абзацев нет — «раскладки нет».

**Ч2. Свой дефис кода — не место переноса** (`layout_pdf._hyphen_cut_ok`).
Симптом: «COVID-» / «19-га» на двух строках заголовка инфографики (118).
Правило: составное слово рвётся по своему дефису, только если по обе
стороны — СЛОВА (не меньше трёх букв, без цифр, не сокращение капсом):
«COVID-19», «SARS-CoV-2», «IL-6», «ГПП-1» не рвутся;
«почечно-сердечно-сосудистых» рвётся, как рвалось.

**Ч3. Одно место — одна печать** (`main._drop_duplicate_extras`,
`export_qa.duplicates`, `stats.dupDropped`). Симптом: два перевода одной
строки друг на друге (скан 111, инфографика 14). Правило: надпись,
прочитанная с картинки страницы, чьи строки перекрывают строки абзаца слоя
больше чем на `EXPORT_QA_DUP` меньшей, не печатается; из двух надписей
с картинки про одно место остаётся более длинная. Сравниваются СТРОКИ мест
(места строк `slots`, строки надписи `lines`) долями листа, а не рамки
абзацев: рамка абзаца таблицы законно накрывает соседей. Пары «абзац —
абзац» разводит сама сборка (`_resolve_collisions`).

**Ч4. Слой сборки — наружу для проверки** (`layout_pdf.build(keep_overlay=)`,
`_overlay`, `_overlayOrder`). Где сборка печатала НА САМОМ ДЕЛЕ — это
непрозрачные точки её слоя до наложения на страницы (раздвижка по краске,
рост на свободную бумагу, перевёрстка уводят печать с входных рамок).
Вызывающий снимает оба ключа до показа отчёта.

**Ч5. Приёмка готового файла** (`backend/export_qa.py`, `main._export_qa_kick`,
`GET /api/projects/{pid}/export/qa`, отчёт `<файл>.qa.json` рядом с файлом).
Лист выгрузки против листа оригинала (у «ленты» — виртуальные страницы),
масштаб — от высоты текста страницы (строка не мельче `EXPORT_QA_TEXT_PX`),
потолок площади `EXPORT_QA_MAX_MPX`. Краска — отличие от ФОНА МЕСТА в любую
сторону (белые буквы на красной плашке — тоже краска). Коды:
UNTRANSLATED (текст слоя оригинала не изменился и это текст исходного языка;
найденный детектором строк в растре — `verify`, без чтения не уверены),
NOT_TRANSLATED (то же у места без перевода — непереведённое, не дефект
сборки), OVERPRINT (текст оригинала изменился, а своего места печати у него
нет), SPILL (печать на рисунке, линии, плашке вне своего места), SILENT
(у места перевод есть, сборка там не напечатала ничего), BLANK (место стёрто,
перевода на нём не видно), RESIDUE (строка стёрта наполовину), DUPLICATE,
SMALL (кегль перевода против оригинала по доле краски с поправкой на длину
текста ниже `EXPORT_QA_SMALL`), SIZE_MIX (место дальше медианы своего класса
кегля на `EXPORT_QA_MIX` — вид B разборов), PAGES. Word, Excel, PowerPoint,
текст и субтитры — по счётчикам самой выгрузки (MISSING: перевод есть,
а в файл не лёг). Почему ФОНОМ: рендер обоих файлов и детектор строк —
секунды на лист, книга — минуты; поток один на процесс, проверка — одна
за раз, потолок `EXPORT_QA_BG_TIME`; не успели — «проверено X из N»,
а не «всё хорошо». В STATE и в проект приёмка не пишет ничего: она
НАЗЫВАЕТ, исправляют правила (Ч1–Ч3 и следующие). Экран «Скачать» говорит
итог словами и ведёт к строкам («Показать строки»); событие
`dead.exportQa`; у первой выгрузки нового файла — сообщение владельцу.
Замер на семи проектах: у скана 111 — 26 мест «остался оригинал», 30 строк
стёрты наполовину, 12 пустых мест, 3 двойные печати (всё, что увидел
критик); у прозы 117 — 1 находка (пустая строка после абзаца), у статей —
2–3 находки, у инфографики 14 — кегль (самый частый вид критиков).

**Ч5б. Платный взгляд** (`export_qa.vision_*`, `main._export_qa_vision`,
`POST /api/admin/export-qa/{pid}`, шаг расхода `exportqa`). Правила не видят
начертания, выключки, перевода кусками и не уверены в растровых строках.
Зрячая модель (`_dm("ocr")`) получает пару «оригинал | выгрузка» с
пронумерованными отметками находок правил, подтверждает или снимает каждую
и называет то, чего правила не видят (коды FRAGMENT, FONT, ALIGN, MERGED…).
Сама — только у ПЕРВОЙ выгрузки нового файла (строка очереди сверки),
не больше `EXPORT_QA_VISION_PAGES` листов, `EXPORT_QA_VISION_USD` на файл
и `EXPORT_QA_VISION_DAY_USD` в сутки; повторно — кнопкой суперпользователя.
Платим МЫ: расход — на служебную организацию `_qa` (как `_support`), лимит
клиента не режется, сумм клиент не видит (22а). Подтверждённое моделью —
материал для правил в очереди сверки (`docs/rules/export-review.md`).

**Что видно и ещё не правило** (доказательства — в отчётах критиков
22.10.2026, следующие разборы):
- SIZE/B: кегль подбирается по месту, а однотипные места (ячейки строки,
  выноски, абзацы прозы) выходят разными — теперь это мерится (SIZE_MIX),
  выравнивание кегля по классу — следующий шаг;
- FONT: смешанные начертания и цвет ВНУТРИ абзаца (жирные вставки, синие
  заголовки, курсив генов) переводятся одним начертанием на абзац;
- ALIGN: у прозы 117 выключка по ширине и красная строка не везде
  воспроизводятся, абзац рвётся на короткие строки;
- MERGED/A: пункты при значках и ячейки, слитые разбором (проект 14);
- стихи и разрядка на скане (титул 111 после Ч1): широкие пробелы между
  словами детектор отдаёт отдельными рамками, повтор их краёв по строкам
  стиха `_join_pieces` принимает за край колонки, и блоки собираются
  «по столбцам слов» — перевод ложится кусками, часть строк остаётся.
  Приёмка это видит (DUPLICATE, RESIDUE, UNTRANSLATED), взгляд модели —
  «стих сведён в прозу»; правило — следующее (Ч6): строки стиха — строка
  в строку, без склейки в абзац прозы.

## Ш. Корпус выгрузки: 30 файлов разных форматов и вёрсток (23.10.2026)

Правила раздела Ч проверялись на файлах клиентов, а они однотипны. Корпус
(`tools/corpus_build.py`, рецепты в коде, только шрифты репозитория, семя
на файл) даёт по файлу на трудный случай: газета в три колонки с буквицей,
статья с рефератом в рамке и формулами, счёт с таблицей и печатью,
инфографика белым по цветным плашкам, стихи с разрядкой, буклет с повёрнутым
текстом, бланк, меню с отточиями, книжная проза с выключкой и красной
строкой, EN→ZH, RU→AR, Word с выделениями внутри абзаца, письмо UZ-CYRL,
Excel, PowerPoint, HTML, Markdown, субтитры, скриншот интерфейса, афиша —
и десять трудночитаемых: обгоревшее письмо от руки, записка на линованной
бумаге, рецепт врача с печатью, выцветший машинописный скан, ксерокопия,
мятый чек, старая газета с оборотом насквозь, табличка под углом, факс,
залитая водой страница. Прогон через боевой API — `tools/corpus_run.py`
(стадиями, с памятью, итог — выгрузки, приёмка, строки проекта).

**Ш1. Куски одной базовой линии — одна видимая строка**
(`pdftext._join_baseline_pieces`, `_baseline_piece`, `RULES_VERSION` 21).
Симптом: книжная страница с выключкой по ширине распалась на абзацы-
предложения («…над хребтом.» / «Тропа сначала…»), газета в три колонки —
на абзацы из одного-двух слов вперемешку между колонками. Причина:
генератор ставит каждое слово своим оператором показа текста (так пишут
выключку многие программы и слои распознавания), и pypdf отдаёт каждое
слово отдельной «строкой» — дальше склейка строк в абзацы работала по
словам. Правило: куски с той же базовой линией и кеглем, идущие в потоке
подряд, сводятся в строку, если зазор до `WORD_JOIN_FREE` кегля (межсловный)
либо до `WORD_JOIN_MAX` — и тогда по зазору ПИШУТ не меньше половины соседних
строк той же колонки в пределах `WORD_JOIN_LOOK` кеглей (межколонник
и промежуток между ячейками свидетелей не имеют). Кусок, начатый там же,
где куски `WORD_JOIN_COLSTART` соседних строк, — начало столбца или колонки,
не слово. Через вертикальную линию листа — никогда; части одной строки
pypdf (`split`) не сводятся. Проходы — до неподвижной точки: свидетели
второго прохода — уже склеенные строки. Средняя длина строки документа
после этого считается по видимым строкам. `PDF_WORD_JOIN=0` — выключить.

**Ш2. Конец строки, который поставила ширина колонки, — не конец абзаца**
(`pdftext._geo_breaks`, `join_lines(cont=)`). Симптом: абзац рвётся на
строке, которая случайно кончилась точкой, — примерно каждая десятая
строка прозы; в переводе — две строки с полуфразами и чужой кегль у каждой.
Причина: склейка решала «конец абзаца» по знаку на конце строки. Правило —
по геометрии: если первое слово следующей строки не влезло бы в остаток
этой (`край колонки − конец строки < ширина слова + пробел`), строку кончила
ширина — абзац продолжается, хоть строка и кончилась точкой; следующая
строка при этом не с отступом, не пункт со значком. Край колонки — самый
дальний конец строк своего БЛОКА (до пустой строки-разделителя) того же
кегля, если до него дотягиваются хотя бы две строки (`GEO_EDGE_TOL`);
только у строк с ТОЧНЫМ концом (метрики шрифта). Пункт «8. …» в начале
такой строки пунктом не считается.

**Ш3. Конец строки, который поставил автор, — конец абзаца, строки стиха
или пункта.** Тот же расчёт в обратную сторону: слово влезло бы
(`GEO_FREE_EXTRA` запаса), а строка всё равно кончилась — абзац кончился,
даже без точки. Так строки стиха («Туман над рекою, как лёгкая шаль,» /
«Укрыл берега до холмов,») и пункты больше не сводятся в прозу. Выключенные
по центру и вправо пары правило не трогает. **Ш3б**: у стихотворения на
странице нет края колонки (дальше всех одна строка) — тогда `VERSE_RUN`
и больше строк подряд, каждая с заглавной, с рваным правым краем
(`VERSE_RAGGED`) и левым краем в пределах отступа (`VERSE_INDENT`), — строки
стиха. Каждая строка стиха — своя строка проекта: перевод встаёт строка
в строку, соседи идут в промпт обстановкой.

**Ш4. Соседние строки разного кегля — разные надписи.** Симптом: описание
блюда мельче названия склеивалось с названием СЛЕДУЮЩЕГО блюда («с бараниной
и нутом Лагман»), имя в сертификате — с текстом под ним. Правило: кегль
отличается больше чем на `GEO_SIZE_BREAK` — новый абзац, если фраза не
перенесена и следующая строка не со строчной; от `GEO_SIZE_STRONG` раз —
новый абзац и перед строчной.

**Ш5. Отточие — разметка, а не текст** (`_LEADER_LINE_RE` в `_clean_line`).
Строка только из точек, многоточий, подчёркиваний и тире (меню, оглавление,
бланк) в перевод не идёт и на листе остаётся как была.

`PDF_GEO_BREAK=0` выключает Ш2–Ш4 без выката. Страж — `tests/test_corpus_rules.py`.

**Ш2а. Строка, кончившаяся концом фразы, — продолжение, только когда дошла
до края ВПЛОТНУЮ** (`GEO_FULL_TOL`). Край колонки считается по окну строк
и бывает чуть короче настоящего: почти полная последняя строка абзаца
иначе объявлялась «кончила ширина», и два абзаца сливались (замечание
критика). У выключки по ширине строка с точкой посреди абзаца доходит до
края ровно — там правило работает, как и было («…другой тонкий.» /
«Толстый только что…» у Чехова — один абзац).

**Ш3а. Строки в Title Case и КАПСОМ** (`_title_case`, `GEO_TITLE_SHARE`):
заглавная в начале следующей строки там ничего не говорит о конце абзаца,
разрыв — только по концу фразы. Без этого список авторов и заголовок
статьи на две строки рвались на абзацы («…the European» / «Association for
the Study of» / «Diabetes (EASD)»). То же ограничение — у стихов (Ш3б):
большинство строк в Title Case — это не стих.

**Ш3в. Красная строка** (`GEO_IND_MIN`–`GEO_IND_MAX` кегля). Новая строка
начинается с отступа от левого поля блока, а строка после неё снова у поля, —
это начало абзаца, даже если предыдущая строка дошла до края колонки.
Поле — самое левое начало строк того же кегля рядом, и у блока должен быть
РОВНЫЙ левый край (не меньше двух строк у поля), не выключка по центру:
подпись схемы, выровненная вправо, имеет рваный левый край, и он не отступ.
Строка с отступом заодно не бывает «продолжением по ширине». Симптом без
правила: реплика с красной строки сливалась с абзацем перед ней.

**Ш26. Надстрочник В НАЧАЛЕ строки не задаёт строке место**
(`pdftext._script_head_fix`). Строка pypdf «¹Diabetes Research…» несла
кегль и правый край самой цифры (3.7 при тексте 5.6, край сразу за «1»):
правило разницы кегля (Ш4) рвало аффилиацию посреди фразы. Место строки —
у её основной части (больше всего знаков), правый край — самый дальний,
конец строки — оценка.

**Сверка правил с эталонами.** Старый и новый разбор сравнены абзац
в абзац на боевых PDF (книга 8, статьи 14, 19, 105, Чехов 113, Пушкин 111):
каждое изменение проверено по странице глазами. Новый разбор сводит
то, что старый рвал по концу фразы у края колонки (Чехов, статья 105,
книга 8 — один абзац без красной строки), и разделяет строки стиха
(Пушкин); оставшееся расхождение — подпись инфографики в три строки
(«24-H PHYSICAL» / «BEHAVIORS…»), она сводится не всегда.

### Картинки, сканы и фото (Ш6–Ш25)

**Ш6. Картинка — это страница и для приёмки.** Выгрузка картинки и скана
проверяется по пикселям тем же `export_qa.inspect_pdf`: оригинал и
выгрузка — листами PDF, места надписей — рамками долями листа. Листы
оригинала собираются в потоке приёмки, а не в запросе выгрузки
(единственный воркер). Без этого «проверено» у картинок означало «счётчики
сошлись», а остатки оригинала под переводом не видел никто.

**Ш7. Строки чтения ложатся на строки картинки** (`image_text.read_lines`,
`split_parts`). Модель читает блок строками (промпт), строки сопоставляются
с рамками строк ПО ЧИСЛУ (разошлось — как прежде, пробелом). Разрыв абзаца
внутри блока: другой размер строки (`IMG_BREAK_SIZE`), три и больше строк
подряд с заглавной при РВАНОМ правом крае (пункты, поля бланка) и место
для следующего слова (как Ш3 у PDF). Конец фразы с заглавной следом без
проверки места разрывом НЕ считается: у немецкого существительные
с заглавной, и проза рвалась бы на пункты. Части блока печатаются каждая
в своих строках («Баланс» / «12 450,00 ₽» на экране приложения).

**Ш8. Печатный блок на рукописной странице — печатный** (`main._blk_fam`):
вид «рукопись» у страницы не делает рукописью шапку бланка рецепта.

**Ш9. Полужирный «по всей книге» у скана — не полужирный** (`pdftext._bold_from_scan`):
слой распознавания помечает жирным весь текст; основное начертание снимается,
если жирное стоит не на страницах-сканах большей частью.

**Ш10. Дорисованный полужирный — по кеглю** (`layout_pdf._synth_stroke`): обводка
долей кегля, у плотного письма (иероглифы) тоньше — иначе знаки слипались.

**Ш11. Две бесплатные находки перевода**: варианты через «/» без пробелов
(«brigades/teams», от четырёх букв с каждой стороны; «and/or» и «мг/кг»
законны) и пояснение в скобках сверх оригинала (`_paren_misses`:
«Chaikhana (Teahouse)»; скобки считаются и полноширинные, раскрытие
сокращения «tuberculosis (TB)» законно). Обе — в ремонте, в приёмке
ремонта и в сверках ревизии (`REVIEW_FREE_KEYS`), подписи вето — в таблице
сервера на всех языках.

**Ш12. Орфография языка перевода — данными** (`lang_rules.json` →
`normalize`, `main._lang_normalize`). Узбекское «oʻ/gʻ» модель пишет то
U+2018, то апострофом; правило языка приводит к одному знаку бесплатно.
Слово, стоящее в оригинале буква в букву (имя «O'Brien»), адрес и почта
не трогаются.

**Ш13. Линии таблицы под ячейкой сохраняются** (`layout_pdf._rules_in`,
`_stroke_rules`): закраска ячейки стирала линию сетки; линии меряются до
закраски и прорисовываются после. Край закраски и место для роста
ячейки останавливаются на линии (`_rule_cols`).

**Ш14. Разрядка оригинала повторяется** (`tc` у строки: Tc на листе,
`pdfpages_worker.op_end`): стих с разрядкой печатался сплошным текстом.

**Ш15. Бумага под повёрнутой строкой — полосами** (`_rot_strip_paper`):
один тон на всю повёрнутую строку буклета оставлял заплатку на градиенте.

**Ш16. Перевод пробега HTML — по его текстовым узлам**
(`importers._html_inline_write`): ссылки меню и выделения внутри абзаца
остаются на местах. Деление — тем же правилом, что у выделений Word
(`main._split_target`). Тег режет слово («Полн<b>ый</b>») или кусок вышел
пустым — пробег целиком текстом перевода, как прежде. Пробел на границе
узлов — по оригиналу; нет его у оригинала, а перевод на границе разделяет
слова, — пробел ставится. Язык документа — тег BCP 47 (`uz-Cyrl`, вариант
правописания тегом не бывает).

**Ш17. Частично читаемое — читается**: промпт чтения просит переписать все
различимые слова и отметить пропуск, а пустой ответ — только когда не
различимо ничего (обгоревшее письмо: блок из двух строк приходил пустым
и уходил в «шум»).

**Ш18. Испорченный снимок — третий взгляд по выровненному фону**
(`_uneven_background`, `_flattened`: яркость делится на фон, затем
местный контраст). Только складывается с прежним и только строками той
же высоты, что нашёл первый взгляд, увереннее порога; картинки больше
`IMG_FLAT_MAX_MPX` не выравниваются (память единственного воркера).
**Ш18б**: на шаг выше первой и ниже последней строки ровной колонки — тоже
место пропущенной строки.

**Ш19. Вид печати блока — один на все его части**: машинопись узнаётся по
шагу знака на двух и больше строках, и однострочная часть блока печаталась
рубленым шрифтом. Блок мерится один раз (без стирания), вид передаётся
частям, только когда он ДОКАЗАН; вес (полужирный) у каждой части свой.
**Ш19б**: на странице, где блоки с доказательством большей частью
машинописные, однострочные без своего вида — машинописью (чек).

**Ш20/Ш22. LaMa видит дыру ЗАКРЫТОЙ** (`paint_lama.inpaint`). Главная
находка корпуса: сборка ONNX маску на изображение не накладывает, и сеть
видела буквы внутри дыры, а при дополнении вырезки до 512×512 отражением —
ещё и в зеркальной копии, — и рисовала их обратно, перевёрнутыми.
Симптом: «двойник» оригинала под переводом на обгоревшем письме, чеке,
залитой странице при отчёте «стёрто». Теперь дыра подаётся как при
обучении (img·(1−mask)), маска отражается вместе с картинкой. Дыра для
LaMa шире маски букв на ширину размытия (`LAMA_GROW`).

**Ш21. Пропущенная строка колонки на испорченном снимке**
(`image_text.gap_slots`, `_gap_confirm`). Колонка — по перекрытию с
половиной короткой строки, к ближайшей сверху цепочке, от пяти строк;
место, накрывающее большую часть найденной строки, занято. На неровном
фоне место подтверждает ДЕТЕКТОР по вырезке из выровненной картинки, а не
мера краски: у прожжённой дыры «краска» тянется за место строки, и правило
«рисунок, не строка» отвергало настоящую строку письма. Мест на картинку —
не больше `IMG_GAP_MAX_SLOTS`.

**Ш23. Наклон страницы** (`angle_hint` у `text_paint.measure`). Снимок под
углом наклоняет все строки одинаково, но мерится наклон только у
вытянутой маски: короткие «ИТОГО», «Сдача» выходили прямыми. Наклоны,
согласные между собой у большинства однострочных, — наклон страницы,
и строке без своего замера даётся он.

**Ш24. LaMa — с полем вокруг вырезки** (`text_paint._lama_ctx`,
`LAMA_CTX` строки): вырезка надписи почти целиком дыра, и модель заливала
её ровным светлым тоном (прямоугольник под шапкой чека на тени снимка).
Поле узкое: шире — модель переносит в дыру соседние строки.

**Ш25. Красная строка, разрыв по Title Case, надстрочник** — см. Ш3а, Ш3в,
Ш26 выше: правила PDF, найденные сверкой с эталонами после корпуса.

**Ш27. Дуга — у всей надписи** (`text_paint._arc_of`, `ARC_COVER`,
`ARC_MIN_R_LETTERS`): ячейка ксерокопии «Лим В. О.» дала «дугу» радиусом
13 точек по трём буквам, и перевод лёг кружком. Буквы дуги покрывают
большую часть надписи, радиус — не меньше полутора букв.

**Ш28. Один кегль у однородных строк** (`image_text._single_even`): части
одного блока — кеглем соседних частей, если замер ушёл больше чем на треть
(строку пересекает линия листа); однострочные надписи с кеглем в пределах
20 % — один класс (ячейки таблицы, пункты меню), кегль класса — медиана.

**Ш29. Меню скриншота — документ** (`main._overlay_column_fix`, промпт
чтения): «надпечатка» в одной колонке с переводимыми строками той же
высоты — текст документа; в промпте меню, кнопки и подписи скриншота,
бланка, страницы прямо названы документом.

**Ш30. Правила перевода из критика корпуса**: имена, названия в кавычках
и монограммы — транслитерацией; валюта и единицы оригинала не подменяются
местными; число строк — как у оригинала (промпт, правила 12–14).
**Ш30б**: бесплатная находка «строк перевода не столько, сколько
в оригинале» (`_lines_misses`) — в ремонте, приёмке и ревизии.

**Ш31. Рамки одной видимой строки — одна** (`image_text.row_boxes`): кусок
перекошенной строки («P.01» факса) детектор отдаёт отдельной рамкой, рамок
становилось больше строк чтения, и разбивка отключалась. Место строки на
краю колонки (Ш18б) — только если краска стоит на высоту буквы: пунктир
внизу факса строкой больше не считается (`IMG_GAP_ROWS`).

**Ш32. Запасная «плашка» — видом печати и кеглем блока**: строка, у которой
замер не вышел, печаталась рубленым шрифтом кеглем по испорченной рамке.

**Ш33. На испорченном снимке рамка строки продлевается по краске её цвета**
(`_extend_by_ink`): детектор обрывает строку у пятна. Окно, залитое краской
сплошь, — пятно или прожог, продление стоп; не дальше половины исходной
ширины и не в чужую рамку.

**Стенд «через Claude»** (`tools/corpus_claude_images.py`): когда ключ
поставщика недоступен, весь конвейер картинок идёт по-настоящему, а ответ
зрячей модели и перевод пишет Claude файлами (вырезки блоков → `read.json`
→ сегменты → `tr.json` → выгрузка). Так пройдены пять трудных картинок,
не прочитанных из-за лимита Anthropic.

Корпус — это ещё и стенд самообучения: `tools/corpus_build.py` (рецепты),
`tools/corpus_run.py` (прогон через API стадиями), `tools/corpus_offline.py`
(перевёрстка без модели, псевдоперевод), сравнение разбора с эталонами.
Новая находка — правило здесь, код, тест (`tests/test_corpus_rules.py`,
`tests/test_corpus_image_rules.py`).

### Матрица языков СНГ и мира (23.10.2026)

Те же рецепты на 28 парах: RU→EN/DE/ZH/KK/KY/TG/AZ/UK/TR/UZ-CYRL/AR/KO/FR,
EN→RU/UZ, DE→RU/EN, ZH→RU/EN (`corpus_build.py --langs`, рецепты

**Ш34. Строка другого цвета — разрыв надписи** (`image_text.line_inks`,
ветка цвета в `read_lines`, `IMG_BREAK_INK`): красная строка «ОСТОРОЖНО»
над чёрной подписью таблички склеивалась с ней в одну фразу, и перевод
выходил одним цветом. Цвет — медиана самых далёких от фона точек рамки
строки.

**Ш35. Линия ячейки — не свободная бумага; иероглифы — не моноширинный**:
`_free_rows` не берёт ряды за горизонтальной линией (`_hline_in`,
`IMG_HLINE_SHARE`) — подпись ячейки уходила второй строкой в соседнюю
ячейку. Текст, где от 30% иероглифов (`_cjk_share`), не проходит замер
«моно» и «засечки» по пикселям: равная ширина иероглифов читалась как
машинопись.

**Ш36. Название, код и знак валюты оригинала — неприкосновенны**
(`main._ident_misses`, бесплатная находка `ident`): латинское название
в тексте на другом письме («BANK·ONE» → «БАНК·УАН»), код модели («T200»),
знак валюты («420 ₽» → «420 сом», «420 卢布»). Двойник буквы другого письма
в коде («Т200» с кириллической Т) чинится без модели (`_homoglyph_fix`
в выходе перевода). Промпт: названия и коды латиницей — как написаны, знак
валюты — знаком, числа — по правилам языка перевода с теми же цифрами.
**Ш36б**: ремонт не вправе ВНЕСТИ вариант через «/», пояснение в скобках
или слить строки — правка с ростом `variants`/`addon`/`lines` откатывается
(ремонт подставил совет проверки «Параметрлер/Баптаулар», и правку приняли).

**Ш37. Вторая строка — за счёт плашки НАД строкой** (`_free_above`,
`FREE_ABOVE`, `LAYOUT_FREE_ABOVE=0` — выключить): предупреждение в жёлтой
плашке, кнопка, ячейка шапки — над одиночной строкой пусто до края плашки,
и перевод встаёт двумя строками, поднявшись ровно настолько, насколько
не хватает места под строкой. Край плашки обязан найтись (смена тона
`PLATE_EDGE_DIFF` на `PLATE_EDGE_SHARE` ширины) — поле страницы над
заголовком не занимаем.

**Ш38. Поле бланка «______» — часть текста** (`pdftext._clean_line`,
`PDF_UNDERSCORE_KEEP`, `RULES_VERSION` 22): ряд подчёркиваний внутри
строки и в её конце («Подпись ______») идёт в перевод одной длиной «______»,
и черта на краю строки рамкой не считается. Потерянное поле — находка
`ident`.

**Ш39. Пункт колонки не растёт влево** (`_mark_column_edges`, `COL_EDGE_MIN`):
строка, чей левый край совпадает с краем ещё двух строк страницы, — колонка
(меню, список); пункт меню с отточием рос в поле слева и выезжал из колонки.
Связное письмо (вязь, индийские, монгольское — `_connected_script`)
не получает разрядки Ш14: разрядка рвёт связь букв.

**Ш40. Отточие меню и оглавления — стирается и рисуется заново**
(`pdftext._leader_places` → `layout["leaders"]`, `_attach_leaders`,
`_draw_leader`, `LAYOUT_LEADERS=0` — выключить): строка «Плов ........ 420 ₽»
получает место отточия, растёт поверх него (до `2` кеглей от его конца),
а отточие печатается от конца перевода тем же шагом точек и обычным
начертанием. Конец отточия — перед следующей надписью строки (ценой):
конец строки в слое — оценка. И у строки, напечатанной контурами
(иероглифы). Приёмка отточие своей «перепечаткой» не считает.

**Ш41. Строка с отточием или с ценой справа — РЯД, не история**
(`_row_anchor` в `_story_link`, `ROW_TAIL_MAX`): заголовок «Напитки», пункт
«Зелёный чай» и подпись «чайник 0,7 л» сцеплялись в одну историю и
ужимались общим кеглем до 0.36.

**Ш42. Синтетический курсив — курсив** (`pdfpages_worker`, `SLANT_MIN`/
`SLANT_MAX`): «вертикаль» буквы наклонена вправо на 6–30° (`Tm 1 0 0.2 1`)
— у строки стиль «i»; перевод подписи под блюдом выходил прямым.

**Ш43. Мера кегля в приёмке — в «узких знаках»** (`export_qa._vlen`):
полноширинный знак весит два; китайское меню при том же кегле
мерилось «крупнее» в 1.7 раза (SIZE_MIX 9 на ровной странице).

**Ш44. Сосед за линией таблицы — другая ячейка** (`_free_room`): граница
ячейки — линия с отступом в полкегля, а не середина зазора до текста
соседней колонки и не два кегля от него; `lim2` (колонка в строках рядом)
в таблице с линиями не действует — «соседом» там бывает число строкой ниже
в той же ячейке. «Ед.» → «қапт.», «Цена» → «Бағасы» ужимались до 0.44–0.78.
Сторожат `tests/test_corpus_lang_rules.py` (Ш34–Ш39) и
`tests/test_corpus_layout_rules.py` (Ш40–Ш44, сквозная выгрузка с
настоящими переводами `tests/fixtures/corpus_real_translations.json`).

### Повреждения рядом с переводом (23.10.2026, разбор снимков владельца)

**Ш45. Заплатка не трогает линии, печать и фон за краем.** В PDF
(`_fill_box`): линейка таблицы в поле заплатки (под строкой, над ней)
и вертикаль ячейки сбоку не закрашиваются — заплатка кончается перед ними,
и такие линии штрихом не возвращаются (`_rulesLeft`): возврат на краю
выходил бледным, светлые разрывы под каждой переведённой ячейкой. Конец
строки, раздвинутый по краске за вертикаль ячейки, — перед ней («500.00|»).
Линия — тонкая и на бумаге (`_thin_outside`): промежуток между белыми
буквами на тёмной полосе заголовка — тоже тёмный столбец во всю высоту,
но рядом с ним снаружи такая же полоса (17 «вертикалей» обрезали
арабский заголовок). Окно поиска линии — на 2 точки шире заплатки:
линия, задетая только краем, раньше не находилась. У картинок
(`image_text._restore_structures`, `IMG_RESTORE=0` — выключить): после
стирания и плашек, ДО печати перевода, из оригинала возвращается то, что
изменилось, лежит вне строк текста, не похоже цветом на заплатку и
продолжается за край области — рамка листа, кольцо печати, фон за краем
таблички; прямая длиннее строки — и внутри строк (детектор берёт черту
рамки в рамку строки). Точки и хвосты букв целиком внутри — не
возвращаются.

**Ш46. Точки над прописной стираются** (`_marks_above`, `LAYOUT_MARKS_ABOVE=0`):
рамка строки — 0.85 кегля, точки «Ё/Й/Ä» выше, а поле закраски сверху
0.05 кегля и прижато Т28 к «чужой краске» — к этим же точкам. Мелкая
краска в полосе 0.32 кегля над рамкой, над которой 0.2 кегля чисто, —
знаки строки: верх заплатки поднимается до них («¨» над «2026 ж.»).

**Ш47. Одиночная строка, прижатая вправо, растёт влево**
(`_mark_right_edges`, `LAYOUT_RIGHT_EDGE=0`): правый край совпадает
с правым краем другой строки страницы (числа столбца), левый — ни с чьим,
строка в правой половине — «вправо»; свободная бумага (`_span_x`) держит
правый край, а не центр. «Төлеуге барлығы: … руб.» выходило за край
таблицы, подпись справа — за поле.

**Ш48. Перевод справа налево — от правого края, общего у абзаца**
(`LAYOUT_RTL_MIRROR=0`): абзац, выключенный влево в оригинале, на арабском
выключается вправо по самому правому концу его строк — по концу каждой
строки выходил рваный край.

**Ш49. Подпись поля бланка — ряд** (`_field_rule`, `LAYOUT_FIELD_RULE=0`):
справа на базовой линии черта от 6 кеглей — строка не сцепляется в историю
с соседями. Подписи пропуска сцеплялись, первая переносилась, и все
уезжали на строку ниже своих черт.

**Ш50. Буквица** (`pdftext._dropcap_join` → `dropcap` у рамки;
без слоя — `["ink"]` и место по отступу первых строк, `_dropcap_place`;
`LAYOUT_DROPCAPS=0`): место буквицы стирается, там печатается первая буква
перевода тем же кеглем и цветом, из текста она уходит, строки рядом
начинаются правее неё (`_dcZone` в `_regrid` и истории). Раньше «П»
оставалась поверх английского «already».

**Ш51. Сокращение с точкой остаётся коротким** (правило 7 промпта
перевода): «Ед. изм.: усл.» модель разворачивала в «Unit of measurement:
conventional units» (живая проверка на проде 23.10.2026), и в узкой ячейке
это ужималось кеглем. Правила Ш36/Ш38 (знак валюты, код, латинское
название, поле бланка) той же живой проверкой подтверждены на RU→KY/ZH/UZ/KK
и DE→RU.

## Ы. Петля «проверил — переверстал» (23.10.2026)

Сборка — одна раскладка по правилам; приёмка (`export_qa`) видела, что
вышло, но только сообщала. Теперь `main._layout_loop`: собрал → приёмка по
пикселям → у места с находкой правка → собрал снова → взял лучшее.

**Ш52. Линии ячейки на тёмной плашке не ищутся** (`_rules_in`,
`RULE_DARK_BG` 0.45). Симптом: на синих плашках инфографики (CDC, проект
112) из-под китайского перевода видны русские хвосты строк («НИКАКОГО»,
«заразить»). Причина: в окне заплатки «бумагой» вышли белые буквы, тёмной —
плашка, и просветы плашки между белыми штрихами читались вертикалями
ячейки; Ш45б обрезал по ним конец строки (401 → 340 pt), закраска не
доходила до конца русской строки. Правило: «тёмного» в окне больше доли

**Ы5. Предпечатная проверка сильной моделью — до выдачи** (`backend/prepress.py`,
задача `prepress`; решение владельца 23.10.2026: у выгрузки одна попытка).
Сильная модель (Claude, при недоступности OpenAI; платит сервис — служебная
организация, лимит клиента не тратится, расход не идёт в себестоимость
файла) смотрит КАЖДУЮ страницу: пара «оригинал | перевод» нарезается
плитками ≤ 760×720 на половину (Claude сам уменьшает картинки длиннее
~1568 точек, и точки над «Ё» и тонкая линия пропали бы), мельчайшая строка —
не меньше 16 точек, все плитки страницы — одним вызовом. Ответ — код
дефекта, место и действие из закрытого списка, уверенность; «прочее»
с понятным описанием получает свой код. Ответ о странице берётся из памяти
(`{pid}.prepress.json`) ТОЛЬКО при совпадении текстов страницы, мест строк
(`_placed` сборки), картинки и версий (модель, вопрос, pdfium) — причина
повторного взгляда записывается. Запуск: сам после прогона, давшего полный
перевод (задача низкого приоритета: свой диапазон билетов, уступает любой
обычной задаче, паркуется на выкате), и кнопкой суперпользователя
(`POST /api/admin/prepress/{pid}`). Этапы: 1 — «смотреть» (`PREPRESS=observe`,
файл не меняется, владельцу сводка), 2 — «чинить» и выдавать только
проверенное (`PREPRESS=fix`, с 23.10.2026 у всех организаций), 3 — выученные
правила данными и короткий перевод только в файл.
Этап 2: действия модели по местам становятся рычагами сборки (шире, теснее,
отдельно, стереть шире, не задеть линию, строки как в оригинале, уже
начертание не ниже 0.78, выключка, по ширине — от трёх строк, гарнитура —
только у латиницы и кириллицы; взаимоисключающие — первая), сборка
повторяется, изменившиеся страницы смотрятся вторым взглядом (тот же
растр — ответ из памяти, бесплатно), новая сборка берётся, только если
вес дефектов строго меньше, находок по пикселям не больше и новых видов
нет. Любой выход задачи оставляет кэш (`{pid}.prepress.pdf` + `meta`):
проверенный, «частично» или «не удалось» — иначе выгрузка ставила бы
проверку по кругу (и страховка: три задачи без итога на один вход —
сборка без проверки). Человеку список «посмотрите страницы» — только
видимый брак (`USER_CODES`), гарнитура и кегль — сводка владельцу.
Замер на проде 23.10.2026 (4 одностраничных файла корпуса): $0.02–0.03
и 7–9 с на страницу; модель там отмечала в основном косметику (рубленый
шрифт, который уже рубленый), и рычаги честно не изменили страницу.
Этап 3 (23.10.2026) — остаток закрывает сама система, а не человек:

   вида дефекта (`LADDER`: переполнение — теснее → уже → шире → короче;
   наложение — теснее → отдельно → уже → короче; …); испробованное на месте
   не повторяется, взаимоисключающее заменяет прежнее. Круг берётся только
   строго лучшим; неизменившиеся страницы — из памяти, бесплатно;

   отрицания не меньше, объективные находки, утверждённые термины и письмо
   языка не хуже. Не трогается текст человека (`_human_text`) и текст

**Э1. Подпись поля и значение — два места** (`pdftext._field_pair`,
`PDF_FIELD_SPLIT`). Симптом: в бланке анализов «Пациент:» (полужирным)
и «Сорокина Елена Викторовна» (прямым) склеились в одну строку — значение
печаталось начертанием подписи, а закраска общей рамки стирала линию поля
под ним (RULE_CUT ×7). Причина: Ш1 сводит куски одной базовой линии по
свидетелям соседних строк, а в бланке свидетели — такие же поля. Правило:
кусок, кончающийся двоеточием (не длиннее 60 знаков), и следующий кусок
ДРУГОГО начертания за просветом шире межсловного не сводятся. Обычный пробел
(«Примечание: текст» в прозе) правило не трогает.

**Э2. Обтекание фигуры — ширина строки по профилю оригинала**
(`layout_pdf._shape_profile`, `_shape_at`, `LAYOUT_SHAPE_WRAP`). Симптом:
журнальная полоса — перевод колонки, обтекающей круглое фото и врезку
с цитатой, верстался историей на всю ширину колонки: строки ложились на
врезку, её заливка стиралась. Правило: у каждой новой строки истории ищется
строка оригинала той же колонки на той же высоте (в пределах полшага);
её левый край, отодвинутый больше чем на `SHAPE_EDGE` кегля (с учётом своего
отступа), и правый, не дотянувший до края колонки (не последняя строка
абзаца, а колонка выключена по формату — соседние строки кончаются на одном
крае), становятся пределами новой строки. Только у абзацев «влево/по
формату». Ниже последней строки оригинала профиля нет — ширина колонки.
**Э2б** (`_slot_align`): абзац, у которого все строки, кроме последней,
одной меры (общий левый и правый край), — набор по формату, а не «по центру»:
последнюю строку сдвинула фигура.

**Э3. Заливка под кривой обрезкой накрывает только внутри неё**
(`pdfpages_worker._mark_covered`, `state["cclip"]`, `PDF_CURVE_SOFT`).
Симптом: слова «в молочной», «Весной» у края круглого фото пропадали из
строк (место без строки) и выходили отдельными абзацами-обрывками. Причина:
фото — заливки под круглой обрезкой, а «накрыто ли слово» решала рамка
заливки (квадрат вокруг круга). Правило: кривая обрезка запоминается
областью (многоугольник пути, стек q/Q); слово, попавшее только в рамку,
но не в область, открывается, если на его базовой линии рядом стоит
открытое слово (строка обтекает фото). Целиком «накрытые» строки (подписи-
дуги под панелью схемы — причина, по которой Т19 выключено) не трогаются.

**Э4. Красная строка правее начала ПРЕДЫДУЩЕЙ строки** (`pdftext._geo_breaks`).
Строка, начатая левее предыдущей, — край обтекания, а не отступ абзаца.

**Э5. Слово прозы — не начало столбца** (`pdftext._prose_word`). Симптом:
«…высматривая добычу.» / «Дети целыми днями…» — абзац журнала рвался посреди
фразы. Причина: набор по формату рисует каждое слово отдельно, и последние
слова нескольких строк случайно начинаются на одной высоте («изго-», «сено:»,
«кры-») — счёт Ш1 видел «столбец таблицы». Правило: кусок, перед которым на
его строке стоит слово через обычный пробел (до 1.2 кегля), в счёт начал
столбца не идёт; у столбца таблицы перед ним широкий просвет.

**Э6. Контраст перевода — по самой тёмной краске** (`export_qa`,
LOW_CONTRAST). Симптом: 7 ложных «бледных» ячеек в расписании 6 пт: мелкий
сжатый шрифт при разрешении приёмки — серые края штрихов, и медиана краски
выходила ниже порога. Правило: 90-й процентиль отличия краски от фона;
у настоящего «белого на светлом» бледна и самая тёмная краска.

**Э7. Повёрнутая строка в приёмке — место по пути** (`export_qa._rect_px`).
Симптом: OVERPRINT ×4 на повёрнутой шапке расписания (и ×1 у буклета 06
старого корпуса). Причина: у повёрнутой строки рамка без ширины
(x0 == x1), и её место не входило в «свои места». Правило: рамка — путь
строки (`pts` → `end`) с запасом в кегль.

**Э8. Номер пункта слева — якорь истории** (`layout_pdf._num_anchor`).
Симптом: в договоре «3.3.» оставался на месте, а текст пункта уезжал историей
на строку выше (BLANK у номера). Правило: слева от первой строки куска на
той же базовой линии короткая (до `NUM_ANCHOR_W` кеглей) отдельная надпись
не дальше `NUM_ANCHOR_GAP` кеглей — номер; кусок не сцепляется с предыдущим.

**Э9. Повтор слова после конца фразы — не двойник надписи**
(`pdftext._twin_piece`). Симптом: «…(далее — «Заявка»). Заявка считается…»
рвалось на два абзаца: «Заявка» после «Заявка»).» принималось за надпись,
распознанную дважды. Правило: двойник не кончается точкой и закрывающей
кавычкой.

**Э10. Межсловный пробел соседней строки — тоже свидетель**
(`pdftext._baseline_piece`, `PDF_WORD_GAP_WITNESS`). Симптом: в договоре,
набранном по формату словами-кусками, «…(четыреста двадцать)» / «рублей за
одну…» — абзац рвался посреди строки: у соседних строк в этом месте тоже
пробел между словами, и свидетелей «пишут по зазору» не набиралось половины.
Правило: соседняя строка свидетельствует и тогда, когда слева и справа от
середины зазора её слова стоят ближе `WORD_GAP_WITNESS` кегля (межколонник
шире).

**Э11. Плашка места — тоже своё место** (`export_qa._own_plates`,
`EXPORT_QA_PLATE_OWN`). Симптом: SPILL у перевода, выросшего на вторую
строку внутри своего блока схемы или тёмной панели буклета. Правило:
связная область цвета фона места в оригинале (заливка от края рамки, дыры
от букв затянуты) — своя; больше `QA_PLATE_MAX` листа — фон страницы.
Значок или рисунок НА плашке своим не становится.

**Э12. Слабая строка, которую выдаёт геометрия абзаца** (`image_text._first_or_centered`,
`IMG_RESCUE_FIRST`). Симптом: письмо с печатью — первые строки трёх абзацев
и строка «администрации города…» между заголовком и адресом остались
по-русски. Причина: распознавалка движка кириллицы не знает (уверенность
0.13–0.2), а спасение по столбцу (`_column_rescue`) требует общего края —
у первой строки красная строка, у строки шапки по центру края нет вовсе.
Правило: строка вплотную НАД строкой той же высоты, начатая правее неё на
0.5–6 высот, не уже 0.6 её ширины, под которой колонка, — первая строка
абзаца; строка с той же серединой, что у соседей сверху и снизу (высота
0.5–2 раза), не короче трёх высот, — строка шапки.

**Э13. Печать и подпись не перерисовываются** (`main._image_read_system`).
Симптом: текст круглой печати «ДЛЯ ДОКУМЕНТОВ» и кусок кольца переведены
и напечатаны поверх печати. Правило: промпт чтения называет текст печати
(кольцо и середина) и подпись надпечаткой (`overlay: true`) — оригинал
остаётся. Действует на новые чтения (кэш по отпечатку картинки).

**Э14. Наклонная строка — четырёхугольник детектора, а не рамка**
(`image_text._detect_boxes` → `quad`/`ang`, `_quad_inter`, `_dedupe_boxes`,
`_join_pieces`, `group_blocks`, `_paint_measure`; `IMG_ROT_LINES`,
`IMG_ROT_MIN`). Симптом: визитки на столе под углом 8–11° — из 14 строк
вышло 3 блока-склейки, перевод напечатан прямо, соседние строки стёрты;
диаграмма с подписями оси под 45° — две подписи склеены в одну рамку,
а стирание по рамке снесло столбики. Причина: прямоугольник наклонной
строки накрывает соседние строки почти целиком — по нему они «дубли»
и «одна строка». Правило: у строки с углом от `IMG_ROT_MIN` до
90−`IMG_ROT_MIN` градусов хранится четырёхугольник; дубли — по пересечению
четырёхугольников, куски такой строки не клеятся, строка — свой блок (высота
строки — толщина четырёхугольника), замер и стирание — только внутри
четырёхугольника (с запасом), угол печати — по маске букв внутри него.

**Э15. Сноски Word — в разборе** (`main._docx_flat_parts`, `_docx_note_parts`).
Симптом: текст сноски остался на языке оригинала (MISSING у приёмки).
Причина: python-docx части сносок не знает и держит байтами. Правило:
части `footnotes`/`endnotes` регистрируются как XML-части, их абзацы идут
ПОСЛЕ колонтитулов (служебные разделители — нет); карты, записанные раньше
(без сносок), принимаются по счёту абзацев без сносок.

**Э16. Направление письма — по языку перевода** (`main._docx_flip_direction`).
Симптом: письмо AR→RU — русский текст справа налево (точка в начале
строки), столбцы таблицы в обратном порядке. Правило: если направление
оригинала и перевода разное, во всех частях с текстом снимаются (или
ставятся) `w:bidi` абзацев и разделов, `w:rtl` прогонов и `w:bidiVisual`
таблиц, выравнивание вправо/влево зеркалится. Счёт — `stats.dirFlipped`.

**Э17. Цифры арабского письма — обычными у языка не арабским письмом**
(`main._lang_normalize`). Номер «٤٨٧/٢٠٢٦» из арабского оригинала
печатается «487/2026» в русском переводе; у арабского и персидского
перевода цифры как есть.

**Э18. Диаграммы PowerPoint — в переводе** (`importers.pptx_slots`,
`_pptx_write`, `SLOT_RULE` 3). Симптом: на переведённом слайде встроенная
диаграмма — заголовок, подпись оси, категории — осталась по-португальски.
Правило: за абзацами слайдов идут абзацы частей `ppt/charts/chartN.xml`
(заголовки, подписи осей) и строки кэша рядов и категорий (`c:strCache`);
обратная запись — по номеру. Проекты, залитые до правила, узнаются по
отпечатку и выгружаются прежним правилом 2. Встроенная таблица данных
диаграммы не правится (названо).

**Э19. Подчёркивания поля в тексте — не линия таблицы** (`export_qa`,
RULE_CUT). Симптом: 4 «разрыва линии» у подписей договора и 2 у бланка —
это ряды «___» внутри текста («Дата «___» ______ 20__ г.»), а перевод
несёт свои поля (Ш38) своей длины. Правило: пиксели линий внутри рамки
текстового куска оригинала с «___» из проверки разрыва линий исключаются.

**Э20. Лист снят под углом — блоки по выпрямленным строкам** (`image_text`:
`_page_skew`, `_deskew_box`, `_same_light`, `group_blocks`, `_finish_lines`,
`divider_between(ang=)`). Симптом (корпус 2, «объявление в тени»): первая
строка абзаца прилипла к заголовку, шапка таблицы и строки «14/15 октября» —
к абзацу; модель прочла в блоке только абзац, а стёрт был весь блок — строки
таблицы пропали без перевода, абзац встал по центру раздутой рамки поверх
таблицы. Причина: рамка детектора ось-параллельная, у строки шириной 700 px
при наклоне 3° она на 37 px выше самой строки, а допуски сборки считаются от
высоты рамки; у снимка в перспективе угол у каждой строки свой (−3° вверху,
+2° внизу). Правило: детектор хранит четырёхугольник каждой строки (`q4`,
у склеенной — всех кусков, `q4s`); если медиана модуля угла длинных строк
(ширина от четырёх толщин) не меньше `IMG_SKEW_MIN` (1°), каждая строка
выпрямляется вокруг своего центра (проекция точек на ось строки — изогнутая
строка разворота не прямоугольник), блоки собираются по выпрямленным рамкам
с узким допуском кегля (0.72–1.38: толщина теперь точна, заголовок 41 px
и подзаголовок 28 px — разные блоки), фон под тенью считается тем же, если
каналы соседней строки потемнели пропорционально (оттенок тот же, яркость
в пределах 0.7–1.43 — тёмная серая шапка таблицы и светлое поле так не
сливаются), линия таблицы ищется
вдоль наклона окном из трёх строк пикселей (самый тёмный по столбцу, опора —
то же окно у строк рядом; только для пар строк с измеренным углом). Наружу —
исходные рамки блока и строк (`lineBoxes` — по ним стирают, режут кроп
и меряют буквы), выпрямленные строки — отдельным полем `lineBoxesR`, только
для баз и шага раскладки абзаца (элемент выгрузки несёт его, часть
разрезанного блока — нет). Склеенная из кусков строка выпрямляется в одной
системе координат; наклонные надписи Э14 не выпрямляются. Замер на 21 снимке корпусов: изменились
3 — объявление исправлено, рецепт и разворот не хуже (у рукописи волна
строк тоже включает режим — названо), остальные побайтно прежние.
`IMG_DESKEW=0` выключает.

**Э21. Буквы в глубокой тени — порог краски от яркости бумаги**
(`text_paint.measure`, `INK_REL*`). Симптом: абзацы в тени ушли плашкой —
тёмным прямоугольником поверх снимка (покрытие маски 0.001 при бумаге 65).
Причина: тень умножает яркость и бумаги, и краски, разница между ними
сжимается ниже постоянного порога 48. Правило: на нейтральной бумаге темнее
`INK_REL_REF` (190) порог снижается пропорционально её яркости, не ниже
`INK_REL_MIN` (0.35) прежнего и не ниже утроенной медианы отличия (шум ночного
снимка — не буквы); текстура фона меряется по прежнему порогу, иначе шум
выпадал бы из замера. Светлая бумага и цветная плашка — как были.

## Ю. Фото без грубого брака с первой выгрузки (корпус 2, 24.10.2026)

ТЗ — `docs/plans/photo-first-export.md`. Мера — фото-бенч `tools/photo_bench.py`:
21 снимок корпуса с ЗАМОРОЖЕННЫМИ чтением и переводом
(`tests/fixtures/photo_bench/`), настоящий разбор, выгрузка и приёмка по
пикселям, база `tests/fixtures/photo_bench_baseline.json`. Закон раздела:
хуже, чем оригинал в своём месте, файл не отдаётся — порядок предпочтений
«перевод на месте → плашка в своей рамке → оригинал нетронутым → подпись».

**Ю1. Перевод равен оригиналу — надпись не трогаем** (`main._export_images`,
`IMG_SAME_KEEP`). Симптом (визитка 66): e-mail «i.samoylov@…» стёрт,
перепечатан и лёг поверх телефона и адреса; приёмка насчитала шесть
двойников. Причина: блок, чей перевод буква в букву равен оригиналу
(e-mail, телефон, латинское название), проходил обычной дорогой —
стирание и печать по замеру, а у наклонного снимка печать встаёт мимо
места. Правило: такой блок (сравнение `_same_as_source`: NFKC, пробелы)
не стирается и не печатается — остаётся как на снимке, счётчик `img_same`.
Приёмка его непереведённым не считает: слова оригинала есть в переводе.
`IMG_SAME_KEEP=0` возвращает прежнее. Приёмка (`export_qa`) получает такое
место с пометкой `keep`: строки объяснены, «не напечатано» не ищется. Тест —
`tests/test_image_scan.py`.

**Ю2. Движок строк бенча — версии сервера** (`tools/photo_bench.py`). Симптом:
локальный замер «детектор пропускает ~26% строк разворота» не подтвердился на
сервере. Причина: локально стоял rapidocr 1.2.3, на сервере 1.4.4 (у 1.2.3 на
развороте 65 нет первых строк обеих страниц — 32 строки против 37). Правило:
бенч печатает версию движка, кэш рамок ключуется ею; эталон чтения снят на
версии сервера. Чтение надписей в бенче — одной порцией на картинку
(`IMAGE_READ_MAX_BLOCKS`): порции нумеруют блоки заново с нуля, и ответ
заглушки садился бы на чужие блоки.

**Ю3. Печать не ложится на чужой текст** (`image_text._collide_guard`,
`_hits`, `_letters_out`, `IMG_COLLIDE`). Симптом: перевод блока сполз на
соседнюю надпись (разворот 65, письмо 69). Правило: после раскладки меряется,
где легла краска печати (`_printed_rect` — тем же `_paint_put`); часть за
пределами своего блока не должна накрывать рамку надписи документа (печать,
подпись и шум — `skip` — не преграда: оригинал лежал под ними) и буквы
оригинала, которых детектор не нашёл (`has_letters`, как у «свободных
строк»). Накрыла — раскладка «теснее» без роста; не помогло — блок
остаётся оригиналом ЦЕЛИКОМ, всеми частями (`collide`, счётчик `img_collide`),
без подписи под фото. Замер бенча: хуже не стал ни один снимок.
Граница: печать ВНУТРИ своей рамки поверх букв, которые стирание по маске
не сняло (изогнутые строки разворота), сторож не видит — это лечится
разбором, а не печатью.

**Известное, что лечится разбором** (следующие заходы ТЗ): на снимке под
углом рамки строк перекрывают соседей, вырезка для чтения с полем показывает
модели две строки — текст блоков дублирует соседей (визитка 66: шесть
двойников). Лекарство — вырезка по четырёхугольнику строки, выпрямленная.
Блок двух языков (табличка 68) делится по строкам до перевода.

## Е. Известные границы (что ещё не так, и это сказано)

- (С, 13.10) Ячейки шапки таблицы с длинным переводом («Стоимость»,
  «Сердечная недостаточность») мельчают: ячейка растёт вширь и вниз (Т1, Т4),
  но не вверх.
- (Т19) Обрезка по настоящей кривой выключена: строки, спрятанные за рамкой
  обрезки, но внутри её прямоугольника, всё ещё печатаются.
- (Т13) Перевод, раскрывший сокращение («Печень (метаболически
  ассоциированная…)» вместо МАСБП), не влезает в место подписи схемы и
  налегает на соседнюю («СОАС», стр. 1) — лечится переводом, а не вёрсткой.
- Плашка «КОМАНДА…» (стр. 31) переполняется второй строкой ниже плашки: место
  по вертикали не ищется. Градиентная заплатка под «Optimize» остаётся —
  стирание по маске для неплоских мест слоя не сделано.
- «TRE | LEKD» (стр. 10, две подписи на двух дугах, слитые одним путём) путь
  не разрезает.
- Подпись схемы переводится без рисунка и без тела документа («STEPPING» →
  «СТЕППИНГ», калька); якорь «метка ↔ абзац с теми же словами» не сделан.
- Пропавший знак сравнения («<7%» → «7%») проверки перевода не ловят —
  находки `comparison_sign_lost` в `checks.py` нет; на разборе знак теперь
  сохраняется (Т7).
- Пороги Т22, Т25, Т32 измерены на проекте 14 и книгах 8/19/20, на других
  документах — нет.
- Дуга, на которую перевод не влез и на `CURVE_MIN_SHARE`, выходит за конец
  дуги (вместо обрубленного текста).
- Строки со сборкой букв (Г2, Н1) печатаются контурами и не выделяются как
  текст в готовом PDF: нужен вшитый CID-шрифт с ToUnicode, reportlab глифы
  по номеру не ставит.
- Кхмерский и бирманский по-прежнему режутся по знакам (у BudouX нет их
  моделей); кернинг латиницы и кириллицы reportlab не делает, а контурные
  строки — делают (шрифт Noto с GPOS).
- Прежний текст остаётся под закраской: «скопировать текст» отдаст и его.
- Надпись наполовину в слое, наполовину кривыми («Optimize» слоем + «quality
  of life» кривыми) разбор надписей отсеивает как слой (`LAYER_OVERLAP`) —
  кривая половина остаётся оригиналом.
- Колонтитул страницы, поставленной прямо (Ж2), повёрнут и печатается по пути.
- Русский текст плотнее английского по площади на 35–50%: в плотной колонке
  без свободной бумаги кегль 0.75–0.85 — предел, лучше не будет без
  переноса текста на другую страницу (её у нас нет: страницы оригинала).
- Гарнитура «полусерифная» (Museo) печатается Noto Serif — ближайшим, но
  не тем же; своих файлов редких гарнитур у нас нет.
- Надпись по дуге, у которой детектор нашёл меньше четырёх букв, печатается
  по хорде под углом, а не по дуге.
- Абзац, разорванный порядком потока (колонка дорисована позже), остаётся
  двумя абзацами: кегль у них общий (З2), перевод — двумя кусками.
- Надпись растром на дуге, у которой буквы не выделились по пикселям
  («MEDITERRANEAN DIET», «GOALS OF CARE» на стр. 1; «STRENGTHENING» — см. П4),
  остаётся оригиналом (Л9) — лучше английская подпись, чем заплатка.
- Многострочная надпись рисунка через две плашки рядом (стр. 19, «Consider
  medication…» | «Consider metabolic surgery») делится только по вертикали
  (К13); разделение по горизонтали — не сделано.
- Заголовок в подбор печатается начертанием тела, если абзац от трёх строк
  (строка — одним начертанием, Л2).
- Номера аффилиаций (надстрочные «1,2» у авторов и в сносках) печатаются
  строкой текста («Дэвис,1,2Ванита»): надстрочность разбор не хранит.
- Блоки мелкого текста (финансирование, конфликт интересов) печатаются
  ступенью класса кегля (Л), то есть мельче оригинала, когда перевод длиннее.
- Инфографика (стр. 1, 4, 10, 12, 19, 28, 30): подписи мельче оригинала, пункты
  при значках-галочках местами не совпадают со значками (М3 закрывает только
  маркер-букву, не значок-картинку).

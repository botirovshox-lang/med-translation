# Автоматический разбор случаев и выкат правил (раздел Ы7)

Решение владельца сервиса (25.10.2026): нерешённые места проверки перед выдачей
(`prepress_cases`) и первые выгрузки новых файлов (`exportReviews`) разбираются
**без человека**, а правила выкатываются **автоматически, с критиками**. Прежнее
правило docs/rules/export-review.md «выкат только после ок владельца» этим решением
заменено для автоматического разбора; ручной разбор в сессии с владельцем остаётся
как был.

## Кто что делает

| Шаг | Кто | Где |
|---|---|---|
| Раз в час: есть ли работа (без модели) | раннер | `tools/auto_rules/run.sh`, Планировщик Windows (`install_task.ps1`) |
| Разбор, виды, правило, тест, справочник, регрессия | агент Claude Code (`claude -p`, Opus 5.5) | `docs/rules/auto-rules-agent.md` |
| Критики: дизайнер, переводчик, код | три субагента `reviewer` | там же, п. 5 |
| Можно ли выкатывать | **код, не модель** | `tools/auto_rules/guard.py` |
| Все тесты (прощается только то, что падает и на базе) | код | `tools/auto_rules/gates.sh` |
| Выкат, окно наблюдения, эталоны до/после, автооткат | код | `tools/auto_rules/deploy.sh` |
| Отметка случаев, сообщение владельцу в Telegram | код | `run.sh` |

## Рубежи (взято из мировой практики)

Судья LLM шумит и смещён по позиции — поэтому последнее слово у детерминированных
рубежей, а не у критиков (Meta SapFix/Getafix и Copilot Autofix тоже держат
исправление за несколькими проверками; человеческое ревью у них заменено здесь
рубежами и автооткатом — это решение владельца, а не забывчивость).

1. **Белый список путей** диффа и **запретные пути**: раннер, выкат, деньги, права,
   вход, сторожа изоляции и утечек (`guard.FORBIDDEN`); строки `main.py` со словами
   денег и прав (`_PAID`, `_OWNER_ONLY`, `_hide_cost`, лимиты…) трогать нельзя.
2. **Тесты не ослабляются**: проверок в существующих тестах не меньше, чем было;
   удалять тесты нельзя; правило без теста и без записи в `pdf-reading.md` — отказ.
3. **Размер**: не больше `AUTO_RULES_MAX_LINES` (1500) строк диффа.
4. **Все тесты** проходят (кроме падающих и на базе).
5. **Выкат за раз и в сутки**: замок на этой машине и на сервере (между машинами
   владельца); не больше `AUTO_RULES_MAX_DEPLOYS_DAY` (2) выкатов в сутки.
6. **Автооткат**: health за 120 с; окно наблюдения `AUTO_RULES_WATCH_S` (600 с) —
   трейсбеков в журнале не больше, чем было до выката (+2); эталоны
   (`tools/fidelity_report.py`) — предупреждений не больше, чем до. Иначе сервер
   откатывается на прежний коммит, а в main уходит revert (иначе следующий ручной
   выкат привёз бы то же).
7. **Деньги**: потолок сессии агента `AUTO_RULES_BUDGET_USD` (15); платные шаги
   разбора — до $1 на файл (export-review.md, п. 3).

## Управление

- Выключить: создать файл `%USERPROFILE%\.medcat-auto-rules\OFF`.
- Сухой режим (ветка без пуша): `AUTO_RULES_DRY=1 bash tools/auto_rules/run.sh`.
- Логи: `%USERPROFILE%\.medcat-auto-rules\logs\`, выкаты — `deploys.json` там же.
- Поставить в Планировщик: `powershell -File tools/auto_rules/install_task.ps1`.

## Чего это НЕ делает

- Не открывает новых дверей в API: Telegram — ключом самого сервера по ssh.
- Не канареит по организациям: правило вёрстки действует у всех сразу; защита —
  эталоны до/после и автооткат. Ограниченный ключ ssh (`command=`) для раннера — не
  настроен; раннер ходит обычным ключом владельца.
- Не меняет данные проектов: правило — код; откат кода не требует миграции данных.
